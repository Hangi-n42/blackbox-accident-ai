# HGB 단일 대조 독립 감사

판정: 저장 산출물과 실행 코드 검사 통과, 후보 미채택 결론에 동의. 추가 학습이나 영상/모델 추론 없이 저장 정답·확률·모델 메타데이터로 감사했다. 감사 프로세스 exit 0.

## 확인한 통제

- 8개 분할의 training_manifest selection이 기존 curated_usable baseline과 순서까지 같다. 공개 각2435행(외부2395+공개40), 날짜1661/1960/1986행.
- train/held ID 분리, 평가 총3390행(50+1612+1167+561)의 (fold,id,sample_index) 유일성 및 원천 일치 확인. 날짜 간 반복 원천/시각은 기존 설계이며 독립3390사례로 해석하지 않는다.
- 양 모델 scaler의 mean/scale/variance/count/feature count가 정확히 동일. 기존 scaler를 복사하고 HGB classifier만 학습하는 실행 코드를 확인했다.
- baseline LogisticRegression 및 HGB의 class_weight='balanced', 클래스 순서, manifest의 클래스 수와 N/(4*n_class) 가중치 요인이 일치한다. 원천별 추가 가중치 없음.
- 8모델 모두 동일 사전 고정 HGB 파라미터다. baseline 전영상 확률이 이전 NPZ와 비트 단위 일치한다. CSV 확률은 저장 NPZ와 수치 정밀도 내 일치, 분류는 argmax와 같다.
- 모든 범위·차량별 confusion, 클래스별 F1, Macro-F1, 반전 분자/분모/율을 독립 재계산했다. 정답 STOPPED 제외47행 조향 및 공식식 공개 S3 재계산 통과.
- 예측 변경·정답 복구·새 오답·새 반전·반전에서 다른 오답으로 이동을 각 행에서 재계산했다.
- 사전 보호 원본/기준/운영 해시와 run.py 해시를 재확인했다. 숫자와 증거는 audit.json에 보존.

날짜1 전체 개선도 차량별로 다르다. Civic F1 .573576→.554492로 하락하고 RAV4 .370621→.505873으로 상승한다. Civic 반전275→141은 실제 개선 일부를 포함하지만 등속 F1 .389189→.269231, 정지 F1 .984901→.976581의 악화와 교환된다. 따라서 전체 날짜1 F1만으로 Civic 문제가 해결됐다고 표현할 수 없다.

날짜2의 핵심 악화는 등속이다. 등속764개 중 정답323→192, A/D 오분류441→572. 등속 F1 .564685→.394251. Civic 반전율 .308943→.349593으로 +4.065%p. 날짜3은 반전 합계가16으로 같지만 새11개가 생기고 기존11개가 다른 오답으로 이동했다. RAV4 반전1→2는 분모35에서 +2.857%p다. 날짜3에는 STOPPED 정답이 없으므로 고정4범주 Macro-F1 절대값을 다른 날짜와 동일 난이도처럼 비교하지 않는다.

실행 로그의 학습 F1은 선형 약.808–.845 대비 HGB 약.947–.976으로 높지만 held-out 이득은 일관되지 않는다. 이는 학습 적합 개선이 원천 밖 일반화로 이어지지 않은 결과다. 데이터 원천 단서/깊이/카메라 회전 중 무엇 때문인지 확정한 인과 실험은 아니다. 모델 복잡도를 더 올리거나 낮추면 반드시 해결된다는 근거도 아니다.

## 한계와 후속 판정

원래 개발 후보 채택 조건 중 S3 +.01, 날짜별 비악화, 각 날짜·차량 반전율 증가≤.01을 실패했다. 공개 새 반전0만 통과했다. 한 설정의 실패를 모든 tree/boosting 계열의 불가능성으로 확장하지 않는다. 그러나 공개50개로 재탐색하면 선택 편향이 커지므로 추가 HGB 설정 탐색은 권하지 않는다.

이번 감사는 학습 전과정을 새로 재현한 검증이 아니다. 이미 저장된 파일, 모델/scaler 메타데이터, 실행 코드 및 보호 해시를 대조했다. 학습 F1은 실행 로그 수치이며 별도 재추론하지 않았다. 모델/원본/기준 결과는 변경하지 않았다.
