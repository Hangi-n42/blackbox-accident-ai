## 새 A/D/C 창 선정 결과

`matched_windows.json`의 windows는 빈 목록이다. 신규 원천의 조건이 먼저 실패했으므로 기존 개발 영상에서 18창을 억지로 채우지 않았다. 기존 28창의 유효 검증 A0/D2/C1 및 유효 속도쌍0이라는 문제도 그대로다.

최소 기능 확인용 부족 조건은 다음과 같다.

- 기존 개발 및 알려진 공개 동일 route와 겹치지 않는 동기화 원천 2경로 이상. 두 차량 일반화를 주장하려면 두 차량을 포함한다.

- 기존 후보 기준을 고정: 전창 속도>5m/s, |조향|≤5deg, A a>.5m/s², D a<−.5, C |a|<.1; 같은 속도 비교 최대차2m/s. 비공개 대회 임계값이 아니라 강한 상태의 연구용 조건이다.

## 확보 가능한 경로와 최소 수신 방식

기존 `chunk1_members.json`, `chunk3_members.json`의 원격 ZIP 멤버 목록에는 알려진 로컬24개 route ID 밖의 **18개 route / 필수멤버가 나열된176개 segment**가 남아 있다. 이들은 **로컬 미확보 목록 후보**이며 A/D/C·속도 범위는 아직 모른다. 원천/필수파일 목록은 `unacquired_route_candidates.json`에 기록했다. 두 차량 각9개 route이고, 이 후보의 route 날짜는 기존 로컬 학습 날짜와도 다르다. 같은 도로의 공간 중복은 여전히 가능하다.

2026-09-20 공식 Hugging Face 배포 ZIP에 HEAD 요청만 수행했다. 본문을 읽거나 데이터 파일을 다운로드하지 않았다.

| 배포 | HEAD | Content-Length | Range 안내 |
|---|---:|---:|---|
| https://huggingface.co/datasets/commaai/comma2k19/resolve/main/raw_data/Chunk_1.zip | 200 | 8,731,252,405 bytes | Accept-Ranges: bytes |
| https://huggingface.co/datasets/commaai/comma2k19/resolve/main/raw_data/Chunk_3.zip | 200 | 9,412,088,454 bytes | Accept-Ranges: bytes |

전체 ZIP 다운로드는 필요하지 않다. 향후 승인이 있는 수신 단계에서 ZIP 중앙목록/HTTP Range의 실제 동작부터 확인하고, 미사용 route의 frame_times·speed·steering timestamp/value만 선택 수신하여 조건을 검색한 뒤 해당 영상 멤버만 받는 방식이 적절하다. HEAD의 Range 안내는 실제 선택 추출 성공을 증명하지 않으며 이번에는 선택 수신을 실행하지 않았다.

현지24개 기준으로 영상 하나의 크기 중앙값은37,502,676 bytes, 영상 이외 필수 시각/센서 파일 합계 중앙값은161,848 bytes다. 이는 예산 참고용 관측값이며 원격 후보의 정확한 압축전송 크기 또는 필요한 영상 수를 확정하는 값은 아니다. 176개 전량 수신이나 신규 대용량 다운로드는 수행하지 않았다. ADAS-TO·ZOD는 계속 제외한다. ANAID는 배포자의 프레임-센서 대응근거 확보 전까지 감독학습/독립 정밀평가에 넣지 않는다.

## 추가 확인: 두 영상 선택 수신의 정확한 크기

위 HEAD 이후, 소량 수신 가능성을 판단하기 위해 **ZIP 중앙목록 메타데이터만** 제한된 HTTP Range로 읽었다. Chunk1 1,725,452 bytes + Chunk3 1,909,875 bytes = **3,635,327 bytes**. 응답206과 Content-Range/실제 길이를 읽기 전에 검사하고 요청/누적 상한을 적용했다. 영상·센서 payload 수신은 여전히0이다. 따라서 앞의 '본문읽기0'은 HEAD 단계에 해당하며 전체 네트워크 수신이0이라는 뜻은 아니다.

| 최소 후보 | 영상+필수시각/센서 압축bytes | 그중 시각/센서만 |
|---|---:|---:|
| Civic: Chunk_3/99c94dc769b5d96e\|2018-05-12--15-03-33/16 | 37,593,706 | 73,172 |
| RAV4: Chunk_1/b0c9d2329ad1606b\|2018-08-06--10-04-53/25 | 37,570,000 | 79,027 |
| 합계 | **75,163,706** | **152,199** |

선정은 기존에 없는 route 중 차량별 가장 이른 route, 그 안의 가장 작은 segment번호라는 내용 비의존 규칙이다. 두 route/date는 기존 개발·공개동일24원천과 다르지만 **차량은 기존 두 차량 그대로**다. 다른 날짜/route ID는 새로운 차량 또는 새로운 도로를 의미하지 않는다. 이 두 영상으로 A/D/C18창이 충족된다는 보장은 없다.

최소수신을 실행한다면 두 후보의 시각/센서 약0.15MB를 먼저 받아 조건을 확인한 다음 영상 약75MB를 결정할 수 있다. 보다 넓게 조건을 찾을 경우18route의176segment에 대한 필수 시각/센서 압축합계도 **12,116,026 bytes**이므로 영상 전체를 선다운로드할 필요가 없다. 표의 byte수는 ZIP 멤버 압축payload 합계이고 HTTP/ZIP 로컬헤더 등 소량 오버헤드는 별도다.

`remote_sizes.py` exit0, `remote_segment_sizes.json`에176segment별 멤버크기/offset/CRC, `minimal_two_clip_plan.json`에2개 후보계획, `remote_metadata_checks.json`에메타데이터Range실증기록을 저장했다. 실제센서/영상수신은 수행하지 않았다.
