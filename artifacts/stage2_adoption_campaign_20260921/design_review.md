# Stage2 캠페인 후보 설계 검수 A

**권고 후보는 하나다: Q3의 동일 타일을 합성 이미지 한 장 대신 시간순 독립 이미지 목록으로 전달한다.** 실행 가능성과 변경 범위가 분명하지만 성능 개선은 아직 가설이다. 새로 발견된 Nexar 검수 파일에는 사용 가능한 신규 진입 정답이 없으므로, 별도 적격 참조를 확보하지 못하면 노출 개발자료 실험으로 제한해야 한다.

운영 V6는 `stage2_uncapped_jerk_v6c`가 기존 네 질의를 수행한 뒤 최종 접촉만 전 영상 움직임 argmax로 교체한다. Q3 후보는 최종 접촉이 아닌 내부 Q2 접촉까지 최대 12개다. Q3에 Q1/Q2의 대화나 상대 식별 이력은 전달되지 않는다. Mac 실행기도 이 정책을 사용하지만 MLX4bit와 CUDA NF4는 수치적으로 동등하지 않다. 이번 Mac 비교를 제출 서버 실행 검증으로 부르지 않는다.

새 자료 조사 결과:

| 로컬 자료 | 실제 보유 | 현재 진입 참조 사용성 |
|---|---|---|
| 00014–00016 | 원본 mp4 3개, AI 검수 PNG 347장 | primary entry/contact 모두 unknown. 조건부 관찰을 정답으로 승격하지 않음 |
| 00017/18/19/21/22/23 | 원본 mp4 6개, A PNG493/JPG19·B PNG440 | 조정 기록의 entry 6건 모두 null. 조건부 접촉구간은 19/21/23 세 건뿐 |
| 별도 Nexar40 정제 | 기존 원본·PTS·검수 자료 | 전부 개발 노출. 진입 근사 4건이라는 수량이 새 독립 정답을 뜻하지 않음 |

위 수량은 파일 목록과 기존 검수 문서로 확인했다. 이번 담당자가 새 원본을 육안 재검수한 것은 아니다. 기존 접촉면 가림·상대 불명확성과 entry unknown을 결과에 맞춰 지우지 않는다. 공급자 event time, 사건 관찰 창, 프레임 등장 시각도 진입 정답이 아니다. 물리 진입 시각이 영상 이전이라는 미상과 대회 첫 프레임 인코딩은 구분하되, 같은 실제 상대·첫 프레임 차로 상태가 확인돼야 한다.

후보는 원래 Q3의 384×256 타일을 완성된 시트에서 무손실 crop한다. 번호·헤더·장면 픽셀·후보·순서를 그대로 유지하고 blank filler 타일은 제외한다. `MLXVLM.ask(images,...)`는 이미 다중 이미지를 지원하며 총 픽셀 예산을 이미지 수로 나눈다. 표준 12타일은 각 98,304픽셀로 100,000 예산보다 작다. 실제 bounded RGB와 processor 입력을 검사해야 하며, 총 픽셀이 같다고 토큰 위치까지 같다고 가정하지 않는다.

Q3의 첫 문장만 `These input images are in chronological order.`로 고정하고 나머지 정의·후보 번호·40토큰·파서는 유지한다. Q1/Q2/Q4와 다른 세 출력은 바꾸지 않는다. 이미지별 경계가 생기면 모델의 후보 비교가 달라질 수 있다는 가설이며, 새 해상도·수동 상대 표식·영상 모델링을 제공하는 변경은 아니다. 입력 묶음과 필요한 순서 문장 변경을 포함한 하나의 정책 실험으로 기록한다.

기존 CCD8에서는 입력→Q2 이전→12후보까지 8→8→8로 참조 지원이 남고 선택만 실패했다. 따라서 후보를 늘리는 것보다 이 지점의 표현을 바꾸는 검사가 직접적이다. 단, 이 8건은 노출된 개발자료다. 신규 최대 12건을 검사할 경우 결과를 보기 전에 적용 가능성·같은 상대·첫 프레임 상태·진입구간을 동결하고 원천 그룹과 기존 노출을 감사해야 한다. 새 적격 참조가 나오지 않으면 일반화 개선으로 판정하지 않는다.

실행 비용은 추가 학습·다운로드 없이 후보 Q3 한 호출/사례다. 기존 8건에서 원래 Q3와 후보를 새로 비교하면 16호출, 다른 세 질의는 검증된 캐시 재생이 가능하다. 신규 최대 12건에서 전체 baseline4+후보1이면 60호출이다. 한 번의 사전 지정 smoke를 포함해 전체 100호출/75분 한도를 넘지 않는다. 과거 16worker의 71.576초·MLX 최대 약6.0924GB는 참고 기록일 뿐 다중 이미지의 새 실행시간이나 메모리 보장이 아니다.

시간 배분안은 참조/원천 확인 15분, 구현·입력 smoke 10분, 고정 비교 25분, 독립검증·보고 15분, 종료 여유 10분이다. 종료는 07:40:52 UTC를 넘기지 않는다. 한 smoke에서 다중 image/grid/토큰 대응과 픽셀 보존·출력 계약을 확인하고, 결과를 본 뒤 레이아웃·문구를 바꾸지 않는다.

채택 판단은 캠페인의 사전 기준을 따른다: 확정 진입 회복 ≥1, 확정·가능 정확도 회귀 0, 새 거짓 첫 프레임 선택 0, paired MAE 변화 상한 ≤0, 형식 오류 증가 없음, 다른 세 출력 보존. native PTS와 원래 참조 구간을 쓰고 불확실 구간을 점으로 축소하지 않는다. 이 수치 기준을 통과해도 참조의 독립성·적격성이 부족하면 확인용 후속이 필요한 개발 근거로만 보고한다.

두 번째 후보는 억지로 채우지 않는다. 기존 4건의 손실/λ 반복, VLM 접촉 복원, 초기 shift 보정, 보조합 제거, 단순 세분화, 표식/legend/first-state gate, 8B 확대는 문서화된 실패를 재실행할 근거가 부족하다. 제출 자산을 수정하지 않고 단일 후보 비교 뒤 종료한다.
