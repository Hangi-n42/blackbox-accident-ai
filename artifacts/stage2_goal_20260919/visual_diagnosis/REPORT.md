# 00007·00010 실제 VLM 입력 재구성과 시각 오류 진단

2026-09-19. **현재 실행 캐시의 2사례×4질의 RGB 입력8개를 정확히 재구성했다. 00007은 초안접촉 허용범위 안의 VLM630을 최종 움직임합산330이 덮어썼다. 00010의 첫 프레임 다음 선택은 관측 이전0과 첫shift를 비교하는 초기화 항의 큰 점수에 지배된다.** 이는 개발 자료의 코드·이미지 진단이며 새로운 GT 또는 개선 성능이 아니다.

## 입력 동일성과 실행 범위

- `current_baseline/inputs.json`에 있는 두 사례 모든 PNG 바이트SHA를 대조했다.
- `current_baseline/run/stage2/human_dev/00007`, `00010`의 새 `calls.json`, `result.json`, `motion.npz`를 사용했다. 과거 priority01 결과를 대신 사용하지 않았다.
- 실제 V6 추출본의 `solution.stage2_v2._sheet`와 `_predict_file`에 저장된 답변을 순서대로 재생했다. 이는 모델 재추론이 아니다.
- MLXVLM.ask의 RGB변환,1,200,000 pixel예산,32배수 내림,BICUBIC을 그대로 적용했다. **8/8 image_sha256·크기·질문·토큰예산이 기록과 일치했다.** 각 case의 `call1..4_raw.png`와 `call1..4_bounded.png`를 저장했다.
- 직접 판독한 모델 입력은 각 사례 contact(call2)·entry(call3) 총4장이다. coarse·space 입력도 해시검증/저장했지만 이번 직접 판독 범위와 구분한다. 두 native_context 시트와 원본크기4장도 읽었다.
- 새 모델 추론0,새 후보평가0,운영코드/정답변경0. 재현은 `reconstruct.py`, `inspect_motion.py`다.

## 00007: 움직임 합산 단계에서 접촉 후보를 잃음

현재 출력 흐름은 VLM coarse669→fine630→기본motion316→uncapped 합산330이다. 단일 사람초안은 접촉625(20.833333초)이다. 630은21.0초로 초안±0.3초에 들지만330은11.0초다. **현재 Mac 내부VLM의 이 사례는 초안 기준 정답이다.** 과거 CUDA/V7의 내부VLM0/9 기록을 현재 결과에 적용하지 않는다.

실제 contact시트에서313–317은 은색SUV가 자차 좌측에 있고 정면에는 도로·멀리 있는차량이 보인다.627–631에는 회색HondaSUV 뒷면이 자차 바로 앞에 크게 보인다. 원본330에도 은색SUV가 좌측옆에 있고,630에는 HondaSUV가 정면근접한다. 둘의 접촉면은 하단에 가려져 **실제 최초물리접촉을 이번 이미지로 재확정하지 못했다.**330에서 직접 접촉이 보이지 않는다는 것과 실제로 접촉이 없었다는 주장은 다르다.

입력entry시트172·229에도 후반차와 형태가 유사한 은색SUV가 보인다. 이 sparse시트와 가려진 번호판만으로 동일차량의 연속궤적을 인증할 수 없다. 따라서172가 다른 차량을 골랐다는 원인으로 단정하지 않는다. 최초진입·재진입의 해석과 동일상대 연결은 사람초안의 추가 근거가 필요하다.

## 00010: 초기화 경계와 후보 누락이 동시에 있음

시작0·1·2 원본은 주차장 통로·난간·자차후드다. 직접 접촉하는 근처 상대차체나 실제접촉면은 보이지 않는다. 최종1(0.033333초)을 접촉 관측 근거로 지지하지 못한다. 전체 시야 밖 사건 부재까지 증명한 것은 아니다.

코드는 `previous_shift=0`에서 시작하여 첫 두프레임의 광류shift를0과 비교한다. 현재 입력으로 첫 두flow를 CPU 재계산해 저장feature와 일치를 확인했다:

- s1=(1.300319,−0.319954), s2=(1.314667,−0.300371).
- j1=||s1−0||=1.339104, j2=||s2−s1||=0.024277.
- index1 최종점수57.178535 중 normalized jerk56.747692, residual0.244978, appearance0.185865.
- 다음최대620의점수7.523332.

따라서 첫 관측이동량을 이후 관측간변화량과 섞은 항이 이 사례의 선택을 지배한다는 계산 근거가 있다. s1은 실제 영상간 이동에서 나온 값이므로 가짜flow라 부르지 않는다. 이것은 물리단위 jerk가 아니라 픽셀변위 변화 proxy다.

내부VLM은337(11.233333초)을 선택했다. 실제 입력337에는 요금부스 옆 흰소형차가 보이고, 초안접촉637(21.233333초)은 출구장면이며 좌하단에 어두운차체 일부가 보인다. 모델이 흰차를 근거로 답했는지는 응답이번호뿐이므로 확정할 수 없다. 단일 초안의 `검은색 차량` 설명을 독립 identity GT로 삼지 않았다.

fine접촉 후보의 마지막번호는621(20.7초)이므로637초안과 가장가까운후보도0.533333초 차이다. **이 사례는 정확한 선택기가 있어도 해당fine후보 안에서는±0.3초에 도달하지 못한다.**entry후보도 내부접촉337에서 끝나 초안진입572(19.066667초)를 포함하지 않는다. 최종접촉만 바꾸면 이 기존entry 입력구조가 자동수정되는 것은 아니다.

## 초기 jerk 제거는 이미 수행·기각한 후보

`research/v7/motion_initialization_protocol.json`은 index1의 jerk 직접기여만 제거하고 기존정규화·다른점수·VLM입력을 고정한 단일가설을 정의했다. `research/v7/motion_init_dev/evaluation.json`은 접촉4/9→4/9,MAE3.7323166→1.4397240초를 기록한다. `research/v7/task_decomposition_followup_review.md:11`의00010 1→620도 초안637과0.566667초 차이로 계속 오답이다.

이전 실험의 코드 의미는 타당했지만 ±0.3초 정답수증가 gate를 통과하지 못했다. **새 개선실험으로 반복하지 않는다.**초기화처리의 인과범위를 확인하는 이번자료는 실패기록의 설명 보강이다. index1 제거는00007의중간구간330오인,00010의candidate누락·entry상한을 해결하지 못한다. 실제경계접촉일때 유용한 첫운동량을 잃을 위험도 남는다.
