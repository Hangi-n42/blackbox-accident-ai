# Stage2 접촉 질문 단독 변경: 사전 구조 검사로 기각

2026-09-17. 운영 코드·모델·원본·기존 결과를 변경하지 않았다. 새 모델 추론, 학습, 다운로드, 제출은 하지 않았다.

## 결론

**현재 최종 접촉은 VLM 접촉 답변과 무관하게 움직임 점수의 최대 프레임으로 결정된다. 질문만 바꾸고 움직임 보정을 고정하는 후보는 접촉 성능을 개선할 수 없다.** 따라서 공개 5개 GPU 재추론을 시작하기 전에 후보를 구조적으로 기각했다. 이는 새 질문의 시각 판독 성능을 측정했다는 뜻이 아니다.

이전의 '접촉 선택 질문 하나를 바꾸고 움직임 보정 유지' 권고는 질문 결과가 최종 접촉에 반영된다는 잘못된 전제를 포함했다. 이번 코드 경로 검사로 바로잡는다.

## 실제 검사

- 현재 Mac 실행기와 Stage2 정책 관련 파일의 해시를 기존 진단 freeze와 대조해 일치 확인.
- 공개 5개 입력 순서·경로를 기존 manifest와 대조. 전체 입력 해시·디코딩을 반복하지 않음.
- 저장된 base/new 움직임 배열을 기존 추론에 기록한 배열 해시와 대조.
- 각 공개 영상의 접촉 후보를 하나씩 VLM 선택으로 가정한 총 **63개 대체 선택**에서 두 움직임 교체 단계를 재생하고, 실제 운영 `apply_collision` 함수를 호출.
- **63/63 최종 접촉 불변**, 나머지 3개 출력 불변. 동일 순수 함수를 한 번 더 호출한 반복 검사도 일치.
- 과거 공개 10Hz 시간 매핑을 사용해 접촉 **4/5, MAE 0.54초** 재계산.
- 실행 exit status **0**. GPU 생성 반복성은 새로 시험하지 않았으며 순수 함수 반복 검사와 구분함.

`S2_002`는 후보에 정답 프레임30이 있으나, 30을 선택했다고 가정해도 최종 프레임47로 덮어쓴다. 최종 오차는 여전히 1.7초다. 이 사례를 위한 질문 반복 수정은 수행하지 않았다.

## 실제 데이터 흐름

1. `stage2_v2._predict_file`: VLM 정밀 접촉 선택.
2. `stage2_motion_collision._predict_file`: base motion argmax로 접촉 덮어쓰기.
3. `stage2_uncapped_jerk_v6c.apply_collision`: uncapped motion argmax로 다시 덮어쓰기.

첫 번째 VLM 접촉은 진입 후보의 종료 범위와 공간 질의 이미지에는 영향을 준다. 따라서 원래 전체 파이프라인에서 질문을 바꾸면 진입·공간까지 간접 변경될 수 있다. 이번 '다른 세 필드 고정' 검사는 그 출력들을 보존한 분리 진단이며, 질문만 바꾼 완전한 end-to-end 실행이라고 주장하지 않는다.

## 다음 실험의 조건

질문 튜닝보다 **실제 최종 접촉 결정 규칙**을 대상으로 후보를 정의해야 한다. 단순 VLM 반환으로 교체하면 기존 공개 결과가 4/5에서 1/5이므로 이를 권하지 않는다. 먼저 후보별 물리 접촉 단서와 움직임 피크를 구분하는 관측 가능한 정답 자료를 확보하고, 후보 선택과 최종 교체 규칙을 함께 사전 명시한 실험이 필요하다. 기존 공개5개에 맞춘 임계값 탐색은 하지 않는다. 진입·공간 문맥과 최종 접촉의 불일치도 별도 회귀 항목으로 유지한다.

현재 공개 5개는 노출된 개발 자료이며 새 독립 평가가 아니다. Nexar의 불확실한 접촉 추정을 확정 정답으로 바꾸지 않는다. 이번 후보 기각은 모든 프롬프트 개선이 무효라는 결론이 아니라 현재 고정된 최종 접촉 경로에 한정된다.
