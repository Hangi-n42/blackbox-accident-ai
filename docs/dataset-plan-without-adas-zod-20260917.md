### ANAID 실제 표본 QA — 학습 편입 보류

- 위치: `external_data/anaid/access_sample_20260917/`; 응답·크기·SHA256은 `access.json`.
- 영상: 526×330, 약 19.997 FPS, 컨테이너 프레임 수와 실제 디코딩 모두 **121**.
- CSV: **132행**, `frame_id` 00000.jpg–00131.jpg. `vEgo`, `vEgoRaw`, `aEgo`, `steeringAngleDeg`, `standstill` 등 존재.
- 이 표본의 `yawRate`는 전부 0. 조향 토크 단위 역시 데이터 카드의 Nm 표기를 그대로 신뢰하지 말고 신호 정의를 검증해야 한다.
- 프레임 수와 CSV 행 수 불일치는 확인된 사실이다. 원인, 올바른 오프셋, 다른 클립의 동일 증상 여부는 미확인. 영상과 CSV를 앞에서 잘라 맞추거나 프레임 번호에 20 FPS를 일괄 적용하지 않는다.
- 기존 추출 JPEG·원천 시각·제공 전처리 설명을 대조해 대응 관계가 증명된 클립만 사용한다. 해결되지 않으면 해당 MP4/CSV 쌍은 제외하고 comma 기반 계획을 유지한다.

### 이용 조건 정정

ANAID 논문은 Dataset License를 CC BY 4.0이라고 명시하지만, 실제 Kaggle Version 1 페이지는 **CC BY-SA 4.0**으로 표시한다. 앞선 CC BY 단일 판정은 수정한다. Kaggle 취득분의 라이선스 기록은 BY-SA로 남기고, 가공 데이터 배포 시 동일조건 적용을 검토한다. 이를 이유로 모델 가중치가 자동으로 같은 라이선스라고 단정하지 않는다. 코드 저장소 GPL-3.0과 데이터 라이선스도 구분한다. Sama는 배포 데이터 카드의 CC BY 4.0을 보존한다. UHDM·VDmoire의 사용자 이용 가능 전제는 유지한다.

## Stage1 — 확보된 VDmoire와 UHDM으로 추가 효과 확인

1. UHDM 전체 파일 무결성/디코딩 목록을 만들고, 자연 사진·문서·합성·원천 불명 유형을 분류한다. 초기 파일럿은 검수 통과 원천 100쌍 이내로 제한한다. `pair_*` 폴더를 독립 원천이라고 단정하지 말고 중복 콘텐츠·다른 촬영 장비의 같은 콘텐츠를 연결한다.
2. clean GT를 무조건 대회 ORIGINAL이라고 부르지 않는다. 대응·가공 이력이 확인된 자료만 사용하며 정렬/테두리/해상도 차이를 이용한 편법 분류를 진단한다.
3. 현행 모델, VDmoire만 사용한 후보, VDmoire+UHDM 후보를 **동일 입력 영역·크기·평가 영상**으로 비교한다. 기존 patch 대 full-frame 결과는 데이터 추가 효과의 증거로 사용하지 않는다.
4. 원천별 분할 후 고해상도 패치를 추출하고 원천마다 동일한 총 가중치를 준다. UHDM을 복제해 가짜 영상으로 만들지 않는다. 학습·검증의 같은 원천 파생물 혼입을 금지한다.
5. 영상 Macro-F1과 원본 오탐/재촬영 누락을 따로 보고한다. 도로 원본–물리 재촬영 쌍은 별도 미확보 과제이며, 이를 확보하기 전 도로 일반화 개선을 확정하지 않는다.

## Stage2 — Nexar 중심, Sama는 공간 판단 보완

1. 기존 40개 Nexar 사건의 개발/검증 사용 이력과 AI 참조 정답의 불확실 구간을 보존한다. near-miss, 제3자 사고, 관측 불가능 필드는 구분하고 대회 네 항목의 0 정답으로 대체하지 않는다.
2. 새 사건 단위로 접촉 구간, 첫 바퀴 진입 구간, 진입 방향, 회피 공간을 검수한다. 사건 시점은 탐색 힌트로만 쓰고 실제 접촉·진입 정답은 다시 확인한다. 원본 PTS를 보존한다.
3. Sama는 초기 200–500개 검수 이미지 예산으로 차선/차량/주행 영역의 진단부터 한다. 숫자는 제안 예산이며 확보 실적이 아니다. 연속 녹화에서 잘린 영상이므로 video ID만으로 완전 독립이라고 보지 않고 인접 구간을 묶어 분리한다.
4. Sama의 1 FPS 영상은 ±0.3초 시점 평가에 사용하지 않는다. Drivable Space는 회피 공간 정답이 아니다. 차선과 차량 위치를 찾는 보조 기능의 개발/검증에 한정한다.
5. 공간 보조 기능 추가 전후에 다른 설정을 고정하여 Nexar의 항목별 성능·시점 오차를 비교한다. 새 사건의 봉인 평가를 유지한다. 기존 AI 참조 점수는 공식 대회 점수와 구별한다.

## Stage3 — comma 유지, ANAID는 QA 통과 후 확장

1. 현재 Mac 모델을 대조 기준으로 유지한다. 기존 comma-only 후보는 공개 회귀 평가에서 현행보다 낮았으므로 다시 자동 채택하지 않는다.
2. ANAID 첫 표본 불일치 원인을 먼저 분석하고, 소수의 다른 run/정상·회피 클립에서 재현되는지 확인한다. 각 파일의 프레임-신호 대응이 확인되기 전에는 모델을 학습하지 않는다.
3. QA가 통과하면 정상/정지/가감속/회전 후보를 선별한다. 가속 페달이나 조향 토크를 가속/조향 정답으로 대신 사용하지 않는다. 실제 속도·가속도·조향 신호에서 불확실 구간을 제외한 대체 라벨을 만들고 영상 관찰과 대조한다.
4. 차종별 단위·부호·중립값과 시간 지연을 확인한다. comma 주행 경로와 ANAID run 단위로 분리하고 자료별 표본 가중치를 조정한다. 4개 run 중 하나는 초기에 건드리지 않는 평가용으로 남기되, 같은 차량·지역이므로 독립 도메인 검증이라고 부르지 않는다.
5. 동일한 특징/학습 예산으로 comma-only와 comma+ANAID를 비교하고, 실제 대회 공개 회귀에서 항목별 저하도 확인한다. 합산 proxy 점수만으로 채택하지 않는다.
6. ANAID 정렬을 복구할 수 없으면 추가 학습을 중단하고 comma 기반 오류 분석을 진행한다. OpenLKA는 이후 작은 차종별 표본 검수 후보, URT는 교차로 진단 후보이며 ZOD와 동등한 외부 검증을 확보했다고 표현하지 않는다.

## 실행 우선순위 및 완료 기준

1. UHDM 확보분 QA와 Stage1 동일 조건 비교: 후보 B의 추가 이득이 없으면 기존 기준 유지.
2. ANAID 정렬 불일치 진단: 대응 입증 여부로 편입/제외 결정. 데이터가 있다는 이유만으로 학습하지 않음.
3. Nexar 새 사건의 항목별 참조 품질 개선 및 Sama 소량 QA: 공간 분석 필요성 확인 후 단일 요소 비교.
4. ANAID 통과 시 Stage3 결합 비교: 주행별 분리와 기존 공개 회귀 저하 여부 확인.
5. 부족한 도로 재촬영/외부 주행 검증 보완: OpenLKA·URT 등은 특정 부족분이 남을 때만 검토. ADAS-TO·ZOD 재시도는 이번 계획에서 제외.

이번 턴에는 학습·모델 교체·실험·제출을 시작하지 않았다. 새 원본 다운로드는 승인된 ANAID 약 218KB 표본으로 제한했다. Sama는 브라우저 미리보기 및 파일 목록 접근 확인이며 전체 취득은 아니다.
