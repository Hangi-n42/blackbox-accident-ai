**실제로 확인된 병목**

1. **최종 충돌은 전 영상의 움직임 점수 최댓값이다.** VLM의 정밀 접촉 답변을 base motion argmax로 덮어쓰고 다시 uncapped jerk 복합점수 argmax로 교체한다. 프롬프트의 실제 접촉 판단이 최종 충돌을 직접 결정하지 않는다. 광류 shift 차분을 jerk라 부르지만 물리 센서로 측정한 차량 jerk가 아니다. 따라서 큰 영상 움직임이 최초 접촉과 일치한다는 보장은 코드에 없다.
2. **질문만 바꾸는 접촉 실험은 이미 구조 검사에서 기각됐다.** 공개 5개의 저장 후보 63개를 대체 입력한 검사에서 최종 접촉 63/63 불변. S2_002는 정답30을 넣어도 최종47. 9/17 초반 계획의 질문 변경 권고를 다시 실행해서는 안 된다. 이것은 새 질문의 VLM 성능 시험이 아니라 최종 출력 의존성 검사였다.
3. **충돌 출력과 진입·공간 판단 문맥이 다르다.** 진입 후보의 종료점과 공간 질의 이미지는 교체 전 VLM 충돌을 사용한다. 최종 충돌만 바뀌면 네 출력이 서로 다른 시점·상대를 참조할 위험이 있다. 단, 공간 문맥을 최종 충돌 주변으로 바꾸는 단독 후보도 이미 개선에 실패했으므로 문맥 정렬만으로 성능 개선을 단정하지 않는다.
4. **진입 탐색은 잘못된 구간 선택을 회복하지 못했다.** Mac의 동일 실행 대조에서 전체 탐색 후 두 번 세분화한 후보는 진입0/8→1/8이지만 MAE12.6237→13.5838초로 악화했다. 후보 정답 포함률은 2/8→2/8→1/8로 감소했고 시작 프레임 정답이 탐색 중 사라진 사례가 있었다. 단순 coarse-to-fine 추가는 이미 실패했다.
5. **사고 상대 식별과 공간 판정의 신뢰도를 검증할 정답이 부족하다.** 사람 초안 개발 자료에서 방향·공간 편향과 다른 차량 참조가 관측됐다. 동일 상대의 식별·바퀴와 차선 관계·충돌 당시 공간을 별도로 확인해야 한다. JSON 파싱 성공은 의미 정확도를 증명하지 않는다.

P1은 가시성 있는 5사건 규모의 **주석 절차 파일럿**부터 설계할 수 있다. 이는 필요한 총 데이터 수나 통계적 충분량이 아니다. 큰 비접촉 움직임 후 접촉, 약한 충격, 여러 차량, 시작 전 진입/실제 차선 진입 등을 구분할 수 있어야 한다. 확보된 기존40·9·6개에서 미노출 정답5개가 준비됐다는 증거는 없다. 가려진 접촉을 반복 검수해 확정 수량을 늘리지 않는다. 가시성 있는 사례만으로 개발하면 가림이 있는 사고에 대한 성능은 계속 미검증임을 보고한다.

P2에서는 새로 검수한 사건을 기준으로 정답이 전체 원본에 있는지, 실제 제시 후보에도 있는지, 후보가 있어도 같은 상대를 선택하지 못하는지부터 나눈다. 진입은 `전체 원본 → 내부 VLM 충돌 이전 → 12개 제시 후보 → 최종 선택`의 각 단계에서 정답 허용 구간이 사라지는 수를 기록한다. 상대 식별이 의심되면 텍스트 설명을 반복하는 대신 사람이 확인한 **동일 상대의 픽셀 표시** 조건과 자동 조건을 제한적으로 비교하는 진단을 설계할 수 있다. 표시에는 정답 접촉 시각을 포함하지 않는다. 이것은 제출 성능이 아닌 보조 정보를 제공한 원인 진단이며, 개선 효과는 미확인이다.

이 분해에서 근거가 생긴 요소 하나만 최종 선택 규칙 후보로 만든다. 후보 수·시간창·임계값·불확실 시 fallback은 결과를 보기 전에 고정한다. 기존 V6A/B와 같은 접촉 확인 질문 추가, VLM 단독 반환, 일정 프레임 앞당기기, 공개 S2_002 전용 규칙을 다시 채택할 근거는 없다. 새 근거에서도 접촉 판독이 개선되지 않으면 후보를 기각하며 모델 크기 확대로 자동 전환하지 않는다.

첫 비교는 접촉만 바꾸고 다른 세 출력을 보존해 효과를 분리한다. 이 분리 비교를 통과한 뒤 같은 최종 접촉·상대를 진입과 공간에 연결하는 전체 실행을 검증한다. 접촉 개선만으로 전체 S2 개선을 확정하지 않는다. 객체 탐지·추적 모듈은 상대 식별 실패가 확인된 경우에 기존 자산부터 제한적으로 평가하며 전체 파이프라인을 먼저 재구축하지 않는다. 이 방향은 공식 필독의 충돌 상대 역추적·객체 위치 분석 제안과 일치하지만, 이 구현의 성능은 아직 미검증이다.

**채택 기준**

- 평가 전에 후보·정답·분할·입력·렌더·모델·질의 예산을 고정한다. 동일 사고의 재인코딩·잘린 영상도 같은 그룹으로 취급한다.
- 시점의 주 지표는 Acc@0.3초다. MAE·큰 오차·기존 정답 손실은 보조 진단이다. MAE만 줄어든 후보를 점수 개선으로 부르지 않는다. 반대로 Acc와 MAE가 엇갈릴 때 적용할 회귀 기준은 결과 전에 정한다.
- 각 필드의 알려진 정답 수·unknown 수·클래스별 수·후보 포함률·선택 실패·fallback을 공개한다. 네 항목이 완비된 공통 평가 집단일 때만 공식 식에 따른 로컬 S2를 계산하며 공식 서버 점수와 이름을 구분한다.
- 이미 노출된 자료에서 채택한 후보 하나를 별도의 잠금 자료에서 확인한다. 소수 파일럿 통과는 일반화나 공식 상승 보장이 아니다.
- 출력 계약·다른 필드 회귀·동일 영상 독립 예측·오프라인 실행을 통과해야 제출 후보로 올린다. 비공개 평가 입력으로 추가 학습·튜닝·pseudo-labeling하거나 다른 영상의 통계로 보정하지 않는다.

서버 제약은 L40S 44.7GiB, ZIP10GB/해제32GB, 설치10분/세 Stage 전체 추론60분이다. 기존 V6 전체42분41초에서 남은17분19초를 새 Stage2가 전부 사용할 수 있다고 가정하지 않는다. V7의 Stage1 변경과 비공개 입력 수·길이, 후보 호출 수까지 포함한 별도 실행 근거가 필요하다. **바로 착수할 세 산출물**

1. 제출 기준과 Mac 기준을 분리한 Stage2 평가 manifest 및 기존 실패 목록.
2. 대회 적격 사고·동일 상대·접촉·진입이 확인되는 소량 정답 묶음과 사건 단위 개발/확인 분할.
3. 최종 접촉 오류 분해와 그 결과에 따른 단일 후보 선정 계획. 진입·공간 문맥 회귀와 서버 검증을 포함한다.

현재 이미 완료한 63개 구조 검사, DeepStack 수정, 실패한 8B·native-video·진입 세분화 실험을 다음 할 일로 다시 제시하지 않는다. 정답 공백을 해소하지 못하면 새 공식 성능 개선 주장은 보류하고 검증된 V6 Stage2를 보존한다.
