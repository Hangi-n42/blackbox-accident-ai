## 실행 작업 결과

단일 진입점은 `scripts/mac/run_stage2.py`, 공통 모델 어댑터는 `scripts/mac/mlx_stage2.py`다. 기존 `artifacts/mac_experiments/stage2_mlx/run.sh`도 이 경로로 연결했다. 이전 측정 실행기와 snapshot은 결과의 근거이므로 수정하지 않았다. 새 실험은 `--case` 또는 기존 `inputs.json`을 받는 `--manifest`로 동일한 실행기를 사용한다.

단독/일괄 모두 영상마다 새 프로세스를 사용한다. 스레드·seed·환경변수·모델 로드/움직임 계산 순서를 통일했다. 처리된 입력 텐서를 실제 평가한 뒤 GPU 동기화하고 생성 함수에 전달한다. 이미지 픽셀, 채팅 프롬프트, 처리기 출력 텐서의 SHA256을 기록한다. 질문·모델 가중치·기존 V6의 최종 접촉 보정 정책을 바꾸지 않았다. 모델을 영상마다 로드하므로 처리량 최적화와 별개다.

**판정: 실행 경로 통일 완료, 출력 반복성 검증 미통과.**

- 첫 통일 시도에서 S2_001 단독/일괄 출력이 달랐다. 실제 이미지/프롬프트가 같은 2번째 질의에서 원시 응답이 달랐다.
- 텐서 materialization/동기화 추가 후 단독 A와 일괄 AB의 S2_001은 모든 입력 해시·원시 답변·최종 예측이 일치했다.
- 역순 BA 검사에서는 S2_002의 동일 처리기 입력 해시에 대해 방향이 RIGHT와 LEFT로 달랐다. S2_001도 최종 예측은 같지만 중간 충돌 선택 응답이 달랐다.
- GPU 작업 프로세스 10개 모두 exit 0. 최종 단독 비교 도구 exit 0, 역순 비교 도구 exit 1. 실패를 성공으로 분류하지 않았다.
- 영상마다 별도 프로세스이므로 이 관찰만으로 파일 간 상태 누출이라고 단정할 수 없다. 실행 시점/Metal 커널/수치 연산 등 세부 원인은 미확정이다. 고정 seed·greedy는 결과 동일성 증명이 아니다.
- 증거: `artifacts/mac_experiments/execution_unification/verification.json`, `materialized_single_comparison.json`, `materialized_order_comparison.json`.
- 기존 `baseline_20260916`의 9개 검수 점수는 당시 경로의 측정값으로 보존한다. 이번 경로 통일 후 새 확정 기준 점수로 재명명하지 않았다. 출력 안정화 뒤 같은 고정 세트를 재측정해야 한다.

## 공식 평가 페이지와 로컬 문서 대조

[공식 평가](https://dacon.io/competitions/official/236753/overview/evaluation)를 직접 조회했고 본문뿐 아니라 base64 삽입 이미지의 평가표/수식도 확인했다. 로컬 `대회_통합_정보.md` 5절과 다음 산식이 일치한다.

- S1 = 원본/재녹화 두 클래스 Macro F1.
- S2 = .35 접촉 Accuracy@0.3초 + .35 진입 Accuracy@0.3초 + .15 방향 Macro F1 + .15 공간 Macro F1.
- S3 = .70 가감속 Macro F1 + .30 조향 Macro F1.
- 종합 = .20 S1 + .40 S2 + .40 S3.

최종 기여 비중은 재녹화 20%, 접촉 14%, 진입 14%, 방향 6%, 공간 6%, 가감속 28%, 조향 12%다. 이는 공개 가중치를 곱한 값이며 기대 개선량이 아니다. 시간 오차는 영상별 프레임–시각 대응으로 계산한다. Stage3 조향은 GT STOPPED를 제외하지만 출력 행은 생략하지 않는다.

평가 서버 L40S, 추론 전체 60분, 설치 10분, ZIP 10GB/해제 32GB, 추론 중 네트워크 차단 조건도 로컬 문서와 일치한다. 서버 기본 SciPy 1.15.3과 Mac 호환 1.17.1은 서로 다른 환경이다. 현 구현은 Metal GPU 가용성을 강제하므로 서버에서 그대로 실행할 수 없다. 이는 모든 MLX 버전의 CUDA 가능성에 대한 일반적 주장이 아니라 현재 실행기 코드의 제약이다.

이번 현재 웹 확인은 평가 페이지 범위다. 로컬 문서의 실제 물리 재촬영 정의, 최초 바퀴 차선 접촉, CAN 라벨 설명, Public 표시 규칙 등은 프로젝트에 보존된 운영진 Q&A 통합 기록으로 참조했다. 해당 Q&A 전체를 새로 재검증했다고 주장하지 않는다.

## 추천 순서

아래는 가중치·관찰된 실패·검증 가능성을 함께 고려한 개발 판단이다. 현재 자료로 비공개 점수 향상 폭은 예측할 수 없다.

### 선행 0: 비교 가능한 실행과 검증·제출 경로 확보

1. 동일 처리기 텐서에서도 생기는 원시 출력 변동을 먼저 분리한다. 새 실행기는 입력/질의 해시를 남기므로 동일 입력의 logits/연산 경로 비교를 할 수 있다. 실패한 반복성 검사부터 통과시키고 고정 14개 기준을 다시 측정한다. 답변 캐시·사례 ID 정답표로 반복성을 가장하지 않는다.
2. 노출된 9개는 개발용으로 유지하고, 사고 원천별로 분리한 새 사람 검수 자료를 확보한다. 접촉/진입 불확실 구간과 모르는 라벨을 보존한다. AI 검수값을 공식 정답으로 승격하지 않는다.
3. 개선 후보는 Mac에서 개발하되 제출 서버용 로더/가중치 포맷·전처리 계약을 먼저 정한다. Mac 변경을 원래 CUDA 파일에 자동 덮어쓰지 않는다. 서버 경로의 로컬 자산 로드·출력·시간 검증 없이는 제출 준비 완료로 판단하지 않는다.

### 1: Stage2 접촉–진입 시간 관계와 사고 상대 식별 (종합 28%)

관찰: 기존 Mac 측정에서 접촉 4/9, 진입 0/8. 최종 접촉보다 진입이 늦은 사례 4개(00004/5/8/10). V6 정책은 4회 VLM 결과의 진입·공간 문맥을 남겨두고 최종 접촉만 uncapped jerk로 교체한다. 따라서 시간과 문맥이 서로 다른 결정을 기반으로 할 수 있다.

첫 실험 제안: 고정된 상대 차량과 접촉 후보를 기준으로 진입 탐색을 구성하고, 진입 후보가 실제 정답 ±0.3초를 포함하는지부터 분해한다. 정답 후보 자체가 없는 경우와 모델이 잘못 선택한 경우를 구분한다. 차선 진입은 화면 등장 시점이 아닌 바퀴의 차선 최초 접촉이다. 최종 entry를 collision 이하로 단순 잘라내는 보정은 하지 않는다. 실제 시점을 찾았다는 증거가 아니기 때문이다.

통과 조건: 같은 검증셋의 접촉/진입 정확도와 MAE, 후보 커버리지, 방향/공간 회귀, 영상별 소요시간을 함께 비교. 새 자료로 검증하기 전 개선 채택 금지. 기존 native-video 전환은 노출된 9개에서 4/9→1/9로 실패했으므로 근거 없이 재도입하지 않는다.

### 2: Stage3 가감속의 일반화 (종합 28%)

가감속 하나의 비중이 방향+공간 합계(12%)보다 크다. 현재 공개 가감속 F1 .835282는 기존 개발/학습에 사용된 50개 희소 라벨의 결과다. 과거 제출 S3 .526617은 가감속/조향 혼합 점수여서 가감속 실제 서버 점수로 분해할 수 없다.

첫 작업 제안: 차량·주행 경로 단위로 분리된 검증에서 가속/감속/등속/정지를 각각 확인하고, proxy CAN 범주와 공식 희소 라벨의 의미 차이를 조사한다. 전환 구간·카메라 움직임·회전 시 광류와 실제 종가속의 혼동을 오류별로 나눈 뒤 하나의 특징/모델 후보를 정한다. 영상당 임의 랜덤 프레임 분할은 같은 주행 정보가 양쪽에 섞일 수 있어 피한다.

이전 시간 convolution head는 외부 proxy 가중 점수 .604002→.602949로 실패했다. V5의 공간 특징 확장은 정확도 시험 전에 시간 gate에서 탈락했다. 이를 성공한 후보나 모든 시간 모델의 실패로 일반화하지 않는다.

### 3: Stage1 실제 물리 재촬영 일반화 (종합 20%)

공개 10개 F1=1.0은 해당 예제에 대한 적합도다. HANDOFF가 기록한 마지막 제출 S1은 .507884이며 새 Mac 제출 점수는 없다. 보존 문서상 실제 도로 원본/물리 재촬영 대응 자료는 확보 0쌍이었다. 공개 합성 재촬영의 점수만으로 이 과제를 완료했다고 보면 안 된다.

첫 작업 제안: 실제 화면 재촬영 대응 자료를 원천 영상/디스플레이/촬영기기 단위로 분리해 진단한다. 고해상도 패치의 주사·반사·모아레·압축 흔적 후보는 그 자료에서 비교한다. 기존 TPO resize/normalize 감사에서 명백한 계약 오류는 확인되지 않았으므로 중앙 crop 교체를 버그 수정이라고 추진하지 않는다.

### 4: Stage2 방향·회피공간 (종합 각 6%, 합계 12%)

이전 기준 방향 F1 .222222(2/7 정답), 공간 F1 .181818(2/9 정답), 검수 9개 공간 예측은 전부 0. 그러나 이번 반복 검사에서 방향 값 자체의 변동도 확인돼 현재 점수를 안정된 수치로 취급할 수 없다.

접촉 상대/진입 궤적을 고정한 뒤 방향은 화면 좌우 기준으로, 공간은 접촉 당시 주변 차량·차선·도로 경계를 포함해 판단하도록 비교한다. 모두 0을 출력하는 현상을 단순히 출력 비율 강제나 1로 치환해 고치지 않는다. 상대 식별과 접촉 시점의 개선을 먼저 적용하고 별도로 검증한다.

### 5: Stage3 조향 (종합 12%)

공개 GT 정지 제외 47개에서 F1 .883422다. 방향/공간과 동일한 총 비중이지만 현재 한정된 자료에서는 앞선 항목보다 뚜렷한 실패 근거가 적어 후순위다. 실제 서버 조향 성능은 S3 혼합 점수만으로 확인 불가다. CAN 정답과 카메라 회전/도로 굴곡/진동을 구분하며 GT STOPPED 마스크 및 전체 행 출력 계약을 유지한다.
