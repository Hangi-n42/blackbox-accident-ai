# Mac Stage2 검증 및 제출 계약

## 현 실행 계약

입력은 한 영상의 제공된 이미지 목록이다. 원본 frame ID를 보존하고 중복/읽기 실패를 오류 처리한다. CPU motion 경로, 영상별 새 프로세스, 오프라인 로컬 모델, 입력 해시, 정책/디코더/정밀도 설정, 코드 해시, 질의와 최종 예측을 보존한다. `--manifest`의 PTS/정답은 추론에 전달하지 않는다. 점수 계산만 영상별 PTS를 사용한다.

출력은 ID, collision_frame, entry_frame, entry_side, evasion_space. 프레임은 제공된 ID 집합 안에 있어야 하며 방향은 LEFT/RIGHT, 공간은 0/1이다. 다른 영상의 예측·라벨·분포를 이용하지 않는다. 기존 출력 경로에 재실행하지 않는다.

## 개발 자료와 새 검증 후보

기존 공개 5건과 사람 검토 9건은 노출된 개발 자료다. 사람 검토도 단일 검수 초안이며 모르는 라벨은 제외한다. 항목별 분모가 다르므로 공식 Stage2/종합 점수로 명명하지 않는다.

새 검증 후보는 기존에 확보된 00017/18/19/21/22/23 원본 6개다. 현재 파일 해시를 원래 QA 기록과 대조하고 기존 개발 원본과 동일 파일이 없는지 확인한 manifest를 `artifacts/mac_experiments/priority01_20260916/prospective_validation_manifest.json`에 만들었다. 기존 AI 검토가 존재한다. 이를 새 사람 정답이나 완전한 미노출 holdout이라고 부르지 않는다.

사람이 예측을 보지 않고 사고 적용 가능성, 카메라 차량의 사고 상대, 최초 접촉, 최초 바퀴 차선 진입, 좌우, 공간을 확정해야 한다. 불확실한 시점은 구간/unknown을 보존하고 소스 영상 SHA와 native PTS에 연결한다. 같은 사고·중복 편집 영상 여부도 확인한다. 판정 기준을 동결한 뒤 후보를 한 번 비교한다. AI 자체 판단을 사람 정답으로 승격하지 않는다.

## 서버 실행 계약과 미검증 사항

Mac의 MLX 4bit는 원래 CUDA NF4와 수치 동등하지 않다. 현 실행기는 Apple Metal을 요구하므로 Linux/L40S에 그대로 제출할 수 없다. V6 CUDA 원본과 submit_v6.zip은 보존하고 자동 덮어쓰지 않는다.

서버 쪽은 보존된 Transformers/CUDA 로더와 로컬 가중치를 사용하는 경로를 기준으로 한다. 후보를 이식할 경우 동일 이미지 리사이즈·프레임 번호·질의·JSON 검증 계약을 적용하고 서버에서 새 기준과 후보를 함께 측정해야 한다. Mac에서 발견한 MLX 구현 오류를 Transformers에 그대로 패치하지 않는다. 설치된 Transformers의 deepstack 마스크 처리는 이미 실제 토큰 위치를 사용한다.

오프라인 가중치 로드, 5개 컬럼/ID/프레임 유효성, 모든 단계의 실행 시간과 메모리를 실제 L40S 환경에서 확인하기 전에는 제출 가능으로 판정하지 않는다. 현재 CUDA 실행 자원 및 보존 가중치의 서버 로드는 이번 작업에서 검증되지 않았다. 새로운 모델 다운로드·서버 구매·대회 제출은 수행하지 않는다.
