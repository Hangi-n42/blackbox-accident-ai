# Stage2 데이터 정제·사용 계획 사전 전문가 검토

검토일: 2026-09-16. 사용자가 PREVENTION을 제외하고 Nexar 사용을 확정한 전제에서 방법론만 검토했다. 데이터 다운로드·추론·학습은 수행하지 않았다. 이 문서는 독립된 설계 검토이며 개선 성능을 실증한 결과가 아니다.

## 판정

**Nexar 중심의 사건 단위 선별·대회 정의 재주석 → 검증 집합 확보 → 현 모델의 사고 상대·진입 후보 탐색 개선 순서는 실행 가능하고 현재 결함에 맞는다.** PREVENTION을 다른 대규모 자료로 즉시 대체할 필요는 없다. 다만 Nexar에는 현재 필요한 진입·방향·회피 공간 정답이 없어 사람 재주석 비용이 필수다. 현 9건은 개발용으로 유지하며 신규 6건 역시 기존 AI 검토와 동일 사고 여부 조사 전에는 잠금 검증으로 인증하지 않는다.

## 실행 순서와 최소 조건

1. **목록·노출 이력 감사:** 이미 있는 Nexar train 원본부터 SHA256, 원본 ID, 제공 event timestamp, 영상 길이·PTS, 기존 모델/사람 열람 이력을 manifest에 기록한다. 파일 해시뿐 아니라 시간 이동·재인코딩·잘린 동일 사고를 대표 프레임 지각 유사도와 사건 검토로 묶는다. 자동 유사도는 중복 후보 탐색이며 중복 부재의 증명은 아니다. 카메라/주행 원천 ID가 없다면 독립성의 한계도 남긴다.
2. **사건 적격성 선별:** 자차와 상대 차량의 실제 물리적 접촉이 관찰되는 train 사건을 중심으로 한다. near-miss, 제3자끼리 충돌, 비사고는 정밀 시점 평가에서 제외하고 보조 음성 자료로 별도 표시한다. 해당 자료의 접촉/진입을 0으로 만들지 않는다. 예측용 test처럼 사건 전에 끝난 영상으로 접촉 정답을 만들지 않는다. 제공 event는 탐색 안내에만 사용한다.
3. **중복 그룹을 먼저 분할:** 동일 사고·인접 클립을 한 분할에만 둔다. 기존 9건은 dev다. 신규 사건에 고정 seed와 분할 규칙을 먼저 기록하고 train/dev/잠금 평가를 배정한 후 상세 주석한다. 소표본에 기계적으로 80/10/10을 적용하지 않는다. 아직 학습을 하지 않는 파일럿에서는 새로운 검증 확보가 train 양 확보보다 우선이다. 잠금 평가를 보고 실패 유형을 고치면 그 자료는 다음 실험부터 dev가 된다.
4. **대회 기준 주석:** 아래 항목을 모델 예측을 보지 않고 표시한다. 원본 전체 시간축과 `frame_id ↔ native PTS`를 보존한다. 처음부터 진입한 영상의 정답은 해당 입력의 첫 프레임이며, 제출 파일명이 0부터 시작한다고 가정하지 않는다. 접촉 주변으로 영상을 잘라 첫 프레임을 재정의하지 않는다.
5. **품질 검사:** 잠금 평가에는 독립된 두 사람의 초기 판독을 권장하고 불일치만 조정한다. 두 번째 검수자가 첫 번째 답을 먼저 보는 방식은 독립 일치도 측정이 아니다. AI 작성 초안은 AI 주석으로 보존한다. 시간 불확실 구간을 기록하고 좁은 시점 정답을 확정하지 못한 항목은 정밀 정확도 분모에서 제외하되 제외 수와 사유를 공개한다. 예측에 가까운 시점을 정답으로 골라서는 안 된다.
6. **작은 고정 실험:** 현재 Mac VLM 가중치는 유지하고 후보 탐색 정책만 변경한다. 복수 진입 구간과 첫 프레임 이미 진입 여부를 따로 유지하며 같은 상대 차량인지 검증한다. 실패한 단일 구간의 반복 축소를 그대로 다시 학습/평가하지 않는다. 후보·질의 횟수·프레임 예산·채택 조건을 dev 실행 전에 정한다. 신규 대규모 미세조정은 별도 학습/검증 정답이 확보된 뒤 판단한다.

파일럿 목표를 최대 30개의 실제 접촉 사건으로 둘 수 있지만 이는 작업량 제한이지 충분한 통계 표본이라는 뜻이 아니다. 적격·비중복·주석 가능 사건이 부족하면 숫자를 맞추기 위해 모호한 정답을 강제로 만들지 않는다.

## 주석 스키마에 필요한 최소 항목

- 사건: 원본/사건 그룹 ID, split, 노출 이력, 원본·프레임 매핑 해시, 적격성 및 제외 이유.
- 상대: 충돌 상대 ID와 색/차종/경로 메모. 첫 프레임·진입 전후·접촉 주변에서 식별 가능한 핵심 프레임의 박스 또는 클릭을 우선 기록한다. 전 프레임 고밀도 트랙은 초기 필수가 아니다. 객체 탐지/추적 자동 결과를 GT로 바꾸지 않는다.
- 접촉·진입: frame ID, PTS, 가능한 경우 불확실 하한/상한, known/unknown, 사유. 진입은 상대 차량 첫 바퀴가 자차 차선 경계에 닿는 순간이며 교차로에서는 판단 가능한 차선 연장선을 따른다.
- 방향: 블랙박스 화면 기준 LEFT/RIGHT. 차량의 움직임 방향이나 도로 방위와 혼동하지 않는다.
- 회피 공간: 접촉 당시 **자차(대회 용어 피의차량)**가 진행·회피할 공간. 상대 차량의 공간이 아니다.
- provenance: 검수자, 예측/타인 정답 미노출 여부, 검수·조정 버전과 일시.

**항목별 결측을 보존해야 한다.** 접촉은 명확하지만 진입/방향/공간이 가려진 사건을 통째로 버리면 쉬운 차선 변경만 남는 편향이 생긴다. 실제 접촉이 확인된 사건은 보존하고 각 항목의 known mask로 학습·평가한다. 모든 항목의 GT가 있는 하위 집합과 전체 적격 집합을 별도 보고한다. unknown을 0이나 LEFT로 채우지 않는다.

## 평가·채택 기준

- 접촉·진입 Accuracy@0.3초와 MAE를 원본 PTS 기준으로 산출한다. 부분 정답 지표는 각각 분모와 정답 누락률을 함께 표시한다.
- 방향·공간은 고정 클래스 Macro F1와 혼동행렬, 클래스별 사례 수를 함께 기록한다. 한 클래스가 부족한 소표본 점수를 일반 성능으로 해석하지 않는다.
- 각 탐색 단계에서 정답 허용 구간을 포함하는 후보 비율을 보고해 후보 생성 실패와 선택 실패를 나눈다. 사고 상대 식별 오류도 별도 기록한다.
- 진입이 접촉보다 늦는 등 시간 모순은 오류 진단이다. 단순 clamp를 개선 근거로 삼지 않는다.
- 동일 사건에 대한 기준/후보 짝지은 비교, 재실행 일치, 최대 메모리와 처리 시간을 함께 확인한다.
- dev에서 정한 후보 하나만 잠금 자료에 평가한다. 허용 회귀·진입 개선·실행 비용 조건을 사전에 고정한다. 표본이 적을 때 임의의 통계적 유의성·대회 점수 향상을 주장하지 않는다.
