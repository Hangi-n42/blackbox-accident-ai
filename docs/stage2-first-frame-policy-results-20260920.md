# Stage2 확대 첫 프레임 상태 판정의 진입 선택 적용 결과

2026-09-20 KST. **새 사고 자료에서 확정 진입 오답 1건을 바로잡아 사전 성공 조건을 통과했다.** CCD_000052의 진입 출력이 f17(1.7초)에서 f0으로 바뀌었고, 나머지 11건은 그대로였다. 영상 중 진입 사례에서 잘못된 첫 프레임 선택은 발생하지 않았다. Mac의 실제 모델 호출 53회와 전문가 에이전트의 사전 검수·사후 독립 검증을 완료했다.

다만 시간 참조를 확보한 것은 선정 12건 중 3건뿐이다. **AI 참조와 전문가 상대표식을 사용한 제한된 정책 실험의 성공이며, 공식 S2나 자동 제출 성능 향상의 증거는 아니다.** 제출 코드는 변경하지 않았다.

## 무엇을 비교했는가

기준선은 기존 V6c Mac 경로의 영상당 네 질의다. 후보 정책은 그 결과를 공유하고, 표시된 사고 상대의 첫 프레임 상태를 확대 입력으로 한 번 더 질문한다.

- 유효한 `INSIDE` 응답: 진입을 첫 원본 프레임으로 설정한다.
- `OUTSIDE`, `UNCERTAIN`, 잘못된 응답 또는 표시할 상대가 없음: 기준선 진입을 유지한다.
- 접촉 시점·진입 방향·회피 공간: 기준선 출력 그대로 유지한다.

상태 질문·40토큰 출력 한도·모델·엄격한 JSON 파서는 앞선 해상도 실험과 같다. 입력은 노란 상부 표식이 있는 384×256 첫 프레임 타일을 최근접 보간으로 1152×768로 확대한 것이다. 원본 세부를 추가하지 않은 확대군도 앞선 실험에서 같은 개선을 냈으므로 이 조건 하나를 고정했다. 추가 해상도·프롬프트 탐색은 하지 않았다.

기준선 Q3는 기존의 표시 없는 12개 후보 시트를 사용한다. 따라서 이번 비교 대상은 **상대표식·확대 입력·별도 상태 질문·조건부 보정을 합친 정책**이다. 각 요소의 개별 인과 효과를 분리한 실험은 아니다. 실제 추가 입력은 모두 이미지 토큰 864개, 전체 입력 토큰 945개였다.

신규 600프레임과 기존 1,822프레임, 신규 MP4 12개와 기존 81개를 비교하고 최인접 장면 66쌍을 시각 대조했다. 검사 범위에서 정확 중복이나 같은 사고로 제외할 근거는 없었다. 다른 편집본·다른 카메라까지 포함한 완전한 사고 독립성 인증은 아니다.

## 측정 결과

정답이 구간이면 구간 전체에서 예측 오차가 ±0.3초 이내일 때 확정 정답, 어느 시각에서도 허용 범위를 만족하지 못하면 확정 오답, 나머지는 불확정이다. 구간 중앙값을 정답으로 만들지 않았다.

| 사례 | 고정 진입 참조 | 상태 응답 | 기준선 → 후보 | 판정 |
|---|---|---|---|---|
| CCD_000052 | 시작 전 진입, 제출 f0 | INSIDE | f17 → f0 | 확정 오답 → 확정 정답 |
| CCD_001237 | f8~21, 0.8~2.1초 | OUTSIDE | f24 → f24 | 불확정 유지 |
| CCD_000540 | f32~37, 3.2~3.7초 | OUTSIDE | f44 → f44 | 확정 오답 유지 |

| 지표: 시간 참조 3건 | 기준선 | 후보 |
|---|---:|---:|

동일한 실제 정답 시각을 두 정책이 공유하도록 비교하면, 적격 3건의 **정확도 차이는 +1/3, 평균 절대 오차 차이는 −0.5667초**다. 변화가 052 한 건의 1.7초 오차 제거뿐이고 다른 두 건은 같아서, 넓은 구간의 불확실성은 이 차이에서 상쇄된다. 이는 통계적 신뢰구간이나 공식 점수 추정이 아니다.

시작 전 진입 1건은 0/1→1/1이었다. 영상 중 진입 2건은 확정 오답 1·불확정 1로 같았다. 알려진 OUTSIDE 2건에서 INSIDE 오응답과 새 첫 프레임 선택은 모두 0건이다. 알려진 첫 프레임 상태 참조는 3/3 일치했다.

상태를 질문했으나 참조가 미상인 643은 `UNCERTAIN`, 022는 `OUTSIDE`여서 각각 f15·f12를 유지했다. 이를 상태 정답으로 세지 않았다. 표식 불가 7건도 기존 진입을 유지했다. 모든 추가 응답은 유효한 JSON이었으며, 전체 12건에서 **접촉·방향·공간 세 출력은 정확히 동일**했다.

사전 조건인 두 진입 유형 확보, 확정 개선 ≥1건, 확정/가능 정확도 손실 0건, 알려진 OUTSIDE 또는 영상 중 진입에서 새 첫 프레임 선택 0건, paired MAE 비증가를 모두 충족했다.

## 왜 개선됐고 무엇이 남았는가

052의 실제 사고 상대는 첫 프레임에서 가장 가까운 세단이 아니라 그 한 대 앞 차량이다. 두 독립 검수와 표식 QA가 같은 차량임을 확인했고, 그 차량은 첫 프레임에 이미 자차 차로 안에 있다는 참조에 합의했다. 별도 상태 질문이 INSIDE라고 답하면서 f0 제출 규칙이 적용돼 오답을 고쳤다. **영상 시작 전의 물리적 진입 시각을 복원한 것은 아니다.**

기존 Q3에도 “첫 이미지에서 이미 차로 안이면 첫 이미지를 선택”하라는 문장이 있고, 후보에도 f0가 있었다. 따라서 없던 규칙이나 후보를 추가해서 얻은 개선으로 설명할 수 없다. 별도 상태 판정을 조건부 선택에 연결한 전체 정책의 이득은 확인했지만, 기존 모델이 상대를 잘못 봤는지, 공간 관계를 틀렸는지, 시간 선택에서 틀렸는지는 번호 응답만으로 확정할 수 없다.

540은 첫 프레임 OUTSIDE 판정이 맞아 보정하지 않는 것이 정책대로다. 문제는 이후 진입을 f44로 늦게 선택한 것이다. 기존 후보 `[0,4,9,13,17,22,26,31,35,39,44,48]`에는 참조 구간 f32~37 전체에서 ±0.3초를 만족하는 **f35가 이미 있다.** 이 사례의 오류는 후보 누락으로 설명되지 않는다. 상대 식별·바퀴와 경계 인식·최종 시간 선택 중 어느 내부 단계가 원인인지는 아직 확인하지 못했다.

1237은 1.3초 폭의 진입 참조라 어떤 점 예측도 구간 전체에서 ±0.3초를 만족할 수 없다. 현재 f24는 실제 정답이 f21이면 경계상 정답이고 더 이르면 오답이므로 불확정이다. 이를 모델 정답 또는 개선으로 포장하지 않았다.

## 검증·실행 기록

최종 동결 1,793개 파일을 전후 대조했다. 17개 worker 모두 exit 0, 실제 질의는 기준선 48회와 상태 5회로 총 53회다. 독립 검증은 저장 답변으로 기준선 48개 질문·시트·출력을 CPU 재생하고, 상태 입력 5개의 전처리 텐서 해시를 재생해 모두 일치함을 확인했다. 상태 격자는 모두 `[1,48,72]`였다. 점수·구간·같은 정답 기준 차이·정책 분기·다른 세 출력 보존도 별도로 재계산했다. 검증기의 모델 로드·추론은 0회였다.

최초 실행은 부모 프로세스의 환경변수 중복 키워드 때문에 모델 호출 전에 실패했다. 중복 지정 한 항목만 제거했고, 실패 로그·코드·최초 동결본을 `attempt_00`에 보존했다. 입력·참조·질문·정책은 유지한 채 전문가 재검증과 새 동결 후 실행했다. 모델 응답을 본 뒤 코드를 조정한 재시도가 아니다.

완료된 부모 측 worker 경과 시간 합은 149.623초(기준선 130.523초, 추가 상태 19.100초)다. child worker 내부 시간 합 141.547초와 계측 범위가 다르다. 프로세스 시작·모델 로드 등을 포함하며 자료 취득·검수·독립 검증은 제외했다. 최대 MLX 메모리 6.092GB, 최대 프로세스 RSS 4,171,776,000바이트다. Linux/CUDA의 성능·수치 동등성이나 전체 제출 시간 예산을 측정한 결과는 아니다.

## 판단과 다음 실험 제안

**이 정책을 연구 후보로 유지할 근거는 확보했다. 제출 코드 승격은 하지 않았다.** 시작 전 진입의 독립 확인 사례는 1건이고, 시간 참조는 12건 중 3건뿐이며, 실제 모델이 자동으로 알아낸 상대가 아닌 전문가 상대표식을 사용했다. 출력 세 값의 보존은 접촉·진입이 같은 상대를 가리킨다는 의미적 일관성을 증명하지도 않는다.

다음 진단은 영상 중 진입 선택으로 옮기는 것이 적절하다. 540의 기존 후보 f31·35·39에서 같은 상대의 바퀴와 차선 경계 관계를 개별적으로 판별할 수 있는지 확인한다. 선택된 이미지만 보고 전체 영상의 최초 진입을 확정하지 않고, 상태 판별과 최초 접촉 시점 추정의 차이를 유지해야 한다. f35는 시점 허용 오차를 만족하는 후보이지만 진입 참조 구간 내부이므로, 그것만으로 f35의 차로 상태를 INSIDE 정답으로 정하면 안 된다. 각 후보의 상태 참조를 예측 전에 별도로 검수해야 한다. 비교할 때는 표식·질문·후보를 고정하고 축소/확대 중 한 요소만 바꿔야 한다. 이 한 사례는 이미 노출됐으므로 원인 진단용이며 새로운 성능 증명이 아니다. 자동 상대 지정과 별도 사고 자료의 정책 확인도 제출 적용 전에 필요하다. 이번 작업에서는 추가 변형을 실행하지 않았다.
