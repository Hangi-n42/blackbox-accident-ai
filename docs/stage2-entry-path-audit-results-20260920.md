# Stage2 진입 경로 재검수와 자동 시작 상태 보정

상태: Mac 신규 16질의 및 평가 완료. 보정 전후 출력이 같아 개선 0건, 단일 후보 채택 실패. 독립 실행 검증 PASS, 전문가 결과 검토 완료. 제출 경로는 유지한다.

## 재검수와 실제 제출 경로

기존 CCD 두 묶음 24건을 목록화하고, 이전에 진입 참조가 있던 8건을 새 응답을 보기 전에 고정했다. AI 전문가 A/B가 각자 8건의 전체 400프레임 시트와 필요한 원본을 다시 확인했다. 두 검수자 모두 같은 사고 상대를 확인했으며, 시작 전 진입 4건·영상 중 진입 4건이다. 단일 프레임으로 합의시키지 않고 두 검수 구간의 합집합을 참조로 사용했다. 나머지 16건은 기존 미상 상태를 유지했고 이번에 재검수·채점하지 않았다. 8건은 새 확인용 자료나 대표 표본이 아니다. 사람의 독립 정답 검수도 아니다.

실제 V6/V7 및 복원본의 Stage2 실행 모듈 6개는 바이트가 같다. 제출 기록상 V7 접수 92730이 존재하지만 현재 서버 상태를 조회한 것은 아니다. 기존 응답 96개를 24건의 실제 정책에 재생해 질문·입력 RGB·네 출력을 재현했다. 이 재생은 새 모델 호출 0회다.

진입 Q3는 최종 출력 collision_frame이 아니라 **내부 Q2가 선택한 접촉 프레임까지** 12개 후보를 만든다. 이후 motion 보정은 collision_frame만 바꾼다. 질문은 독립 호출이므로 Q3가 Q1/Q2의 상대 식별 이력을 전달받지 않는다.

| 사례 | 보수적 진입 참조 | 내부 Q2 / 최종 충돌 | 기존 진입 | 기존 판정 |
|---|---|---|---|---|
| 688 | 시작 전 → f0 | 47 / 38 | f13 | 오답 |
| 801 | 시작 전 → f0 | 36 / 39 | f13 | 오답 |
| 453 | f8–12 | 22 / 49 | f4 | 오답 |
| 196 | 시작 전 → f0 | 38 / 37 | f10 | 오답 |
| 728 | f26–30 | 38 / 36 | f14 | 오답 |
| 1237 | f8–22 | 33 / 44 | f24 | 불확정 |
| 052 | 시작 전 → f0 | 48 / 49 | f17 | 오답 |
| 540 | f31–38 | 48 / 49 | f44 | 오답 |

범위는 저장된 원본 번호와 PTS 0.0–4.9초(10Hz)를 사용한다. 시작 전의 f0은 제출 인코딩이며 실제 최초 진입 시점을 안다는 뜻이 아니다. 688은 도색 차로 없는 주행 통로, 052는 자차 움직임에 따른 차로 해석의 한계가 있다. 540의 시간 구간 재검수는 f35/f39의 개별 바퀴·차선 좌표를 확정하지 않는다.

**전체 입력 → Q2 이전 구간 → 12개 후보에서 참조 구간 커버리지가 모두 8 → 8 → 8로 유지됐다. 최종 선택은 확정 정답 0·확정 오답 7·불확정 1건이다.** 허용 오차는 ±0.3초를 포함한다. 넓은 구간의 각 가능한 시점에 맞는 후보가 존재한다는 뜻이며, 1237/540은 참조가 넓어 구간 전체에서 정답인 단일 후보는 없다. 나머지 6건은 그런 후보도 남아 있다. 8건 모두 원 응답이 제시 후보 번호라 파서 보정·실패가 원인은 아니다.

## 선택한 변경 하나

이 자료에서는 후보 누락보다 **최종 선택**을 먼저 개선할 근거가 있다. 후보 생성과 기존 Q3를 유지하고, 무표식 첫 프레임과 자동 Q2 접촉 문맥에서 같은 상대의 시작 상태를 묻는 보정 정책 하나를 고정했다.

- 입력은 1536×768 한 장. 왼쪽은 기존 384×256 첫 프레임의 nearest 3배 확대(1152×768), 오른쪽은 내부 Q2 인덱스 ±2의 최대 3장이다. 확대가 원본의 새 세부를 복원하지는 않는다.
- 전문가 표식·상대 좌표·정답 시점은 모델에 제공하지 않는다. 양쪽에서 같은 상대를 식별하고 첫 프레임 차로 관계를 INSIDE/OUTSIDE/UNCERTAIN으로 답한다.
- 엄격한 JSON INSIDE일 때만 entry_frame을 첫 원본 번호로 바꾼다. OUTSIDE/UNCERTAIN/형식 오류면 기존 진입을 유지한다. 나머지 세 출력은 기존 값을 복사한다.
- 새 원래 Q3 8회와 보정 질의 8회, 총 16회만 실행한다. 기존 Q3의 원시 응답·전처리 텐서 재현을 통제 조건으로 삼는다. 반복 조정은 하지 않는다.
- 사전 채택 기준: 확정 개선 최소 1건, 확정·가능 정확도 손실 0, 영상 중 진입을 f0으로 바꾼 사례 0, 평균 절대오차 변화 상한 ≤0, 두 유형 포함, 통제 재현 및 나머지 세 출력 보존.

입력 전문가 검수에서 **052의 자동 접촉 문맥 f46/48/49에는 상대가 없다는 한계**를 추론 전에 발견했다. 앵커를 정답에 맞춰 교체하지 않았다. 052에서 INSIDE를 확정하면 시점이 맞더라도 근거 없는 상대 연결로 별도 실패 처리하도록 사전 등록했다. 728/1237은 첫 프레임 상대가 작거나 가려져 있다. 입력 형식 PASS는 대상 식별 가능성이나 판단 정답의 보증이 아니다.

이 변경은 첫 프레임 확대·자동 문맥·이진 질문을 함께 사용하는 정책이다. 개별 요소의 인과 효과를 분리하는 실험은 아니다. 영상 중 최초 진입 위치를 다시 찾는 정책도 아니다.

## 실행 결과

Mac에서 16개 worker 모두 exit 0으로 끝났다. 새 원래 Q3 8건은 과거 원시 응답과 입력 전처리 해시를 재현했다. 보정 응답은 **8건 전부 유효한 JSON OUTSIDE**였고 INSIDE·UNCERTAIN·형식 오류는 모두 0건이다.

| 지표 | 기존 Q3 | 보정 정책 |
|---|---:|---:|
| 확정 정답 / 확정 오답 / 불확정 | 0 / 7 / 1 | 0 / 7 / 1 |
| 시작 전 진입 4건의 확정 정답 | 0 / 4 | 0 / 4 |
| 영상 중 진입 4건의 확정 정답 / 오답 / 불확정 | 0 / 3 / 1 | 0 / 3 / 1 |
| ±0.3초 정확도 가능한 범위 | 0–12.5% | 0–12.5% |
| 평균 절대오차 가능한 범위 | 0.9625–1.325초 | 0.9625–1.325초 |

정확도·평균 절대오차의 **같은 참조 시점에 대한 보정 전후 차이는 정확히 0**이다. 범위는 불확정 정답 구간 때문에 생기며 신뢰구간이 아니다. 개선·손실·새 거짓 첫 프레임 선택 모두 0건이고, entry_frame을 포함한 네 출력이 전부 유지됐다. 052의 근거 없는 INSIDE 조건도 발생하지 않았지만, 최소 개선 1건 조건을 충족하지 못해 정책을 채택하지 않는다.

## 원인 해석

확인된 사실은 두 단계로 나뉜다. 기존 경로는 이 8건에서 시간 후보를 유지했지만 선택에 실패했다. 새 정책은 첫 프레임 상태에 INSIDE를 한 번도 내지 않아 보정 자체가 활성화되지 않았다. 후자는 출력 불변의 직접 원인이다. 파싱 실패나 입력 생성 오류로 보정이 꺼진 결과는 아니다.

반면 **왜 전부 OUTSIDE를 냈는지는 state-only 응답으로 확정할 수 없다.** 같은 상대를 잘못 연결했는지, 차로·바퀴 관계를 잘못 읽었는지, 좌우 문맥이나 지시를 잘못 적용했는지를 분리할 출력이 없다. 801/196처럼 검수자가 같은 상대를 연결할 수 있는 입력에서도 개선되지 않아 052의 상대 부재만으로 전체 실패를 설명할 수 없다.

입력에서 확인된 제약은 052의 상대 부재, 728/1237의 작은 첫 프레임 상대와 가림, 688의 도색 경계 부재다. 첫 프레임은 이미 축소한 영상의 확대이므로 새 세부를 제공하지 않는다. 이 제약이 각 모델 응답을 실제로 유발했다는 인과관계까지 검증한 것은 아니다. 052에서도 UNCERTAIN 대신 OUTSIDE를 내므로, 불확실하면 기권하라는 지시가 정상적으로 작동했다는 증거도 없다.

이 결과는 자동 첫 프레임 보정 정책 하나의 실패다. 후보가 충분하다는 판정이나 최종 선택 개선 필요성이 뒤집힌 것은 아니다. 동시 변경한 문맥·확대·질문 각각의 효과도 분리하지 않았다. 공식 S2, 제출 서버 CUDA NF4 성능, 새로운 사고에서의 일반화 개선은 확인하지 않았다. 다른 세 출력은 캐시를 복사했으므로 그 정확도나 동일 상대의 의미적 일관성을 새로 검증한 것도 아니다.

## 검증과 다음 조치

독립 검증 **PASS(exit 0)**: 동결 2,056파일(이전 1,896 포함)의 전후 해시, 24건의 캐시 96응답 정책 재생, 신규 16개 worker와 CPU processor 텐서 해시, 엄격 상태 파서 및 구간 평가를 확인했다. 검증자는 모델을 추가 호출하지 않았다. 8개 gate 응답은 각각 12토큰 후 EOS로 끝나 40토큰 제한에 잘린 답이 아니다. 이미지 grid는 모두 [1,48,96], 이미지 토큰은 1,152개다.

16개 fresh worker의 부모 벽시계 합은 71.576초, 최대 MLX 보고 메모리는 6.0924GB, 최대 RSS는 3.8552GB였다. 영상마다 모델을 다시 불러오는 개별 질의 연구 실행이며, 제출의 모델 재사용·전체 네 출력 시간이나 Linux/CUDA 메모리를 뜻하지 않는다.

이번 정책은 제출에 반영하지 않는다. 결과 전문가도 **REJECT_FROZEN_CANDIDATE**로 판정했다. 원래 후보 범위는 유지됐고 zero-shot 상태 보정도 개선하지 못했으므로, 후속 후보는 **기존 12개 후보를 대상으로 학습하는 시계열 최종 선택기**로 제안한다. 자유생성 번호 선택을 바꾸고, 시작부터 진입한 경우와 영상 중 최초 진입을 함께 학습하는 방향이다. 효과는 미검증이며 이번에 학습하지 않았다.

선행 산출물은 별도 사고의 사람 검수 참조다. 같은 상대의 시간상 연속성·첫 프레임 상태·진입 전후 구간·가림/미상을 기록하고, 원 영상/사고 그룹으로 학습·개발·최종 검증을 분리해야 한다. 넓은 구간을 임의 중간점으로 바꾸지 않으며 현재 AI 참조 8건만으로 학습·검증을 겸하지 않는다. 같은 후보와 원본 시간으로 기준 대비 평가하고, 거짓 f0 선택과 상대 오식별도 따로 검수한다. 필요한 학습량이나 점수 개선은 현재 자료로 확인할 수 없다. 실제 채택에는 별도 검증과 제출 CUDA 실행 확인이 필요하다.
