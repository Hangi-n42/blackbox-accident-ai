# Stage3 데이터 정제·사용 계획 전문가 검토

검토일 2026-09-16. 사용자 전제대로 comma2k19, ADAS-TO, ZOD 사용 가능으로 놓고 기술·검증 설계만 검토했다. 다운로드·학습·새 성능 측정은 하지 않았다. 판정: 아래 수정 후 소규모 정제 파일럿 진행 적합. 성능 향상은 미검증.

## 확인 근거

- 기존 `research/stage3_strategy.md`: comma2k19 24개 구간을 취득했고 공개 중복 1개 제외, 23 route를 학습에 사용했다. 이미 사용한 구간은 새 독립 holdout이 아니다.
- `research/v6_stage3/summary.md`: OPEN_001과 comma 원본 1,200 decoded 프레임 해시가 일치한다. 기존 proxy 직접 감사에서 공개 가감속 10행 모두 CONSTANT였고, 조향은 9/10 일치했다. 가속/감속/정지의 proxy 정답 적합성은 이 감사로 검증되지 않았다. 깨진 컨테이너 PTS 대신 원본 frame_times 대응이 사용되었다.
- [comma 공식 구조](https://github.com/commaai/comma2k19): 두 차량, 약20km 고속도로, route/segment 구조, boot-time 센서·프레임 시간, 차속 m/s와 조향 degree. route 분리만으로 지리적 독립성을 보장하지 못한다.
- [ADAS-TO 공식 구조](https://github.com/OpenLKA/ADAS-TO): car_model/driver/route/clip 계층과 meta timing, carState의 실제 상태와 carControl 등 명령 데이터가 분리된다. 개입 전후 장면의 선택 편향이 있으므로 일반 주행 전체를 대표하지 않는다.
- [ZOD 공식 SDK](https://raw.githubusercontent.com/zenseact/zod/main/zod/data_classes/vehicle_data.py): 종속도·종가속도·조향각과 타임스탬프를 읽는 코드가 제공된다. 단위/좌표/시간 변환을 원본 필드대로 구현해야 한다.

## 승인 가능한 역할

1. comma2k19: 이미 확보한 영상·CAN을 파이프라인 회귀검사와 기준 학습에 재사용한다. 필요한 경우 미노출 route를 추가하되 같은 고속도로의 일반화 한계를 표시한다.
2. ADAS-TO: 정지·출발·제동·곡선 및 다양한 차종을 보충하는 학습/개발 자료다. 클래스 수량은 센서 기반으로 확인한다. 파일명·시나리오 stop/turn을 프레임 정답으로 복사하지 않는다.
3. ZOD: 소수의 별도 QA 구간에서 파서·부호·동기화만 검사하고 이를 개발 노출로 표시한다. 나머지 독립 drive 그룹은 최종 외부 검증으로 잠근다. ZOD 평가값으로 임계값·모델을 반복 수정하면 다음 실험에서는 그 평가셋을 개발 자료로 재분류해야 한다.

## 초안에서 반드시 보완할 사항

### 1. 분할 단위를 현실적으로 정의

차량/운전자/route를 동시에 전부 분리한다는 선언만으로 해결되지 않는다. comma는 차량이 둘뿐이다. 첫 분할은 수집 session/route와 중복 연결 그룹을 사용한다. ADAS는 driver 단위 분리를 우선하고 차종 분포를 기록한다. 차종 외삽 검증은 별도 가능한 경우에만 시행한다. 지리 중복은 지도/경로 정보가 있을 때 조사하며 없으면 미검증으로 남긴다. ZOD sequence들이 같은 drive 또는 중첩 시각이면 하나의 그룹이다. cross-dataset 중복도 썸네일 후보 검색 후 시계열 프레임으로 확인한다. 학습에 노출된 그룹 전체를 평가에서 제외한다.

### 2. 10Hz는 입력 시간 계약이며 센서 timestamp 대체물이 아니다

원본 영상·frame_times·센서 시각을 모두 보존한다. container PTS와 신뢰 가능한 별도 frame_times가 충돌하면 검증된 원천을 명시하고 근거를 기록한다. 10.1/20Hz를 단순 프레임 번호 나누기로 맞추지 않는다. 고정된 시간 그리드에서 선택한 원본 프레임의 실제 시각과 센서 대응 시각을 저장한다. 속도·조향의 결측 보간은 짧은 간격에 한정하고 허용 간격은 파일럿의 센서 주기를 확인한 뒤 학습 전에 고정한다. 긴 공백·비단조 시각·정렬 불명확 구간은 unknown이다. unknown은 학습/평가 mask에 적용하며 최종 추론의 모든 프레임 출력 의무는 그대로 유지한다.

### 3. 실제 상태 신호라고 해서 완전한 정답은 아니다

ADAS vEgo/aEgo/steeringAngleDeg를 사용하고 accel 명령·플래너 목표·모델 예측을 섞지 않는다. aEgo와 속도 차분 일치는 품질 진단이지 독립 센서 정답의 증명은 아니다. 실제 생성 경로와 필터 지연을 확인한다. comma의 기존 speed 미분, 속도 0.3m/s·가감속 ±0.25m/s²·조향 ±2°는 비교 기준 proxy로 보존한다. 새 정제 버전은 별도 버전으로 만들고 기존 결과와 비교한다. 자동차별 정답 점수가 좋아지도록 임계값을 맞추는 방식은 금지한다.

차량별 조향비·영점·부호가 확인되지 않는 경우 임의 yaw 변환으로 대회 조향 정답을 확정하지 않는다. 신뢰 가능한 좌우 방향만 보조 학습하고 경계는 unknown으로 두거나 해당 차종을 조향 학습에서 제외한다. yaw/영상은 교차 진단으로만 쓴다. 다른 차량의 조향각 절댓값을 하나의 임계값으로 통합한 결과는 대회와 일치하지 않는 proxy일 수 있다.

### 4. 파일럿 수량은 독립 샘플 수가 아니다

기존 comma 최대20구간 재점검, ADAS 최대50클립, ZOD QA 최대5 sequence는 초기 작업량 상한 제안이다. 동일 운전자·route·drive 반복이면 독립 근거가 아니다. 실제 메타를 본 뒤 그룹 수/클래스 지원/결측률을 기록하고 부족한 클래스와 촬영조건만 확장한다. 이 규모만으로 최종 일반화 성능을 주장하지 않는다.

## 최소 실험 설계

- 첫 비교는 기존 CPU 특징 추출기와 경량 분류기를 고정한다. 원본 baseline, 동일 새 정제 기준 comma-only 재학습, comma+ADAS 재학습을 비교해야 데이터 추가 효과와 proxy 변경 효과를 구분할 수 있다.
- 초기 자료별 가중치 comma:ADAS=1:1은 검증된 최적 비율이 아니라 사전 고정 후보 하나다. 전체 프레임 개수로 큰 자료가 지배하지 않도록 데이터셋→route→클래스 수준의 표본 가중치를 사용한다. 클래스 과샘플링이 원 분포를 바꾼다는 점도 기록한다.
- 평가 표본은 인위적으로 클래스 균등화한 진단과 실제 선택 분포를 구분해 기록한다. 4개 accel/3개 steer 클래스별 F1·지원 건수·자료별 점수와 0.7/0.3 가중 점수를 보고한다. 정답 STOPPED만 조향 점수에서 제외한다.
- 전환 구간을 모두 제외하면 쉬운 정답만 평가하게 된다. 신뢰 경계 밖 구간만 주평가에 넣되 별도 전환 진단 표본과 mask 비율도 반드시 보고한다.
- 학습/선택은 개발 split에서 마친 후 잠금 ZOD에 한 번 적용한다. 외부 평가가 악화하면 후보를 미채택한다. 과거 평가를 없었던 것처럼 취급하고 재튜닝하지 않는다.

## Go / No-go

정제 파일럿 Go: 시간/단위/부호의 근거와 원본 연결, 분할 사용 이력, unknown mask 및 클래스 지원 표가 생성되어야 한다. 필수 신호가 없는 자료는 해당 task만 제외할 수 있다.

학습 Go: 독립 개발 그룹과 신뢰 가능한 각 task 정답이 확보된 이후다. 모든 클래스를 지원하지 못하면 제한된 task 실험으로 표기한다.

모델 교체 Go: 개발 기준의 가중 F1 개선, accel 및 주요 소수 클래스 악화 없음, 잠금 외부 평가에서 개선 방향 재확인, 출력 계약·시간·메모리 검사를 함께 만족해야 한다. 구체적인 실용 최소 개선폭과 비열등 허용치는 평가를 보기 전에 정한다. 증거가 부족하면 기존 모델을 유지한다.
