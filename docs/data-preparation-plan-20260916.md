# Stage별 데이터 정제·활용 계획 — 전문가 검토 반영안

작성일: 2026-09-16. 실행 상태: 부분 진행. VDmoire/comma 파일럿과 Nexar 개발 비교를 수행했으며, UHDM·ADAS-TO·ZOD 확보 및 데이터 추가 비교는 미완료다. 상세 실행 기록은 `artifacts/data_pilot_20260916/progress.md`에 있다.

후속 사용자 지시에 따라 Nexar 검수는 전문가 에이전트가 수행한다. AI 참조임을 명시하고 관측·추론·불확실 구간을 구분하며, 사용자 직접 검수를 개발 실험의 선행 조건으로 요구하지 않는다. 아래 원안의 사람 검수 제안은 현재 실행의 필수 승인 절차가 아니다.

## 전제와 최종 구성

사용자 지시에 따라 ICL-COMMSP와 PREVENTION은 제외한다. VDmoire, UHDM, Nexar, comma2k19, ADAS-TO, ZOD는 사용 가능한 자료라는 사용자 확정 전제로 계획한다. 이전 이용조건 감사의 미확정 판정을 공개 라이선스가 새로 확인된 사실로 바꾸지는 않는다. 이번 계획의 승인 관문으로 라이선스를 다시 요구하지 않는다. 출처·이용조건 기록은 유지한다.

| Stage | 자료 | 역할 |
|---|---|---|
| 1 | VDmoire | 실제 화면 재촬영 영상의 중심 개발 자료. 원본/재촬영 대응 관계와 시간 정보가 확인된 부분 사용 |
| 1 | UHDM | 고해상도 공간 흔적의 보조 학습. 확인된 자연 사진 원본/재촬영 쌍만 초기 사용 |
| 2 | Nexar | 실제 자차 접촉 사건 선별, 대회 네 항목과 사고 상대 재주석, 개발 및 새로운 검증 구축 |
| 3 | comma2k19 | 기존 확보 자료 재사용, 센서 정렬과 대체 정답의 기준 개발 자료 |
| 3 | ADAS-TO | 차종·운전자·주행 상황의 학습 다양성 보완 |
| 3 | ZOD Sequences/Drives | 소량 QA 전용 원천과 별도의 잠금 외부 평가 원천. 학습에는 사용하지 않음 |

‘잠금 평가’는 모델/질문/임계값 선택에 사용하지 않는 최종 비교 자료다. 한 번 결과를 보고 설계를 바꾸면 이후에는 개발 이력을 가진 자료로 기록한다. 선정 조합의 성능 우월성을 이미 확인했다는 뜻은 아니다.

## 공통 정제와 분할

1. **목록부터 확인:** 기존 파일·취득 manifest를 재사용한다. 배포 revision, 소스 ID, 원천 영상/사건/주행 그룹, SHA256, 사용 이력, 촬영/차량 메타, 원본 시각 정보를 기록한다. 새 취득 시 필요한 파일과 예상 전송·저장량을 먼저 계산한다. 아카이브 부분 취득이 불가능하면 필요한 최소 아카이브 단위의 비용을 별도로 제시한다.
2. **원본은 보존:** 원본·정제 라벨·실행 캐시를 분리한다. 깨진 파일, 디코딩 실패, 대응 불명확 자료는 이유와 함께 격리한다. 기존 모델·결과·데이터를 덮어쓰지 않는다.
3. **분할 후 파생물 생성:** 같은 원본의 프레임/패치/재촬영/정렬 변형, 같은 사고의 재업로드, 같은 주행의 인접 구간은 한 그룹으로 묶는다. 파일 SHA는 바이트 중복만 확인하므로 표본 영상 유사성과 원천 메타도 검토한다. 프레임 단위 랜덤 분할은 하지 않는다.
4. **세 종류의 정답을 구별:** 공식 데이터 제공 라벨, 이번 대회 정의의 사람 검수, 센서에서 만든 대체 라벨을 혼합 표기하지 않는다. unknown은 음성 또는 0이 아니다. head/항목별 학습·채점 mask와 제외 사유를 기록한다.
5. **희소 클래스와 편향을 공개:** 원천 그룹 수, 클래스별 건수, 제외율, 장비/차량/날씨 분포를 먼저 보고한다. 파일럿을 임의로 60/20/20 분할해 최종 일반화 수치로 사용하지 않는다. 최종 분할과 채택 기준은 모델 예측을 보기 전에 동결한다.
6. **Mac에서 순차 처리:** 영상은 순차 디코딩하고 필요한 특징/선정 프레임만 캐시한다. 전체 영상을 PNG로 일괄 확장하지 않는다. 센서·영상·메타만 가져오고 사용하지 않을 LiDAR/radar와 새 대형 모델은 첫 단계에서 제외한다.

## Stage1 — 재촬영의 흔적을 보존하면서 출처 누출을 제거

### 정제

- VDmoire는 비정렬 원본 재촬영을 우선하고, 대응 소스 영상·장비 조합·정렬 v1/v2 여부를 연결한다. 같은 REDS/MOCA 원천에서 나온 여러 클립도 가능한 범위에서 묶는다. 공식 test 자료를 학습으로 돌리지 않는다.
- 선택된 60프레임을 연속 30fps라고 간주하지 않는다. 타임스탬프/선별 간격이 확인되기 전에는 절대 주파수에 기반한 시간 특징을 만들지 않는다. 초기에는 기존 프레임 특징과 영상 내 집계부터 사용한다.
- UHDM은 자연 사진과 문서/합성/출처 불명확 자료를 구분한다. 문서와 원본 여부가 확인되지 않는 clean GT는 첫 이진 분류 학습에서 격리한다. pairwise 보조 학습에도 자동 편입하지 않는다.
- 사진의 화면 재촬영 여부는 라벨 근거이고, 단순 압축·리사이즈 여부는 별도 속성이다. 해상도·테두리·색공간·보간·파일 형식이 정답을 대신 설명하는지 진단한다. 메타데이터는 분할/감사에만 쓰고 분류 입력에는 넣지 않는다.
- 네이티브 해상도 패치를 추출한다. 강한 노이즈 제거·모아레 제거·일괄 저해상도 축소는 하지 않는다. 전처리는 클래스별로 다르게 적용하지 않으며, 정렬 불확실한 쌍에서 같은 좌표가 같은 물체라는 가정도 하지 않는다.
- ‘도로 자료는 모두 ORIGINAL, 다른 출처는 모두 RERECORDED’ 구성은 만들지 않는다. 원본 그룹마다 파생 패치가 많아도 그 원본의 총 가중치는 제한한다.

### 활용

현행 TPO와 forensic 특징 계산을 우선 고정하고 가벼운 분류기/보정만 학습한다. 복원용 demoiré 모델은 설치하거나 학습하지 않는다.

- A: VDmoire의 검수 통과 영상만으로 학습한 후보.
- B: A에 UHDM의 검수 통과 사진 쌍을 보완한 후보.
- 대조: 현재 Mac Stage1을 그대로 평가.

UHDM은 정지 이미지 기반 공간 분기에만 사용한다. VDmoire는 프레임 점수를 영상 단위로 집계하는 판단에 사용한다. 이미지 반복으로 가짜 동영상을 만들어 시간 학습에 쓰지 않는다. 데이터 효과를 보려는 첫 비교에서는 새 시간 모델 구조까지 동시에 바꾸지 않는다.

### 검증과 한계

영상 Macro-F1, ORIGINAL/RERECORDED별 recall, 원천/장비별 성능, 원본에 대한 오탐을 기록한다. 패치 정확도를 독립 영상 정확도로 표시하지 않는다. 장비가 적으므로 장비 간 교차 평가를 하더라도 다양한 기기 일반화를 입증했다고 말하지 않는다.

기존 capture manifest의 실제 도로–물리 재촬영 대응쌍은 0개다. 선정 자료로 일반 재촬영 개발은 진행할 수 있지만, 도로 대응쌍 검증 전에는 도로 대회 성능 향상을 확정하지 않는다. 후속 검증은 권리가 확보된 별도 도로 원천을 화면에 재생해 실제 기기로 다시 촬영하고, 원본 및 모든 재촬영 변형을 개발 자료와 분리하는 방식이다. 이는 추가 대형 데이터셋 도입을 뜻하지 않는다.

## Stage2 — Nexar를 대회 정의의 사건 자료로 재구성

### 사건 선별

- 공식 train의 positive를 탐색하되 실제 블랙박스 자차와 상대 차량의 접촉이 있는지 검수한다. 이벤트 시점은 탐색 힌트일 뿐 접촉 정답으로 복사하지 않는다.
- near-miss, 제3자끼리 충돌, 접촉 자체를 확인할 수 없는 사례는 네 항목의 주 평가에서 제외하고 사유를 남긴다. 이를 네 항목의 0 정답으로 만들지 않는다. 사건 전에 끝나는 예측용 test 영상은 접촉 검증에 사용하지 않는다.
- 실제 접촉은 명확하지만 진입이나 방향이 가려진 사례는 전체를 버리지 않는다. 관측 가능한 항목만 남기는 mask 방식으로 쉬운 사건만 선별되는 편향을 줄인다.
- 원본 시각/PTS와 frame ID를 보존한다. Stage2 입력을 10fps로 통일하지 않는다. 최종 추론에는 제공 이미지 번호만 쓰며 평가용 PTS/주석 파일을 전달하지 않는다.

### 최소 재주석

| 항목 | 남길 내용 |
|---|---|
| 사고 상대 | 한 사건에서 계속 동일한 상대인지 확인. 첫 프레임, 진입 전후, 접촉 주변의 박스/클릭과 식별 메모 |
| 접촉 | 최초 물리적 접촉 frame ID·PTS, observed/uncertain/unknown, 필요시 가능한 시간 구간 |
| 진입 | 첫 바퀴의 자차 차선 경계 접촉. 영상 시작부터 이미 진입했다면 입력의 첫 frame ID |
| 방향 | 차량의 이동 방향이 아니라 화면 어느 쪽에서 진입했는지 |
| 회피 공간 | 접촉 당시 자차(대회 용어 피의차량)의 진행·회피 가능 공간. 상대 차량 공간과 혼동하지 않음 |

전 프레임 dense tracking 주석은 초기 범위에서 제외한다. 필요한 핵심 프레임의 상대 식별부터 확보한다. PREVENTION을 대체하는 새 데이터셋을 즉시 추가하지 않는다.

사람은 모델 예측을 보지 않고 판독한다. AI는 검수 구간 찾기/초안 정리에 사용할 수 있지만 최종 사람 정답으로 자동 승격하지 않는다. 잠금 평가의 접촉·진입과 사고 상대는 두 사람의 독립 초기 판독 후 불일치를 조정하는 방식을 제안한다. 두 번째 검수가 확보되지 않으면 단일 검수 초안이라는 한계를 유지한다. 불확실 구간을 임의 중간 시점으로 바꾸어 ±0.3초 정확도를 산출하지 않는다.

### 활용·평가

기존 사람 검토 9건은 개발 진단으로 유지한다. 예약 원본 6건도 기존 AI 검토/사용 이력을 확인하고 자동으로 새 독립 평가로 지정하지 않는다. 새 사건을 원천 그룹별로 개발 및 잠금 평가에 배정한다. 표본이 부족하면 가중치 학습보다 검증 자료 확보를 우선한다.

초기에는 현재 MLX VLM 가중치를 고정한 상태에서 사고 상대 확인, 첫 프레임 이미 진입 여부, 복수 시간 후보 구간의 생성과 선택을 각각 진단한다. 이전에 실패한 ‘한 구간 선택 후 계속 좁히기’를 그대로 재사용하지 않는다. 정답을 본 뒤 후보를 정답 근처로 옮기지 않는다.

지표는 접촉/진입 Accuracy@0.3초와 MAE, 방향/공간 Macro-F1, 후보 구간의 정답 포함률, 포함됐는데 잘못 선택한 비율, 상대 식별 실패, 진입>접촉 사례, 시간·메모리다. 항목별 분모와 unknown 비율을 공개한다. 전체 네 항목을 관측한 공통 집합이 있을 때만 그 집합에서 공식 형태의 S2 가중 점수를 별도로 계산한다. 서로 다른 분모를 합친 수치를 공식 S2라고 부르지 않는다.

## Stage3 — 시간과 센서 의미를 먼저 맞춘 후 자료 결합

### 정제

- 기존 comma2k19 획득분과 사용 이력을 재사용한다. 과거 학습/모델 선택에 노출된 23 route와 공개 OOF를 신규 독립 검증으로 재명명하지 않는다. 알려진 OPEN_001 동일 원천 route는 기존 제외 정책을 유지한다.
- ADAS-TO의 배포 revision을 고정하고 영상, meta, 실제 차량 상태 신호부터 취득한다. 초기 필수 신호는 vEgo/aEgo/steeringAngleDeg에 대응하는 상태다. 제어 명령·목표값과 clip 단위 stop/turn 시나리오를 프레임 정답으로 복사하지 않는다.
- 공통 단위·좌표 부호를 명시하고 프레임/로그 시계의 시작점·단위·단조성·지연·결측을 검사한다. 모든 자료에 하나의 FPS를 가정하지 않는다. 영상별 실제 시간 대응으로 대회용 10Hz 파생 입력과 센서 라벨을 연결한다.
- 긴 공백과 센서 범위 밖에서 끝값을 계속 유지하거나 무제한 보간하지 않는다. 짧은 공백 보간 한계는 QA 자료의 실제 주기에 맞춰 모델 예측을 보기 전에 동결한다. 정렬 실패 구간은 해당 head의 정답을 unknown으로 둔다.
- aEgo와 차속 미분의 일치도는 품질 검사다. 둘이 같다고 독립적인 정확한 정답이 입증되는 것은 아니다. IMU는 중력·차체 자세 보정 없이 종가속도 대용으로 사용하지 않는다.
- 조향 단위·부호·영점 및 신호 종류를 확인한다. 차종의 조향비나 대회 의미에 대한 변환 근거가 없으면 임의 yaw 변환이나 차종별 점수 맞추기를 하지 않는다. 해당 조향 라벨은 격리하고 가감속 등 확인된 항목만 사용한다.

### 대체 정답 생성

정지/가속/감속/등속, 좌/직진/우 범주를 만드는 규칙은 대회 공식 정답과 구분해 version을 기록한다. 기존 proxy 임계값을 출발 기준으로 보존하되 이를 공식 기준이라고 주장하지 않는다. 필터 지연·hysteresis·경계 불확실성을 QA 자료에서 확인하고 개발 예측 전에 고정한다.

모든 전환 구간을 제거해 쉬운 평가만 남기지 않는다. 신뢰 가능한 안정 구간과 전환 진단을 따로 보고하고 head별 mask 비율을 기록한다. 과거 정확 대응 공개 감사는 가감속 10행이 모두 CONSTANT여서 나머지 세 클래스의 정답 기준 검증을 대신하지 못한다.

### 분할과 학습

comma는 route 그룹 분리 및 별도 차량 스트레스 평가로 운영한다. 동일 고속도로를 공유하므로 route 분리가 지역 독립성을 뜻하지 않는다. ADAS는 driver 단위로 먼저 묶고 route/인접 클립을 같은 분할에 두며, 충분한 자료가 있을 때 차종을 통째로 남기는 별도 스트레스 검사를 한다. 두 자료에 같은 주행이 재수록됐는지도 확인한다.

ZOD는 소수 drive를 타임스탬프/신호 QA용으로 먼저 지정하고, 다른 drive의 평가 자료를 잠근다. 같은 drive에서 나온 sequence는 나누지 않는다. QA에 사용한 자료는 최종 외부 점수에서 제외한다. 최종 평가 신호는 동결된 라벨 생성 코드로 처리하며 그 결과로 임계값을 다시 조정하지 않는다.

초기 모델은 기존 광류 특징과 가벼운 head를 유지한다.

- A: 현재 Mac 모델 — 변경 없는 참고 기준.
- B: 새 정제를 적용한 comma-only 재학습.
- C: B와 같은 정제·특징·학습 설정에 ADAS-TO만 추가.

B−A는 정제와 재학습 변화가 포함된 비교, C−B는 통제된 데이터 추가 비교로 표시한다. 초기에는 각 데이터셋의 총 학습 가중치를 동등하게 두는 하나의 제안을 사전 고정하고, 내부에서는 driver/route 길이가 지배하지 않도록 그룹별 가중치를 정규화한다. 이는 최적 배합이 아니라 출발 설계다. 클래스 지원이 없는 자료를 억지 복제로 맞추지 않는다. 배합비 탐색을 ZOD 결과로 하지 않는다.

가감속/조향 Macro-F1, 0.7/0.3 결합 점수, 클래스·차량·주행별 성능, 전환 구간 성능과 마스크 비율을 기록한다. 조향은 참조 정답이 STOPPED인 행을 제외한다. 추론 결과는 정답 mask와 무관하게 모든 요구 프레임에 출력한다. 센서는 모델의 추론 입력이 아니다.

## 1차 작업량 제안과 순서

아래 수치는 품질 검사 작업량의 초기 제안이다. 취득 완료 수량, 충분한 학습량, 유의미한 정확도 추정에 필요한 표본 수를 뜻하지 않는다. 파일럿에 노출된 원천은 개발/QA 이력을 기록한다.

| 작업 | 1차 범위 제안 | 산출물과 확대 조건 |
|---|---|---|
| 공통 | 기존 원천/사용 이력 목록 | 원천 그룹·중복 후보·취득 비용·분할 계획 |
| Stage2 | 새로운 실제 접촉 사건 최대 30건을 목표로 선별. 근접사고는 수에 포함하지 않음 | 관측 가능 항목·상대 식별 주석·불확실성. 독립 사건/클래스가 부족하면 평가 확정 대신 추가 검수 |
| Stage1 | VDmoire 20원천 영상, UHDM 100원천 쌍 내의 정제 파일럿 | 원본 근거, 정렬/해상도 흔적, 장비·중복 연결. 검수 통과분만 후속 학습 후보 |
| Stage3 | comma 기존 23 route의 목록/정렬 이력 감사, ADAS 50클립 이내의 다양한 원천, ZOD 최대 5개 QA sequence | 실제 시계·단위·부호·결측·라벨 생성 가능 항목. QA와 다른 원천을 최종 평가용으로 확보 |

실행은 **공통 목록/분할 → Stage2 검수 기준 및 새 정답 구축 → Stage1/3 소량 QA → 데이터셋 하나씩 추가한 통제 실험 → 잠금 평가** 순서다. Stage1/3의 다운로드·신호 검사는 Stage2 사람 검수와 병행할 수 있지만 GPU 모델 실험은 순차 실행한다.

데이터 정제 gate는 원천/분할이 추적 가능하고, 라벨 의미·시간 대응·입출력 계약을 확인한 자료만 다음 단계에 보내는 것이다. 모델 채택은 고정 평가에서 해당 주 지표의 개선, 핵심 항목 회귀 여부, 원천별 편차와 실행 비용을 함께 확인한다. 소표본의 한 건 증가를 일반화 증명으로 쓰지 않는다. 임의 허용 회귀폭·기대 향상률·학습 시간을 이 계획에서 지어내지 않는다.

## 전문가 검토와 반영 기록

- [Stage1 검토](data-plan-review-stage1-20260916.md): 미확인 clean GT는 보조 학습도 격리, 파일럿의 작은 고정비율 분할 삭제, 실제 시간 간격 확인, 기존 특징 우선, 도로 대응 검증의 한계 반영.
- [Stage2 검토](data-plan-review-stage2-20260916.md): 항목별 unknown, 자차/상대 용어, 최소 상대 식별 주석, 독립 검수/불확실 구간, 30건의 통계적 한계 반영.
- [Stage3 검토](data-plan-review-stage3-20260916.md): 기존23 route의 개발 노출, ZOD QA/평가 분리, A/B/C 대조, 센서 QC와 정답 구분, task별 mask와 전환 진단 반영.

통합안 재검토에서 Stage1·Stage2·Stage3 담당 에이전트 모두 **설계 수준 통과**로 판정했으며, 필수 권고의 누락이나 중대한 오류를 발견하지 못했다. 데이터 품질이나 성능을 실제 실행으로 통과시켰다는 의미는 아니다.
