# Stage1 새 원천·시간 표본·선형 head 실험 결과

2026-09-19. 결론: **시간 표본 23개 후보와 학습한 선형 head 모두 이번 제출에는 채택하지 않는다. V7 유지.** 자료 확대, 실제 추론, 실제 head 학습, 원본 회귀 검사까지 수행했다. 새로운 제출이나 V7 코드·가중치 변경은 하지 않았다.

## 1. 새 원천과 두 번째 촬영 장비 확보

VDmoire `frames/val/Reds`의 22개 폴더에서 대표 재촬영 프레임을 받고 REDS 공식 val_sharp의 대응 원본을 확보했다. 22쌍을 AI가 시각적으로 확인했고 SIFT 대응도 모두 얻었다(최소 inlier 38). 폴더 번호만으로 대응을 단정하지 않았다.

모델 점수를 보기 전에 val **001, 004, 012, 013, 014**를 선택했다. 001은 도로가 인접한 광장, 004는 역 앞 보행 공간이므로 012/013/014의 도로·거리와 구분해 기록했다. 모두 주행 블랙박스가 아닌 handheld 거리 자료다. val014와 기존 train142는 관련된 거리로 보이며, 서울·튀르키예 지역도 기존 자료와 겹친다. **새 원천 ID이지만 독립 장소·세션 평가라는 주장은 하지 않는다.**

이전에는 찾지 못했던 공개 **tcl.zip 링크**를 실제 Dropbox 폴더 UI에서 확인했고, ZIP 목록과 필요한 프레임을 취득했다. 공급자 장비는 iPhoneXR/MacBook Pro와 TCL20 Pro/HP v270이다. 전체 iPhone 13.3GB, TCL 23.1GB 압축파일을 받지 않고 HTTP Range로 필요한 항목만 받았다. 일부 iPhone 요청이 HTTP 200을 반환한 경우 본문 전체 취득을 막고 누락 항목만 재시도했다.

최종 자료:

- 기존 iPhone 16원천에 11시점씩 추가하고, 새 iPhone 5원천의 23시점 양 클래스를 구성: 총 966이미지.
- 동일 새 5원천의 TCL 대응 23시점 양 클래스: 230이미지.
- 합계 1,196이미지, 실제 콘텐츠 원천은 **21개이며 새 원천은 5개**다. 두 장비나 변형을 다른 독립 원천으로 세지 않는다.
- 기존 384개 기본 입력은 파일 바이트 그대로 재사용했다.
- iPhone 신규 기하검사 최소 inlier 609, 최대 중위 재투영 오차 0.877px, 화면 경계 최소 여유 26.63px.
- TCL 115개 시점 대응 최소 inlier 54, 최대 중위 재투영 오차 1.285px, 화면 경계 최소 여유 191.97px.
- 두 장비 모두 화면 내부 native640×360 사각 crop 및 대응 원본 bounding crop을 사용했다. 원근 워핑하지 않았으며 두 클래스에 JPEG95를 공통 적용했다. 서로 다른 장비의 crop 시야·시간도 달라 순수한 장비 효과만 분리한 실험은 아니다.
- 시간 대응은 약 3개 재촬영 프레임/원본 프레임 관계를 사용한 근사다. 정확한 동기화 정답이 아니다. 전 원천의 모든 선택 시점에서 기하 검사를 통과했다.
- 원본·부모 파일 SHA 검사 및 source ID 분할 중복 검사 통과. 장소/세션 독립성은 미확인.

## 2. 12시점 → 최대23시점

가중치·전체 화면 전처리·원래/좌우 반전 50:50·임계값0.5를 유지했다. 기존 대리자료의 12시점 `[1,5,11,16,21,27,32,38,43,48,54,58]`을 보존하고 각 간격의 정수 중간 인덱스 11개를 추가했다. 사전에 정한 기본/JPEG75/블러σ1의 개발 Macro-F1이 엄격히 증가해야 확인용으로 진행한다.

이 대리자료의 12시점은 이전 실험과 동일한 끝부분 제외 규칙이다. 실제 V7 MP4 sampler의 0..N-1 균등12시점과 구분한다. 실제 sampler의 기존 시점 보존 여부와 짧은 영상의 중복 제거는 별도 runtime probe에서 검사했다.

| 개발 8원천, 주요3조건 | V7 12시점 | 23시점 |
|---|---:|---:|
| Macro-F1 | 0.894691 | 0.894691 |
| 원본 오탐 /24 | 5 | 5 |
| 재촬영 누락 /24 | 0 | 0 |
| 원본/재촬영 판정 변화 | — | 0 |

스트레스 JPEG50과 1/2축소에서는 원본 오탐이 각각1건 줄었다. 블러σ2 결과는 동일했다. 이 사후 관측으로 주요 선택 기준을 바꾸지 않았다. **개발 gate 실패로 기존 확인용 및 새 자료에서 23시점 후보를 평가하지 않았다.** 새 자료는 아래 사전 고정 head 실험에서 사용했으므로 이제 향후 연구의 미노출 평가 자료라고 부를 수 없다.

CPU2스레드에서 96기록의 순수 TPO 전처리·추론 평균은 0.5975→1.1463초(약1.92배). 기존 V7 확률 재현 차이는0.

실제 공개 MP4 10개에서 V7 시점과 동일한 12개에 중간 인덱스를 추가하는 별도 probe를 실행했다. 디코딩 포함 6.929→13.259초, 판정 변화0, baseline은 실제 V7 진입점 결과와 일치. 모델 적재는 제외한 warm CPU 측정이다. 이 공개 자료의 변화0을 새로운 일반화 성능이라고 제시하지 않는다. 이 probe는 fail-fast 진단이며 새로운 제출용 decoder 구현이 아니다.

## 3. 고정 TPO 특징의 작은 분류기 실제 학습

TCL 자료 확보 후, 충분한 대규모 일반화 학습을 선언하는 대신 탐색용 단일 head pilot을 수행했다. 시각 backbone은 V7 그대로 고정했다. 학습은 기존 개발8원천, 개발 평가는 기존 확인8원천으로 나눴다. 새 val5원천의 두 장비는 학습에 쓰지 않았다. 이 프로토콜은 새 val 모델 점수를 보기 전에 저장했다.

- 정규화된 512차원 V7 시각 특징에 L2 logistic head(513개 계수).
- C=1, lbfgs, tol=1e-8, max_iter=2000, seed=20260919. 하이퍼파라미터 탐색 없음.
- 학습 입력은 12시점×원래/반전×기본/JPEG75/블러1. 총1,152프레임 관측이지만 학습 콘텐츠는8원천이다.
- 프레임 가중치1/72로 원천·클래스별 전체 가중치를1로 유지했다. 전체 학습 가중치16.
- 실제9회 solver iteration으로 수렴, 저장된 head의 확률과 sklearn 확률 최대 차이0.
- 추론은 프레임별 확률 평균, 임계값0.5. TPO head 교체와 도로 자료·3조건 학습이 묶인 후보이므로 블러 증강만의 효과를 분리한 실험은 아니다.
- 개발 Macro-F1이 증가하고 원본 FP가 늘지 않을 때만 새 자료를 평가했다. 결과 확인 후 재학습·계수·임계값 조정 없음.

| 평가 자료, 주요3조건 | V7 F1 | 새 head F1 | V7 오탐/누락 | 새 head 오탐/누락 |
|---|---:|---:|---:|---:|
| 기존 개발평가8원천, 클래스별24 | 0.895788 | 1.000000 | 2 / 3 | 0 / 0 |
| 새 val5원천 iPhone, 클래스별15 | 0.799107 | 1.000000 | 4 / 2 | 0 / 0 |
| 같은 새 val5원천 TCL, 클래스별15 | 0.753231 | 1.000000 | 7 / 0 | 0 / 0 |

이 표만으로 제출을 결정하지 않았다. 새5원천과 변형3조건을 독립15원천으로 계산하지 않는다. 장비를 제외했어도 공급자·원본 처리·지역·모아레 수집 목적의 편향은 남는다.

## 4. 실제 주행 원본과 공개 예제에서 발견한 회귀

head를 고정하고 기존 comma2k19 원본23개와 공개 Stage1 예제10개를 추가 검사했다. 이 검사는 새 자료의 높은 성능이 다른 입력에 전이되는지 확인한 사후 회귀 점검이며, 새 미사용 공식 평가라고 주장하지 않는다.

| 검사 | V7 | 새 head |
|---|---:|---:|
| comma2k19 원본 오탐 /23 | 5 | 1 |
| 공개 예제 원본 오탐 /5 | 1 | **5** |
| 공개 예제 재촬영 누락 /5 | 2 | 0 |
| 공개 예제 Macro-F1 | 0.696970 | **0.333333** |

comma의 개선은 새 오탐0·기존 오탐4건 해소다. 반면 공개 예제는 모든10개를 재촬영으로 분류했고, S1_O_002~005 네 원본에서 새 오탐이 생겼다. 해당 원본 확률은0.5401, 0.5278, 0.5369, 0.5306이다. 공개 파일은 `Baseline/data/stage1/original` 및 `rerecorded` 원본 파일과 바이트 동일하며 `labels.csv` 라벨과 대조했다. 파일명만 추측한 라벨이 아니다.

**새 head를 제출 후보로 채택하지 않는다.** 제한된 재촬영 수집 자료에서는 잘 분리하지만 공개 원본의 분포로 옮기면 심한 오탐 회귀가 발생했다. 모델이 수집·전처리 특유 단서를 학습했을 가능성은 가설이며, 어떤 시각 특징이 원인인지 인과적으로 입증하지 않았다. 새 자료 F1=1.0 또는 comma 오탐 감소만 강조하면 이 실패를 숨기게 된다.

## 보존·재현과 다음 판단

V7 원본48파일 해시가 모두 유지됐다. head 실험의 코드·가중치 및 데이터 QA 해시 불변, source ID train/dev/test 중복0, 저장 결과로 혼동행렬 재계산, public CSV 라벨 확인을 통과했다. raw-video guard 네트워크 시도0. 새 제출은 하지 않았다.

다음 학습은 실제 주행 원본의 다양한 카메라·압축·야간 등을 학습/개발에 넣고, 원본 회귀 검사도 최초 채택 기준에 포함해야 한다. 이번 공개 예제를 보고 임계값만 올리거나 이 다섯 원본만 추가학습해 같은 예제로 다시 검증하는 것은 다음 독립 개선 증거가 아니다. 지금 LoRA까지 확장하면 모델 용량을 늘리는 동안 확인된 자료 편향을 유지할 수 있으므로 진행하지 않았다.
