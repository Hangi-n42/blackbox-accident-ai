# 0·1순위 실행 결과 — 2026-09-16

## 판정

0순위의 Mac 출력 반복성 오류를 수정하고 14건 기준을 재측정했다. 독립 사람 정답과 L40S 실제 실행 검증은 아직 없어 0순위 전체가 완료된 것은 아니다. 1순위의 진입 시점 개선 후보 하나를 구현·측정했지만 사전 기준을 통과하지 못해 채택하지 않았다. 기본 정책은 버그를 수정한 기존 Mac 정책이다.

## 0순위: 원인과 수정

설치된 mlx-vlm 0.3.4 Qwen3-VL의 `_deepstack_process`는 2차원 `[batch, sequence]` 마스크에 `np.where(mask)[0]`을 적용한다. 이는 토큰 위치가 아닌 배치 위치다. 배치 1에서는 중복된 0번 위치에 서로 다른 시각 특징을 기록한다. 프로젝트의 `scripts/mac/deepstack_fix.py`는 실제 `(batch, sequence)` 위치를 사용한다. 설치된 Transformers 4.57.6의 같은 모델은 이미 boolean mask로 해당 토큰을 선택하고 있어 교정 의미와 일치한다.

별도로 다중 이미지 특징을 개별 길이로 split한 뒤 concat하는 코드에서, 길이가 감소하면 특징을 중복시켜 이미지 토큰과 개수가 어긋나는 오류가 확인됐다. 공개 S2_002에서 tokens 480 / features 576으로 실행 실패했다. 이미 순서대로 연결된 특징에서 불필요한 split/concat을 제거했다. 실패 실행은 보존했다.

패키지 파일·가중치·V6 코드는 수정하지 않았다. 수정은 Mac 실행 프로세스에만 적용되고 mlx-vlm 버전이 다르면 중단한다. 동기식 greedy 생성은 토큰별 logits 해시를 남긴다. seed 고정이나 답변 캐시로 반복성을 대신하지 않았다.

- 동기 생성만 적용: 답변 변동 지속.
- float32 연산 적용: 진입 예측 변동 지속. 기본값으로 채택하지 않음.
- 마스크 수정 후 공개 2건 AB/BA/AB: 답변·예측·각 토큰 logits 해시 일치.
- 기존 비동기 디코더에 마스크 수정 적용한 대조군: 같은 답변·예측.
- 14건 실행: 모든 worker exit 0, 98/98 응답 JSON 파싱 성공.
- 원래 모델 인터페이스 대비 독립 NumPy 수치 테스트 2개, 다중 이미지 길이 테스트 1개, 진입 후보 계약 테스트 2개 통과.
- 기존 기준 결과 93개 파일의 SHA256 모두 유지.

긴 검토 영상 역순 반복 결과는 아래 최종 확인 절과 실험 폴더 `human_repeat_comparison.json`에 기록한다.

## 새 기준과 1순위 실험

같은 worker에서 기존 정책의 네 질의 결과를 `baseline_prediction`으로 보존한 뒤 진입 후보의 추가 질의를 수행했다. 기준/후보가 서로 다른 실행 변동 때문에 달라지는 비교를 피했다. 접촉·방향·공간은 후보에서 수정하지 않는다. 추론 함수에는 정답·PTS·사례 ID를 전달하지 않는다.

후보는 접촉 이미지 문맥의 같은 차량을 찾도록 지시하고, 전체 영상 12개 후보에서 진입을 고른 후 이웃 구간을 두 번 세분화한다. 최대 7회 질의다. 구현을 동결한 뒤 점수를 계산했으며 점수를 보고 질문을 재조정하지 않았다.

| 검토 자료 지표 | 버그 수정 후 기준 | 진입 후보 |
|---|---:|---:|
| 접촉 Accuracy@0.3초 | 4/9 | 4/9 |
| 접촉 MAE | 3.7323초 | 3.7323초 |
| 진입 Accuracy@0.3초 | 0/8 | 1/8 |
| 진입 MAE | 12.6237초 | 13.5838초 |
| 방향 Macro F1 | 0.533333 | 0.533333 |
| 공간 Macro F1 | 0.181818 | 0.181818 |

공개 5건의 접촉은 4/5로 유지됐다. 공개 다른 세 항목의 정답은 없으므로 점수화하지 않았다. 위 9건은 이미 노출된 단일 사람 검토 초안이다. 항목별 분모가 달라 공식 Stage2 점수나 종합 점수로 표시하지 않는다. Stage1/3는 이번에 변경하거나 재측정하지 않았다.

**후보 미채택:** 진입 정확도는 한 건 증가했지만 MAE가 0.9601초 악화했다. 사전 조건은 정확도 증가와 MAE 감소를 동시에 요구했다. 독립 자료 검증도 없는 상태다.

오류 분해 결과, 수정 후 기준의 진입 후보 정답 구간 커버리지는 4/8이다. 후보의 전체 탐색/첫 세분화/마지막 세분화 커버리지는 2/8 → 2/8 → 1/8이었다. 00006은 첫 프레임이 정답 후보에 있었지만 최종 좁히기에서 제외됐다. 00003만 정답 허용 구간에 들어왔다. 첫 구간 선택이 틀리면 후속 세분화가 회복하지 못하는 구조가 확인됐다. 사고 상대를 실제로 정확히 추적했다는 증거는 확보하지 못했다.

수정 후 기준과 후보 모두 최종 진입이 최종 접촉보다 늦은 경우는 1건이다. 예전 버그 포함 측정의 4건과 직접적인 후보 효과로 섞지 않는다. 최종 접촉 보정과 VLM 문맥의 불일치는 남아 있다.

14건 기준+후보 실행은 worker 합계 482.09초, 최대 MLX 메모리 6.0924GB였다. 후보의 추가 VLM 질의 시간 합계는 58.68초다. 전체 서버 처리 시간 추정치가 아니다.

## 남은 0순위 조건과 다음 실험

검증 후보 원본 00017/18/19/21/22/23 여섯 파일의 해시를 확인하고 별도 manifest로 보존했다. 기존 개발 원본과 동일 바이트 파일은 없다. 기존 AI 검토가 존재하므로 사람 정답이나 완전한 미노출 자료로 간주하지 않는다. 사고 상대·접촉·진입·불확실 구간의 사람 검수와 같은 사고의 중복 여부 확인이 필요하다.

서버 계약은 `docs/mac-stage2-validation-contract.md`에 정리했다. 현재 Metal 실행기를 Linux/L40S에 그대로 제출할 수 없다. 보존된 CUDA/Transformers 로더에 동일 입출력·질의 계약을 적용하고 실제 서버에서 별도 기준을 측정해야 한다. Mac MLX 4bit와 CUDA NF4의 수치 동등성을 가정하지 않는다.

다음 성능 실험은 작은 후보 구간을 잘못 고르면 회복 불가능한 구조를 먼저 바꿔야 한다. 사고 상대의 식별 확인, 복수 진입 구간 유지, 첫 프레임에 이미 진입한 경우의 판정을 분리하는 설계를 새 사람 검수 자료와 함께 사전에 고정하는 순서를 권고한다. 이번 실패 자료에 맞춘 추가 프롬프트 튜닝은 하지 않았다.
