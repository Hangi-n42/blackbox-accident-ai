# Stage 3 동등 계산 CPU 최적화 후보

2026-09-11 로컬 CPU 측정. 기존 제출 코드·가중치·ZIP은 수정하지 않았다. 후보는 `solution/stage3_fast.py`, 재현 스크립트는 `research/benchmark_stage3_fast.py`, 상세 결과는 같은 디렉터리의 `report.json`이다. 공개 정답이나 private 점수는 읽지 않았으며 학습·파라미터 탐색도 수행하지 않았다.

## 변경 내용

기존 특징 함수는 12개 ROI의 4개 채널마다 median, percentile20, percentile80을 별도로 호출했다. 후보는 ROI마다 채널축을 묶어 median 한 번, percentile(20,80) 한 번을 호출한다. 통계 함수 호출은 flow당 144회에서 24회로 줄었다. median을 percentile50으로 바꾸지 않아 기존 float32 중간값 연산을 보존했다. 분위수 보간 기본값, ROI 정수 경계, 채널 순서, 출력 float32 변환, 후속 시간 요약과 보간은 같다.

좌표 그리드와 ROI 경계는 각 `extract_motion` 호출 내부에서 생성하는 객체에만 저장한다. 해상도가 바뀌면 갱신하며 다음 파일에는 새 객체를 만든다. 파일 간 입력·특징·모델 상태를 공유하지 않는다. 모델은 기존 파일을 읽기만 한다. 추가 패키지나 가중치는 필요 없다. 후보 모듈은 기존 `solution.stage3`의 상수 및 `transfer_features`를 import하므로 후보를 패키징할 때 기존 모듈도 포함해야 한다.

공개 영상별 출력은 600/601/599/599/599행으로 모든 해독 프레임을 보존했다. 두 입력의 ID·sample_index·가감속·조향을 포함한 DataFrame 전체가 동일했다. 가감속 변경 0행, 조향 변경 0행이다. 6개 파일의 최종 특징 총 5,182,272개도 float32 비트 단위로 전부 동일했으며 최대 절대오차는 0이었다. 따라서 **측정한 입력의 예측 성능은 변하지 않았다.** 다른 입력 전체에 대한 수학적 증명이나 서버 실측 결과는 아니다.

별도로 동일 optical-flow 입력에서 합성 16개(4해상도, 영·상수·난수·큰 값)와 실제 flow 29개를 비교했다. 특징 6,480개 모두 비트 동일, 최대오차 0. 같은 flow 집합을 3회 처리하는 특징 함수 측정은 1.616초에서 0.526초로 줄었다(3.07배 속도).

## 측정 조건과 제한

- Windows 11, NumPy 1.26.4, OpenCV 4.10.0. OpenCV 및 BLAS/OpenMP threadpool은 2개로 제한했다. GPU는 사용하지 않았다.
- 실제 `predict_stage3`를 호출하여 영상 해독, 특징 계산, 가중치 로딩과 예측을 포함했다. 메모리에 특징을 보관하는 동일한 검사 wrapper를 양쪽에 적용했으며 CSV 저장과 특징 비교 시간은 실행시간에서 제외했다.
- 각 전체 입력은 구현당 1회 측정했다. 공개는 기존→후보, 외부는 후보→기존 순서로 실행했다. 신뢰구간을 측정하지 않았으므로 서버 시간 감소를 같은 비율로 보장할 수 없다.
- 보유 comma2k19 클립은 약 1분이다. 외부 긴 입력은 기존 `Chunk_1/b0c9d2329ad1606b_2018-07-27--06-03-57/10/video.hevc`에서 20Hz의 매 두 번째 프레임을 취해 10Hz로 저장하고 5회 반복한 5분 MP4다. 자연스러운 연속 5분 운전이나 독립 검증 데이터가 아니다. 긴 파일에서 계산 동등성과 실행시간만 확인하는 스트레스 입력이다. 연결 경계도 양 구현에 동일하다.
- 전체 실험은 스트레스 영상 생성 포함 182.97초였다. 새 외부 데이터 다운로드는 없다.
