# PUBLIC_DEV_001 사용자 검수 기반 V5 개발 진단

사용자가 제공한 원본 검수 파일을 보존하고, 원본 영상·검수 프레임·실제 V5 로컬 출력 및 같은 정책의 과거 상세 로그와 대조했다. 새 모델 추론은 실행하지 않았다. 이 결과는 기존 공개 개발 영상 한 건의 단일 사람 검수에 대한 진단이며 독립 정확도 검증이 아니다.

## 무결성과 미입력

원본 영상 SHA-256, 검수 화면의 전체 프레임 목록 해시가 일치했다. 별도 에이전트가 원본을 순차 디코딩해 50개 전부의 시각과 PNG 픽셀까지 독립 대조했다. 검수의 frame 33 = 3.3초, frame 24 = 2.4초는 모두 0부터 시작하는 번호로 정확히 대응한다. 1부터 시작하는 번호와 혼동한 흔적은 없다.

최초 JSON의 회피 공간은 빈 문자열이었으나, 사용자가 이 대화에서 명시적으로 ‘공간 있음 (1)’으로 보완했다. 원본 JSON은 변경하지 않고 user_reviews/PUBLIC_DEV_001_space_addendum.json에 질문·답변·원본 해시를 보존했다. 이에 따라 네 평가 항목 모두 사람의 응답은 확보했다. notes는 비어 있지만 선택 항목이며 시각 대응 검사를 막지 않는다. 독립 2차 검수·불일치 조정은 없다. 이것은 개발 진단을 금지하는 조건이 아니며 확정 정답/검증 집합 채택과 구분하기 위한 내부 품질 기준이다. 대회가 검수자 2명을 요구한다는 의미가 아니다.

## 후보 누락과 선택 실패

| 항목 | 사용자 검수 | V5와 같은 정책의 실제 기록 | 진단 |
|---|---|---|---|
| 최초 접촉 | 33번 / 3.3초 | 정밀 후보 14개에 33번 포함. VLM은 33번 선택. 최종 출력은 motion 규칙으로 35번 / 3.5초 | 장면 누락 없음. 최종 대체로 0.2초 늦어지지만 ±0.3초 안이므로 이 영상의 시점 오답은 아님 |
| 차선 진입 | 24번 / 2.4초 | 원본 50개와 디코드 정상 50개에 포함. 충돌 전 탐색 0..33에도 포함. 최종 후보 12개에 24번 포함. 최종 선택 24번 | 탐색 범위 절단·후보 샘플링 누락·선택 실패 모두 관측되지 않음 |
| 진입 방향 | RIGHT | 첫 요약 응답 LEFT, 최종 LEFT | 사람 검수와 불일치. 형식 오류나 기본값 대체가 아닌 유효한 LEFT 응답 |
| 회피 공간 | 후속 답변: 있음(1) | 최종 0 | 사람 검수와 불일치. 모델 원문도 0이며 파싱 실패에 따른 기본값 대체가 아님 |

공식 공개 접촉 정답은 32번 / 3.2초로, 사용자 검수보다 0.1초 앞선다. 원본/시각 매핑은 정상이나 접촉 판정은 1프레임 차이가 있다. 공식 값을 덮어쓰지 않았다. V5 최종 3.5초는 공식 정답 대비 +0.3초, 사용자 대비 +0.2초다. 두 기준 모두 허용오차 안이며 경계 계산은 십진수로 확인했다. 네 항목 응답이 채워졌어도 이 한 건의 개발 진단을 전체 Stage2 성능이나 독립 검증 점수로 보고하지 않는다.

## 코드로 확인한 오류 전파

실제 V5 패키지의 stage2_v2.py는 첫 10개 요약 프레임에서 받은 entry_side를 side 변수에 저장하고 최종 출력까지 유지한다. 이후 접촉 질문은 collision_frame만, 진입 질문은 entry_frame만, 공간 질문은 evasion_space만 받는다. 따라서 이후에 진입 프레임 24번을 올바르게 골라도 첫 방향 LEFT를 수정하는 경로가 없다.

이 사례에서 확인한 것은 **방향·공간 응답의 사용자 검수 대비 불일치와 방향 재검토 경로 부재**다. 공간 질문은 내부 접촉 33번을 기준으로 31·33·35번 세 장면을 사용하고 0을 응답했다. 다른 사고 차량을 보았는지, 이동 방향과 출현 방향을 혼동했는지, 작은 이미지나 공간 기준이 원인인지는 현재 로그만으로 확인할 수 없다. 모든 영상의 좌우나 공간 값을 일괄 뒤집는 수정은 정당화되지 않는다.

## 이어서 할 작업

1. 제공된 사람 검수와 회피 공간 보완 답변을 함께 보존했다. 최초 JSON의 공란을 임의로 덮어쓰지 않았다.
2. 나머지 기존 공개 영상은 추가 개발 진단에, 새 Nexar 검수 후보는 실제 충돌 여부·대상·시간·원천 중복 확인에 사용한다. 기존 공개 영상의 오류를 고쳐 새 독립 검증 성공으로 기록하지 않는다.
3. 여러 검수에서 방향 불일치가 반복되면, 같은 충돌 상대의 진입 전후 장면에서 방향만 재판정하는 후보를 시험한다. 접촉·진입·공간 출력을 고정해 방향 변경의 효과를 분리한다. 추가 호출의 시간 비용도 제출 제한 안인지 측정한다. 현재 한 건만으로 이 후보를 채택하거나 점수 상승을 예측하지 않는다.
4. 후보 장면 누락이 다른 영상에서 확인되면 그 유형의 빈도를 먼저 기록하고, 해당 탐색 구조를 별도 실험으로 수정한다. 이번 영상에서 발생하지 않은 오류를 발생한 것으로 취급하지 않는다.
