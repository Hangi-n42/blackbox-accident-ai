# 실행 결과와 스키마 수정 기록

최초 `v5_fullframe_error_decomposition` 실행은 기존 개발 recorder가 응답을 `raw_output`에 저장했는데 진단 코드가 `raw`만 요구하여 실패했다. 초기 출력 계획은 덮어쓰지 않았다. 수정은 원래 응답 저장 키 `raw`/`raw_output`를 모두 읽도록 한 부분뿐이다. 두 키가 동시에 있으면 동일 문자열인지 확인한다. 응답이 없으면 예측값으로 역생성하지 않고 중단한다.

새 폴더에서 실제 CPU 진단을 실행하여 완료했다. 원본 평가·실행 보고서·동결 파일·사람 주석·기존 코드의 SHA 연결을 확인했고, 기존 evaluator의 `known_labels` 함수를 재사용했다. 픽셀·광류·GPU·모델 호출은 없었다.

- 접촉 fine 후보의 ±0.3초 포함은 기존 10Hz 3/6에서 전체 프레임 4/6으로 바뀌었다. 내부 모델 선택은 양쪽 모두 0/6이다. 전체 프레임의 후보가 포함된 00000/00004/00005/00007에서도 내부 선택은 틀렸다.
- 최종 광류 교체 후 전체 프레임 접촉은 0/6이다. 내부도 0/6이므로 이 전체 프레임 실행에는 맞던 내부 접촉 답을 최종 교체가 틀리게 만든 사례가 없다. 기존 10Hz의 00000은 오히려 최종 광류가 틀린 내부 답을 맞게 바꾼 사례다.
- 전체 프레임 진입의 알려진 5개 중 00000은 균등 후보 누락, 00007은 내부 접촉으로 제한한 앞부분 범위 누락, 00003/00005/00006은 후보가 있는데 선택 실패다. 00004의 진입은 unknown으로 남겼다.
- coarse/fine/entry의 12개 영상·샘플링 조합, 총 36회 선택을 기존 `_choice`로 재현했다. 모두 제공된 번호를 수락한 경로다. 범위 밖 번호 대체·무효 응답 기본값은 없었다. 따라서 관측된 접촉·진입 오류를 파서 fallback 문제로 설명할 수 없다.
- 전체 프레임의 알려진 방향은 2/4, 공간은 1/6 일치다. Unknown을 분모에 넣지 않았고 종합 S2는 계산하지 않았다.

6개 원천은 모두 이미 사용한 데이터이며 정답은 단일 사용자의 초안이다. 결과는 기존 V5의 내부 오류 위치를 설명하는 진단이고, 새로운 독립 검증이나 후보 모델 개선 결과가 아니다. 세부 6행 표는 `summary.md`, 모든 후보·시각·파서 경로는 `report.json`에 있다.
