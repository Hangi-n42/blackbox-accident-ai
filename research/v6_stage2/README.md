# V6 Stage2: 정답 연결 및 오류 분해 도구

**최신 상태 — 2026-09-15:** 추가 검수 4파일의 무결성을 확인했고 00003·00006 방향, 00004 진입은 미상으로 유지했다. 로컬 10Hz+끝점 입력과 전체 프레임 입력의 차이를 진단한 결과, 전체 V5는 접촉 0/6·진입 0/5·방향 2/4·공간 1/6이었다. 전체 프레임에서 동일한 고정 C를 CPU 재계산하면 접촉 3/6, 평균 절대오차 9.3720235806741→1.7929193899782134초이며 다른 세 출력은 동일하다. 기존 10Hz 예약 실패는 유지되고, 이번 통과는 새 사람 검수 00008·00010·00013 평가로 진행할 수 있다는 의미뿐이다. 6개 모두 노출 자료이며 공식 S2·채택·제출 승인이 아니다. 자세한 결과와 오류 분해는 [후속 보고서](review_followup_result_20260915.md)를 참고한다. 아래 내용은 최초 감사 도구의 범위와 당시 상태를 보존한 기록이다.

제출 코드·모델·패키지를 바꾸지 않은 CPU 전용 개발 감사 도구다. 모델 import, GPU 호출, 새 추론, 학습 또는 제출 기능은 없다. 새 확정 정답 없이 기존 공개 자료를 성능 개선 근거로 재활용하지 않는다.

## 완료한 작업

- `SCHEMA.md`: 원천·분할·노출·실제 충돌 상대·원본 번호/PTS·인간 조정 기록 계약.
- `audit.py`: 기존 호출 기록을 보존하는 `normalize_trace`, 동결된 기존 V3 기록의 `import-archive`, GT 검증 및 `evaluate`.
- `test_audit.py`, `cpu_contract.json`: 합성 계약 16개 통과. 시간 변환, 원본 번호 offset, 상한/격자/선택/디코드 누락 분리, 누락 정답, 전체 클래스 Macro-F1, 증거 변조 거부, AI·단일 검수 거부, 파일별 독립성 검사. 합성 정답으로 얻은 숫자는 실제 모델 성능이 아니다.
- `archived_v3_jpeg_trace.json`: 기존 동일 JPEG의 V3 정책 호출·원시 응답·후보·최종 선택 기록 5개. 기록 입력 250개 파일 SHA와 동결 manifest를 재확인했다.
- `public_pts/*.json`: 제공 원본 영상의 native PTS와 rational time_base를 CPU 순차 디코딩해 보존했다. 영상 해시, 대응 JSON 해시 및 inline 대응 내용까지 검증한다.
- `public_official_partial_gt.json`: 기존 공식 충돌 정답만 초 단위로 연결했다. 정답이 없는 세 항목은 null이다. 공개 자료 노출은 development로 명시했다.
- `public_partial_audit_final.json`: 현재 최종 평가기 결과. 기존 공식 충돌 4/5, 진입·방향·회피공간·전체 S2는 null이다. `public_partial_audit.json`은 추가 collision 후보 coverage를 넣기 전 결과이며 실제 V5 소스/모델 manifest/예측 연결 근거를 담고 있어 보존했다.

실제 V5 상세 호출 로그가 새로 생긴 것은 아니다. 기존 V3 archived trace의 실행 소스 5개와 실제 추출 V5 소스의 SHA가 같고, 모델 파일별 동결 SHA map이 같으며 공개 5개 출력이 실제 V5 검증 CSV와 같다는 연결을 기록했다. 이번 감사에서 모델 가중치를 다시 로딩하거나 전체 가중치 바이트를 재해시하지 않았다. 상세 기록은 끝까지 **동등 정책의 기존 개발 로그**로 표기한다.

## 오류 분해

확정 진입 GT가 있으면 허용 오차 ±0.3초 내 후보 존재 여부를 다음 순서로 검사한다.

1. 입력 전체 원본 프레임: 여기서 없으면 원본 시간 표본 범위 누락.
2. 정상 디코드된 프레임: 여기서 없어지면 읽기/디코드 필터 손실.
3. 내부 VLM 충돌 시점까지의 prefix: 여기서 없어지면 충돌 상한 전파에 의한 누락.
4. 실제 제시한 최대 12개 진입 후보: 여기서 없어지면 후보 격자 누락.
5. 최종 선택: 후보 안에 정답이 있었는데 선택하지 못한 경우 선택 오류.

각 단계의 가장 가까운 실제 시간 오차, 전체 후보 수, 진입 GT가 내부 충돌보다 뒤인지도 별도로 기록한다. 충돌은 최종 motion과 내부 VLM 시점의 부호 있는 시간 오차 및 후보 coverage를 분리한다. 실제 최초 진입인지 불명확한 구간 주석은 이 정답 평가에 사용하지 않는다.

`valid_first_selected_semantics_unverified`는 형식상 유효한 첫 번호 선택이다. 이를 이미 차로 안에 있었다는 관측으로 부르지 않는다. 잘못된 JSON의 첫 프레임 fallback, 범위 밖 숫자의 후보 snap도 분리한다. 기존 코드가 독립 질문 사이에서 충돌 상대 ID를 강제하지 않는다는 의미적 한계는 감사기가 자동 해결하지 못한다.

전체 S2는 같은 선언 cohort에 네 정답이 모두 있어야 계산한다. 부분 구성 점수에는 해당 항목의 라벨 수/전체 영상 수를 기록한다. 범주 점수는 방향 LEFT/RIGHT와 공간 0/1을 모두 포함하는 Macro-F1이며, 정의된 범주 중 분모가 0인 F1은 0이다. 공식 시간 허용 오차 외에 임의 후보 채택 문턱을 넣지 않았다.

## 사용

워크스페이스 기준 실행 예시:

```text
.venv\Scripts\python.exe -B research/v6_stage2/audit.py evaluate --gt <확정정답.json> --trace <기존기록.json> --output <새감사결과.json>
.venv\Scripts\python.exe -B research/v6_stage2/test_audit.py
```

`--root`는 증거 파일 경로를 해석하는 워크스페이스이며 하위 명령 앞에 지정한다. 모든 결과 저장은 기존 파일이 있으면 거부한다. 주석 도구의 단일 검수 초안은 바로 넣지 않는다. 독립 검수 두 개와 조정 증거를 갖춘 확정 문서만 human_adjudicated로 받을 수 있다. 해시와 스키마는 문서 연결 및 일관성을 검사할 뿐 검수자의 신원·실제 독립성·판정의 정확성을 인증하지 않는다.

현재 확정 entry GT가 없어 실제 데이터의 상한/격자/선택 오류 비율은 **확인 불가**다. 완전한 새 정답 cohort를 확보한 뒤 기존 정책을 고정한 채 이 분해를 실행해야 한다. 공개 5개 재사용 결과나 형식 검사 통과로 V6 개선을 주장할 수 없다.
