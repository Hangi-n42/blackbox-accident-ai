# 상대 차량 설명을 제공한 개발 진단

이전 목표 회차는 진행으로 분류한다. 추가 검수 반영, 실제 V5 세 개발 영상 비교, 두 수정 후보의 실행·실패 평가가 완료되어 다음 행동을 바꿀 근거가 생겼다. 이번 진단은 그 실패를 덮어쓰거나 제출 후보 탐색 제한을 우회하기 위한 것이 아니다.

## 실행

개발 00000/00003/00004에 한해 검수자가 적은 상대 차량 설명을 영어로 옮겨 제공했다. 원문·번역·파일 해시는 freeze.json에 보존했다. 00003의 “검정색으로 보이는”이라는 불확실성도 유지했다. 정답 프레임·시각·상자 좌표를 질문에 넣지 않았다.

V6A의 실제 입력 모자이크, 후보 목록, 질문, 48토큰, NF4 모델과 픽셀 예산을 유지하고 차량 설명 문장만 앞에 추가했다. 개발 영상당 1회, 총 3회만 실행했다. 예약 영상에는 실행하지 않았다. 실행 전후 코드·모델·파일 결합 검사를 통과했고 네트워크 요청은 0회였다.

## 결과

| 영상 | 원래 A 응답 | 사람 설명 제공 후 응답 |
|---|---|---|
| 00000 | null | null |
| 00003 | 615 | null |
| 00004 | 1044 | null |

추가 설명을 제공해도 유효한 접촉 프레임을 선택하지 못했다. 원래 fallback 규칙을 적용하면 모두 V5의 출력 587/345/594를 유지한다. 이는 접촉을 관찰해서 맞춘 결과가 아니다.

근거가 있는 결론은 **이 사람 설명 제공만으로는 현재 영상 입력에서 접촉 선택이 해결되지 않았다**는 것이다. 모델이 설명을 올바른 차량 픽셀에 연결했는지 확인하지 않았으므로 차량 오식별 가설이 반증된 것은 아니다. 설명 조건부 성공이 나왔더라도 자동 차량 식별 성능의 증거로 사용할 수 없다.

## 다음 판단

확정된 명세 오류가 아닌 상태에서 ‘visible contact evidence’ 문구를 완화해 같은 개발 사례를 다시 맞추는 후보는 실행하지 않았다. 기존 질문이 반드시 차체 접점의 직접 노출을 요구한다고 단정할 수 없고, 간접 단서 허용과 운동 단서 안내를 함께 바꾸면 원인 분리도 되지 않는다는 전문가 비판을 수용했다. contact_criterion_review.md에 근거를 남겼다.

다음에는 V5가 선택한 잘못된 큰 움직임의 실제 수치 성분을 분해한다. 카메라 움직임 추정 오류를 확인할 수 있는 경우에 한해, 질문 변경과 독립된 해당 성분 수정 후보를 검토한다. 이 진단 결과로 예약 평가를 개방하거나 제출 후보를 채택하지 않는다.

이 파일과 freeze.json/report.json/analysis.json은 모두 비채택 진단 기록이다. 모델 학습·새 공식 정답 생성·V6 제출은 수행하지 않았다.
