# 성능 원인에 대응하는 수정 제안

2026-09-13. 사용자 요청에 따라 Stage 1·2·3 전문가가 설계안을 제시하고 상호 검토했다. 아래는 실행 순서와 채택 조건을 정한 제안이며, 이번 요청에서 추론 코드·가중치를 변경하거나 새 학습·제출을 수행하지 않았다. 현재 비교 기준은 제출 V3 87666이다. 점수 상승 폭은 아직 예측할 근거가 없다.

## 전체 우선순위

1. 진단 도구와 검증 정답을 먼저 정리하되, 모든 데이터 수집이 끝날 때까지 구현 검토를 미루지는 않는다. 기존 자료로 입력·시간 정합성과 오류 분해 도구부터 검증한다.
2. Stage 2를 첫 구조 개선 대상으로 둔다. 충돌·진입 정확도의 낮은 상한이라는 직접 근거가 있고, 후보 누락·선택 실패·충돌 문맥 전파를 분리할 수 있다.
3. Stage 3의 시간·라벨 정합성 진단은 병행한다. 외부 자료를 무조건 제거하거나 이미 실패한 회귀 파이프라인을 그대로 재도입하지 않는다.
4. Stage 1은 디코딩과 전처리 진단을 먼저 수행하고, 실제 도로 재촬영 양성 검증을 갖춘 뒤 특징·결합을 바꾼다.

각 실험은 한 가지 변경을 기준 모델과 비교한다. 후보 선정용 개발 검증과 마지막 확인용 미사용 원천을 구분한다. 같은 원본의 프레임·변형·재촬영 파생물이 서로 다른 분할로 넘어가지 않도록 한다. 개선 판단은 대회와 같은 집계 방식의 점수와 원천별 오류를 함께 사용하며, 프레임 수를 독립 사고·촬영 표본 수로 계산하지 않는다.

## 공통 진단 도구

입력 파일별로 디코딩된 원본 번호/순번, 선택 프레임, 모델에 제시한 영역, 후보 집합, 응답 파싱 실패, 각 출력, 처리 시간을 기록하는 개발용 도구를 만든다. 정답이 있는 검증 자료에서만 오류 원인을 분석한다. 평가 추론에서는 학습·설정 갱신 없이 같은 파일의 정보만 사용한다.

Stage 2는 네 항목의 실제 정답과 프레임 시각이 필요하다. 공개 5개에 추가 주석을 만들면 정의 점검에는 사용할 수 있지만 독립 성능의 근거가 되지는 않는다. Stage 3는 가감속·조향의 개별 지표와 클래스별 표본 수를, Stage 1은 원본 오탐과 재촬영 미검출을 분리 기록한다. 출력 형식 통과를 정확도 검증으로 해석하지 않는다.

## Stage 2: 제한된 프레임 선택을 계층적 사건 분석으로 수정

### 1. 먼저 후보 누락과 선택 실패를 나눈다

정답 시각 ±0.3초 안에 제시 후보가 하나라도 있는 비율과, 그러한 후보가 있을 때 실제 모델이 맞히는 비율을 따로 측정한다.

| 진단 결과 | 대응 수정 | 채택 판단 |
|---|---|---|
| 정답 부근 프레임이 후보에서 빠짐 | 진입 coarse 이후 이웃 구간을 다시 나누는 fine 탐색 | 실제 후보 포괄률과 진입 적중률 개선 확인 |
| 정답 후보는 있으나 잘못 선택 | 같은 후보에서 원본 이미지의 차량·바퀴·차선 영역을 추가 관찰 | 후보를 바꾸지 않은 대조에서 선택 오류 감소 확인 |
| 질문마다 다른 차량을 판단 | 동일 상대의 기준 프레임과 표시된 참조 이미지를 후속 질문에 전달 | 상대 식별 오류와 네 항목 점수를 따로 확인 |
| 충돌 오류가 진입/회피로 전파 | 최종 충돌 출력과 후속 판단의 충돌 문맥을 일치시키는 별도 실험 | 다른 세 항목의 손익과 Stage 2 전체 점수 확인 |

영역 crop은 축소 타일을 확대하는 것이 아니라 원본 픽셀에서 가져온다. 회피공간에는 전체 도로·주변 차량·도로 경계도 함께 보여 준다. 사람이 표시한 영역/상대를 쓰는 초기 실험은 개선 가능성을 측정하는 진단일 뿐 제출 성능이 아니다. 자동 영역·상대 선택의 오류는 별도 평가해야 한다.

### 2. 현재 V3의 내부 문맥과 최종 충돌 정책을 분리 검증한다

V3의 VLM 정밀 충돌 출력은 최종 collision_frame으로는 사용하지 않지만, 진입 후보 상한과 회피공간 관찰 위치에는 쓰인다. 따라서 이 호출을 없애는 것은 단순한 속도 최적화가 아니다.

| 후보 | 호출 구성 | 변경 범위 |
|---|---|---|
| 기준 V3 | overview → VLM collision fine → entry coarse → space | 기존 4회 |
| 실험 A | overview → entry coarse → space | 최종 motion 충돌을 내부 문맥에도 적용하고 collision fine 제거, 3회 |
| 실험 B | overview → entry coarse → entry fine → space | A에 진입 세밀 탐색만 추가, 4회 |

A는 motion 충돌 자체가 틀리면 다른 항목도 악화시킬 수 있다. 따라서 A를 먼저 검증하고, 그 손익을 확인하기 전 B로 묶어 배포하지 않는다. A가 손해라면 VLM 충돌 문맥을 유지한 별도 탐색안을 검토해야 하며, 이 경우 추가 호출 비용을 다시 측정한다.

기존 `solution/stage2_entry_refine.py`의 원본 번호 보존·이웃 구간 선택·비정상 응답 fallback은 재사용 후보이다. 이 모듈은 coarse 구간 밖의 진입을 복구하지 못하고, 지역 구간 첫 프레임이 실제 영상 시작을 뜻하지도 않는다. coarse 선택 불확실성이 큰 경우 이웃 구간 하나로 한정하는 설계의 실패율도 측정한다.

입력의 시간 정보가 없으면 10FPS를 가정하거나 ±3프레임을 대회 허용오차로 사용하지 않는다. 추론은 정렬된 원본 번호/위치로 후보를 관리하고, 검증에서 확보한 실제 시각으로 ±0.3초를 평가한다.

### 3. 실행 시간

첫 설계는 VLM 4회 상한을 유지하는 방향으로 검토한다. 호출 수가 같아도 crop과 참조 이미지를 추가하면 시각 토큰·메모리·시간이 늘어난다. 긴 영상 스캔까지 포함해 측정해야 한다. V3 서버 42분38초라는 과거 관측은 새 설계의 60분 통과를 보장하지 않는다.

수정 접점: `solution/stage2_v2.py`, `solution/stage2_motion_collision.py`, `solution/stage2_entry_refine.py`, `solution/vlm_candidate.py`. 후보별로 별도 모듈/결과를 남기고 현재 제출 코드를 덮어쓰지 않는다.

## Stage 3: 시간·목표 정의를 확인한 뒤 학습 가중치와 특징을 수정

### 1. 먼저 검증할 내용

- 같은 디코딩 이미지열에서 20Hz/stride2 학습 경로와 10Hz/stride1 추론 경로의 프레임 대응·특징 배율을 직접 비교한다.
- 영상 프레임과 CAN timestamp의 범위·누락·정렬을 검사한다.
- 정확히 대응하는 공개 원천 구간에서 모델을 거치지 않고 현재 proxy 범주와 제공 정답을 비교한다. 차이가 있으면 목표 불일치의 증거가 된다. 소수 공개 정답으로 미공개 공식 임계값을 확정하지 않는다.
- 같은 예측을 전체 10Hz와 공개 예제처럼 희소한 시점에서 각각 평가해 전환 구간 및 희소 평가 영향을 구분한다.

### 2. 학습 수정 후보

외부 proxy를 모두 공식 정답과 같은 신뢰도로 취급하는 현재 결합에 대해, 출처별 학습 가중치를 분리하는 단일 실험을 한다. 후보 범위는 결과를 보기 전에 제한하고, 모델·특징·분할을 고정해 비교한다. 클래스 균형 가중치와 출처 신뢰도 가중치는 다른 목적이다.

라벨이 불확실한 표본을 낮게 가중하는 방안은 CAN 누락·시간 정합성 등 확인 가능한 근거와 분리해 설계한다. 자체 임계값에서 멀리 떨어져 있다는 사실만으로 공식 정답과 일치한다고 보증하지 않는다.

### 3. 특징 수정 후보

현재 원래 광류 특징을 보존하면서, 카메라 전체 움직임과 국소 잔차를 구분하는 보조 특징을 추가하는 작은 비교부터 진행한다. 전역 움직임을 일괄 제거하면 자차 운동의 신호까지 없앨 수 있으므로 원래 특징을 제거하지 않는 추가 방식부터 시험한다. 자동 움직임 분해가 큰 전방 물체에 끌리는 오류도 점검한다. 이후에만 전용 시간 모델이나 학습형 운동 표현의 필요성을 판단한다.

### 4. 이미 실패한 방법의 취급

공개 GT만 사용한 모델은 이미 시험됐고 최선 개발 점수는 0.585921로, 현재 외부 혼합의 0.798298보다 낮았다. 이 비교 자체도 작은 공개 검증의 한계가 있지만 외부 자료를 즉시 삭제할 근거는 아니다.

연속 CAN 값을 먼저 예측한 뒤 분류한 기존 transfer 방법도 개발 점수 0.575300으로 낮았다. 같은 방법을 새 유망 해법처럼 재도입하지 않는다. 다시 연구하려면 연속량 예측이 차량/경로 분리 검증에서 유효한지부터 확인하고, 기존 공간 특징 압축·목표 단위 처리와 같은 설계 차이를 별도로 검증해야 한다.

배율 증강과 단순 시간 평활화도 기존 결과가 개선을 지지하지 않았으므로 기본 수정안에서 제외한다. 이 부정적 결과를 모든 증강·시간 모델의 실패로 일반화하지 않는다.

검증은 차량 내 경로 분리와 차량 간 분리를 나누고, 두 차량만으로 광범위한 차량 일반화를 입증했다고 주장하지 않는다. 수정 접점: `research/train_stage3.py`, `solution/stage3.py`, `solution/stage3_fast.py`. Stage3 fast의 기존 출력 동등성은 유지하고 새로운 특징·모델은 별도 버전으로 검증한다.

## Stage 1: 실제 재촬영 증거를 보존하는 입력·특징·결합으로 수정

### 최소 변경

`sample_video`의 seek 선택을 순차 디코딩 기준과 비교하고 선택 인덱스·실제 픽셀·프레임 수를 검사한다. 문제가 확인되면 동일 목표 위치를 순차 읽기로 얻는 fallback을 검증한다. 정상 영상의 선택 픽셀과 결과가 유지되는지 확인하며, 이 수정만으로 점수 상승을 주장하지 않는다. Stage3의 고정 FPS 가정을 Stage1에 적용하지 않는다.

기존 DLC와 comma는 서로 다른 개발 진단으로 유지하면서 원본/재촬영 양쪽에 동일한 압축·배율 변환을 적용해 오류와 확률 변화를 비교한다. 변환 자체가 모아레·주사무늬를 지울 수 있으므로 모든 변환에 확률이 불변이어야 한다는 목표를 세우지 않는다.

### 검증 자료 확보 뒤 비교할 모델 변경

1. 원해상도 패치를 유지하며 여러 크기의 패치 특징을 비교한다. TPO 전체 화면 문맥과 내부 영역의 정보를 나누어 시험하고, 테두리 제거가 실제 재촬영 증거를 잃게 하는지도 확인한다.
2. 현재 프레임 확률 평균에 짧은 연속 프레임의 밝기·주사무늬·상대 움직임 특징을 추가하는 작은 모델을 비교한다. 정상 주행 흔들림·와이퍼·반사에 대한 오탐도 측정한다.
3. 기존 0.5/0.5 결합을 기준으로 개발 분할에서만 소수 파라미터의 확률 보정/정규화된 결합을 학습하고, 미사용 원천·기기에서 확인한다. 비율을 임의 조정하거나 TPO 단독으로 즉시 교체하지 않는다.

필요한 검증 자료는 실제 도로 원본과 화면 재촬영의 대응 자료이다. 원천 콘텐츠와 촬영 카메라/디스플레이 분리를 각각 확인한다. 도로 재촬영 양성이 없으면 위 모델 변경의 블랙박스 일반화 개선을 주장할 수 없다.

수정 접점: `solution/stage1.py`의 프레임 선택·패치 집계·결합, `solution/stage1_tpo_merged.py`의 이미지 입력 처리.

## 채택과 제출 기준

- 개발 검증에서 변경이 겨냥한 오류가 줄었는지 확인하고, 후보를 고정한 뒤 별도 미사용 검증으로 확인한다. 불확실한 소수 표본의 최고값만으로 개선을 선언하지 않는다.
- 대회와 같은 Stage 지표와 가중합을 사용한다. 하위 지표의 손익을 공개하고 종합 개선 여부를 판단한다. 모든 하위 지표가 무조건 동시에 올라야 한다고 요구하지는 않지만, 특정 클래스의 붕괴를 총점 뒤에 숨기지 않는다.
- 실제 해제 ZIP의 오프라인 실행·원본 번호·전 프레임 출력·데이터 독립성·크기·시간을 확인한다. 시각 모델 호출 수만으로 시간을 보장하지 않는다.
- 검증 자료·모델의 권리와 출처를 보존하고 비공개 평가 데이터로 학습·보정하지 않는다. 새 후보를 기존 최고 제출과 비교하고, 실험 여러 개를 한꺼번에 섞어 변화의 원인을 잃지 않는다.

이 제안의 첫 산출물은 더 큰 모델이 아니라 Stage 2의 후보/선택 오류표, Stage 3의 시간/라벨 정합성 결과, Stage 1의 입력/기기별 오류표다. 그 결과가 각각 탐색 수정·학습 수정·결합 수정의 채택 여부를 결정한다.


### 출처 가중치 실험의 구체 후보와 추가 교차검토

Stage3 담당은 공개/외부의 총 유효가중치를 1:1로 맞추는 단일 대조를 제안했다. 이는 올바른 비율이 확인됐다는 뜻이 아니라 시험할 하나의 사전 가설이다. 클래스 가중치를 포함한 총 가중치를 정규화해 전체 손실 규모 변화와 출처 비중 변화를 분리한다. 공개 정답이 50개뿐이므로 이들의 영향 확대가 과적합을 키울 위험이 있고, 같은 공개 OOF 상승만으로 채택하지 않는다.

Stage 간 공용화는 원본 프레임 추적·중복 관리 도구에 한정한다. Stage2 원본 파일 번호와 Stage3 디코딩 순번의 의미를 섞지 않는다. Stage3의 전역 운동 분해를 Stage2의 흔들림 제거에 그대로 사용하면 충돌 증거를 없앨 수 있으므로 공유 전처리로 채택하지 않는다.
