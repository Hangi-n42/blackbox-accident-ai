# C 시작 프레임 참조 대조 — 새 C 결과 전 사전 설계

2026-09-13. 기존 A/B 원본 소스·결과는 보존한다. C는 A의 첫 세 질문 완료 후 마지막 진입 질문만 바꾸는 별도 모듈이다. 신규 방향 질문이나 crop/tracking 변경은 하지 않는다.

- A의 overview/entry/space 세 호출, motion 충돌, 방향, 회피공간은 변경하지 않는다.
- B와 같은 coarse 이웃창, 최대 12개 fine 후보, skip 규칙을 사용한다. coarse 응답이 유효한 제시 정수 번호가 아니면 추가 질문을 생략한다. 전체 3~4회.
- 마지막 질문은 이미지 1에 원본 전체영상 첫 프레임, 이미지 2에 기존 local fine sheet를 전달한다. 첫 프레임 번호 N0는 원본 파일명에서 가져오고 0을 하드코딩하지 않는다. 시간/FPS는 입력받거나 가정하지 않는다.
- 응답 JSON이 status=ALREADY_IN_LANE_AT_START이고 entry_frame이 정수 N0이면 N0를 수용한다. OBSERVED이고 제시된 fine 정수 번호일 때만 그 번호를 수용한다. BEFORE_WINDOW/AFTER_WINDOW/UNCERTAIN, 잘못된 상태·번호·JSON·예외는 A entry 유지. boolean/문자열/소수는 정수로 인정하지 않는다.
- 첫 프레임에서 다른 선행차를 상대라고 오인하면 잘못된 N0를 수용할 수 있다. 동일 충돌 차량인 경우만 시작 상태를 판단하라고 질문하지만, 이것이 동일 객체를 보장하지 않는다. 주석 대조로 별도 검토한다.
- **입력 예산 confound:** 기존 1장 입력의 1.2M 예산이 2장 각각 600k로 나뉜다. local fine sheet 화질도 줄어들 수 있다. 이 비교는 시작 이미지+상태규약의 결합 대조이며 순수한 시간 참조 효과로 해석하지 않는다. 입력/실제 bounded 크기를 기록한다.
- CPU mock으로 N0 offset/비연속 번호, 상태별 strict 수용/보존, skip, 원본 시작 vs local 시작 구분, 4회 상한, A 세 호출 보존, pointwise independence를 검증한 뒤 실제 저장 NF4 모델로 공개 5개 순차 실행한다.
- C 새 결과를 보고 질문이나 규칙을 반복 수정하지 않는다. 기존 A 결과의 첫 세 호출과 prompt/이미지/원응답을 직접 비교한다. 모델 전체 파일 SHA를 실행 전후 검증한다.
- 공개 충돌 라벨은 그대로 평가한다. root/독립 reviewer의 공개 시각 관찰은 공식 GT가 아니며 별도 개발진단으로 표시한다. 기존 A/B 관찰과 이번 C 설계의 관계를 숨기지 않는다. 공식 점수로 후보를 고르는 탐색은 하지 않는다.
- 마지막 질문이 N0를 더 자주 선택했다는 사실만으로 개선으로 채택하지 않는다. 실제 동일 상대 여부, 기존 crossing 사례에 잘못 N0를 부여하지 않았는지, 근거가 명확한 already-in-lane 사례를 복원했는지를 root가 검토한다. 최종 패키지 선택은 root 담당이다.
