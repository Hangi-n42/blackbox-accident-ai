# V4 Stage 1 입력 정합성 최소안

실행일: 2026-09-13. CPU만 사용했다. 기존 `solution/stage1.py`, 가중치, 설정, 임계값, 결합 비율은 수정하지 않았다. 후보는 `solution/stage1_v4.py`이며 아직 제출 경로에 연결하지 않았다.

## 공개 영상에서 확인한 사실

공개 원본 5개와 합성 재촬영 5개는 각각 50프레임이었다. 기존 sampler의 12개 RGB 프레임을 독립적인 2회 순차 디코딩 기준과 대조했고 **120/120 프레임이 바이트 단위로 일치**했다. 따라서 이 공개 범위에서 프레임 선택 오류가 성능 저하의 원인이라는 증거는 없다. 공식 평가 입력에서의 발생 여부는 확인 불가다.

## 별도 후보의 변경 범위

- 정상 파일은 기존 12회 seek를 그대로 사용한다. 전체 영상을 무조건 순차 디코딩하지 않는다.
- frame_count가 NaN/음수/0, seek 거절, 선택 프레임 읽기 실패, 보고된 seek 위치 불일치·역행이면 해당 영상만 순차 fallback한다.
- fallback은 실제 디코딩 총수와 metadata 총수를 비교한다. 다르면 실제 총수로 한 번 더 순차 읽어 같은 `linspace(...).round()` 규칙의 위치를 확보한다.
- 복구 뒤에도 선택 프레임이 지속적으로 손상되면 유효한 부분집합을 유지한다. 복구 자체가 실패해도 기존 seek에서 얻은 유효 프레임이 있으면 반환한다. 기존에는 일부 프레임으로 처리하던 영상을 새로 전체 실패시키지 않도록 했다. 아무 프레임도 읽을 수 없으면 기존과 같이 예외다.
- 분류 특징·전처리·TPO·평균 결합·라벨 판정은 바꾸지 않았다. 영상 간 통계나 상태를 사용하지 않는다.

## 검증 결과

| 검사 | 결과 |
|---|---|
| 공개 10개 후보/기존/독립 기준 RGB | 120/120 정확히 동일 |
| 공개 10개 특징 | 최대 절대 차이 0 |
| 공개 10개 정상 처리 경로 | 모두 seek 유지, fallback 없음 |
| 공개 10개 sampler 시간 합계 | 기존 2.253초, 후보 2.261초 — 단회 측정 |
| 기존 5분 반복 MP4 스트레스 입력 | 기존/후보 12프레임 RGB 동일, seek 유지 |
| 해당 5분 입력 시간 | 기존 0.199초, 후보 0.188초 — 속도 개선 주장에 사용하지 않음 |
| 실제 잘못된 HEVC metadata 사례 | 음수 frame_count를 감지하고 1,199프레임의 균등 위치 복구, 기존 순차 참조 RGB와 동일 |
| 해당 HEVC 복구 비용 | 2회 순차 읽기, 4.470초 |
| 기존 설정·가중치·추론 코드 SHA | 모두 사전 동결 기록과 일치 |

`predict_stage1` 함수 AST가 기존과 동일하고 동일한 특징 함수 객체를 사용한다. 공개 영상의 RGB와 특징이 같으며 가중치도 같으므로 정상 출력 동등성의 근거를 확보했다. 새 GPU forward는 수행하지 않았다.

Mock 계약에서 음수/NaN frame_count, 과대 frame_count, 실패 seek, 위치 불일치를 보고하는 거짓 성공 seek, seek 중 한 프레임 읽기 실패를 모두 올바른 균등 표본으로 복구했다. 정상·짧은 영상은 기존과 같았다. 지속 선택 프레임 손상은 기존처럼 11개 유효 프레임으로 처리하여 새 전체 실패를 만들지 않았다.

## 남는 한계와 채택 판단

정상처럼 보이는 과소 frame_count와 실제 픽셀 위치까지 속이면서 POS도 정상으로 보고하는 backend는 빠른 경로만으로 검출할 수 없다. 이 두 경우는 mock에서도 해결되지 않았으며 성공으로 표시하지 않았다. 동일 픽셀이 반복된다는 이유로 seek 실패라고 판단하지 않는다. 정지 화면도 유효 입력이기 때문이다.

`grab()`이 실제 EOF와 디코더의 중도 중단을 구분하지 못하는 한계도 남는다. 순차 읽기는 잘못된 metadata나 seek를 피하는 대체 방식이며 손상 영상을 복원하는 기능은 아니다. 정상 POS 보고를 지원하지 않는 backend가 많으면 fallback 빈도와 총 비용이 증가할 수 있다.

**이 후보는 검출 성능 개선 모델이 아니라 감지 가능한 입력 오류에 대한 방어적 변경이다.** 공개 실패가 없고 공식 영상의 문제 여부도 모르므로 기대 점수 개선은 제시할 수 없다. 전체 60분 제약에서 fallback 빈도·비용을 고려해 root가 제출 포함 여부를 판단해야 한다. 기존 source는 유지했다.

추가 DLC/comma 변환·새 학습·새 데이터 취득은 이번 최소안에서 수행하지 않았다. 기존 해상도 민감성 진단과 모델 결합 결과를 그대로 유지했다.
