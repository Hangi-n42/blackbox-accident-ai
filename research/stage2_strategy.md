# Stage 2 연구 메모 — 평가 정합성, 구현 가설, 공개 자원

확인일: 2026-09-11. 담당: Stage 2 연구 에이전트. 대회 통합 문서와 배포 노트북/라벨을 직접 읽었으며, 아래 웹 출처는 공식 개발자·데이터 제공자 자료다. 모델 실행·새 학습·다운로드는 이 조사에서 수행하지 않았다. 아래 방법은 검증 전 가설이고 예상 점수는 확인 불가다.

## 1. 목적함수와 잘못 최적화하기 쉬운 지점

로컬 `대회_통합_정보.md` 기준으로 Stage 2는 전체 점수 40%다. 충돌·차선진입 각각 전체의 14%, 방향·회피 공간 각각 6%다. 따라서 두 시점의 실제 사건 기준을 맞추는 일이 가장 우선이다. 단순한 위험도 상승이나 사고 직전 경고시점을 출력하면 충돌 평가와 어긋난다.

- 충돌: 블랙박스 차량과 상대 차량의 **실제 첫 접촉**. 배포 평가 대상에는 비충돌·제3자 차량끼리의 사고가 없다는 명세가 있다.
- 진입: 상대 차량의 **바퀴가 자차 차선에 처음 닿는 순간**. 차량 bbox가 중앙에 들어오는 순간이나 화면 최초 등장 시점이 아니다. 교차로는 차선 연장선을 사용하고 이미 진입한 채 시작하면 첫 프레임이다.
- 시간 허용오차: 평가가 영상별 원본 프레임↔시간 대응으로 ±0.3초를 계산한다. 입력 이미지 폴더에서 FPS를 별도 제공하지 않는 명세이므로 임의로 10/30FPS라고 가정해 후처리하면 안 된다. 모든 원본 번호를 유지하고 사건 주변에서는 연속 프레임을 직접 검사한다.
- 방향/회피는 Macro-F1이다. 한 종류만 출력하거나 현재 5건 분포로 사전확률을 고정하면 평가 범주가 바뀔 때 취약하다.
- 파일별 독립 예측, 고정 모델, 오프라인 로딩을 유지한다. 평가 전체 통계로 임계값을 조정하거나 평가 파일별 학습/의사라벨 갱신을 해서는 안 된다.

## 2. baseline에서 직접 확인한 상태

`Baseline/[Baseline_Train]_3Stage_학습.ipynb`의 `fit_stage2`는 ImageNet ResNet18을 고정하고 512차원 특징을 추출한 뒤 2층 양방향 GRU(방향당 hidden=192)를 학습한다. 충돌 head의 cross entropy만 계산한다. entry head 및 scene head에는 supervised loss가 없다.

`Baseline/data/stage2/labels.csv`는 영상 5개이고 충돌 frame은 32, 30, 31, 41, 30이다. 진입·회피·방향은 모두 -1이다. 노트북 주석도 공개 CCD 5건임을 명시한다. 이 5개를 학습하고 다시 점수를 계산하는 것은 일반화 검증이 아니다. 이 라벨들을 특정 ID/파일명의 답으로 제출 코드에 하드코딩해서는 안 된다.

## 3. 점수 지향 구현 가설

### 가설 A — 소형 VLM의 상황 이해 + 연속 프레임의 기하/움직임 결합

추천 첫 실험은 **Qwen3-VL-2B-Instruct + 경량 움직임 분석**이다. 직접 학습 가능한 사고 라벨이 매우 적으므로 범용 시각 모델의 장면 이해를 우선 활용하되, VLM이 프레임 번호를 자유롭게 지어내지 못하도록 후보 선택 문제로 제한한다.

1. 파일명에서 원본 프레임 번호를 추출해 숫자순 정렬한다. ID는 결과 연결에만 사용한다.
2. 전체 영상을 적은 대표 프레임으로 먼저 보여준다. 상대 차량, 진입 방향, 접촉 후보 구간, 공간의 장애물을 파악한다. 대표 프레임 수/해상도는 개발 데이터에서 속도·정확도 곡선으로 결정한다.
3. 저해상도 연속 영상의 optical flow/전역 영상변환 변화와 상대 차량의 크기·가림 변화로 충돌 후보를 추가한다. 흔들림 최대값 하나를 충돌로 확정하지 않는다.
4. 후보 구간을 연속 원본 프레임으로 확대한다. 각 프레임에 원본 번호를 붙인 contact sheet 또는 multi-image 입력을 사용하고, 후보 번호만 선택하게 한다. 필요한 경우 한 번 더 좁힌다.
5. 진입은 충돌 상대 차량을 과거로 추적해 차선 경계와 바퀴 위치를 검사한다. 이미 진입한 상태인지 별도 이진 질문을 둔다. bbox 밑면은 바퀴의 근사일 뿐이므로 불확실성 시 후보 확대를 한다.
6. 회피 공간은 충돌 프레임과 인접 프레임의 차로·주행가능영역·차량·연석·방호벽 등을 같이 본다. 단순 빈 픽셀 면적을 회피 가능 공간으로 간주하지 않는다.
7. 출력은 허용된 frame 집합으로 제한한다. VLM 파싱 실패 시에는 같은 영상에서 계산한 물리 후보로 복구하고 로그에 원인을 남긴다.

**가설의 한계:** 2B VLM이 바퀴의 차선 접촉이나 가려진 물리 접촉을 ±0.3초로 맞춘다는 근거는 없다. 개별 장면에 대해 존재하지 않는 도로 공간을 서술할 수 있다. 때문에 VLM 단독 자유응답과 coarse-only 방식은 제출 전 반드시 비교해야 한다. 추가 호출은 파일 단위 고정 상한을 둔다.

### 가설 B — 탐지·차선 보조 + 사건 시점 모델

**YOLOP**는 객체 탐지·차선·주행가능영역을 하나의 모델에서 제공하므로 파일 내 차량 궤적과 차선교차 신호의 출발점이다. 충돌/진입 각 posterior를 출력하는 작은 TCN 또는 GRU에 전역 이미지 특징, 차량 track 특징, 차선거리, optical flow 변화량을 넣는다. 휠 자체를 검출하는 학습셋이 없다면 bbox만으로 정확한 진입 정답을 생성하지 말고 weak label로만 기록한다.

공개 데이터에서 실제 접촉시점이 검수된 경우, 단일 프레임 CE와 좁은 soft target을 비교한다. 최종 Accuracy@0.3초는 회귀 평균오차와 다르므로, **개발 데이터의 시간정보가 있는 경우** 예측 posterior에서 폭 0.6초 창의 확률질량이 최대인 구간 중심을 고르는 방식도 검증한다. 평가 이미지의 FPS를 모르면서 이 창을 고정 6/18프레임으로 대체하지 않는다.

**가설의 한계:** 충돌 후 카메라가 흔들리는 시점은 첫 접촉보다 늦을 수 있고 급제동/노면 충격도 흔들린다. 일반 차선 검출은 교차로 연장선·눈/비·차선 가림에서 실패한다. 교차로와 기하 불확실 장면은 VLM의 상황 판단과 함께 비교한다.

## 4. 공개 자원 조사와 라이선스 범위

### Qwen3-VL-2B-Instruct — 우선 시험 가능한 VLM

- 공식 모델 카드의 라이선스는 Apache-2.0이며 이미지·동영상 이해용 모델이다. 공식 코드 예제는 `Qwen3VLForConditionalGeneration`과 `AutoProcessor`를 사용한다. [공식 모델 카드](https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct)
- 공식 파일 목록은 전체 4.27GB, `model.safetensors` 4.26GB다. 별도 로그인 승인 안내 없이 파일 목록에 접근했다. 실제 네트워크 다운로드 성공은 아직 검증하지 않았다. [공식 파일 목록](https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct/tree/main)
- 공식 프로젝트에 Apache-2.0 전문이 있다. 채택 시 라이선스/NOTICE, 고정 revision, 모델·tokenizer·processor 파일을 보존한다. [공식 LICENSE](https://github.com/QwenLM/Qwen3-VL/blob/main/LICENSE)
- 배포 서버의 transformers 4.57.6과 실제 로딩/멀티이미지 입력 호환성을 환경에서 확인해야 한다. 가중치 용량은 시간/VRAM 사용량이 아니다. BF16/FP16 추론과 짧은 JSON 출력부터 시험한다.
- 주의: **Qwen2.5-VL-3B-Instruct는 동일 Apache 모델로 간주하면 안 된다.** 해당 공식 LICENSE는 Qwen Research License다. [해당 모델 LICENSE](https://huggingface.co/Qwen/Qwen2.5-VL-3B-Instruct/blob/b318d0972a0bfe62f64d49e1fe95e4fd39292261/LICENSE)

### YOLOP — 경량 기하 보조 모델

- 공식 저장소는 MIT이며 검출·차선·주행가능영역의 공동 예측 모델과 학습 가중치를 제공한다. 공식 BDD100K 수치는 대회 성능 근거로 사용할 수 없다. [공식 저장소](https://github.com/hustvl/YOLOP), [MIT LICENSE](https://raw.githubusercontent.com/hustvl/YOLOP/main/LICENSE)
- 공식 `hubconf.py`는 로컬 `weights/End-to-end.pth`의 `state_dict`를 읽는다. 제출에서 torch.hub 원격 다운로드 대신 필요한 소스와 weight를 함께 고정하여 로드한다. [공식 로더](https://raw.githubusercontent.com/hustvl/YOLOP/main/hubconf.py)
- 구형 PyTorch에서 개발된 코드이므로 대회 torch 2.8.0 호환 검증이 필요하다. torchvision 기본 모델을 포함해 무작위 weight로 조용히 대체하는 fallback은 금지한다.

### CCD — 사고시점 학습 후보, 영상 권리 범위 주의

- 공식 제공자는 사고 1,500개, 정상 3,000개를 설명한다. 사고는 YouTube에서 수집한 50프레임/10FPS clip, 정상은 BDD100K에서 추출했다고 명시한다. frame 사고 주석과 ego-involvement가 있어 **자차 관여 사고만 골라** 학습할 수 있다. 바퀴 진입·회피 공간 라벨은 제공 목록에 없다. [공식 데이터 설명](https://github.com/Cogito2012/CarCrashDataset)
- 제공자가 링크한 [공식 다운로드 폴더](https://drive.google.com/drive/folders/1NUwC-bkka0-iPqhEhIgsXWtj0DA2MR-F?usp=sharing)에 접근했지만 웹 도구는 내부 목록을 읽지 못했다. 용량과 실제 다운로드는 확인 불가다.
- repo LICENSE는 MIT이나 대상 표현은 software/documentation이다. **이를 근거로 모든 제3자 원본 영상의 권리까지 MIT로 해결됐다고 단정할 수 없다.** 대회 통합 문서의 CCD 활용 가능 답변도 라이선스 준수가 전제다. [repo LICENSE](https://raw.githubusercontent.com/Cogito2012/CarCrashDataset/master/LICENSE)
- 채택 전 취득 페이지의 데이터 이용조건을 보존하고, 사용범위·원본 재배포 제한을 기록한다. 공개 배포 baseline 5개에서 개발을 진행하는 것은 이 추가 데이터 권리 확인과 독립적으로 가능하다.

### Ultralytics — 기본 환경에 있어도 자동 채택하지 않음

## 5. 추가 라벨과 검증 설계

1. 공개 5개에서 collision 공식 라벨은 보존하고 entry/side/evasion을 사건 기준에 따라 영상으로 검수한다. 자동 VLM 제안과 사람/에이전트 시각 판독을 공식 라벨과 구분해 저장한다. 확정할 수 없는 사건은 uncertain으로 남겨 supervised target에서 제외한다.
2. 추가 합법 공개 영상은 `source_url, license_url, acquired_at, source_video_id, clip_start, fps_or_timestamps, ego_involved, collision, entry, side, evasion, annotator, confidence, evidence_frames` 기록을 유지한다.
3. 근접한 사고 프레임·잘린 원본·좌우반전·재인코딩 영상은 같은 원천 그룹으로 묶어 분할한다. CCD 공식 split만으로 원본 YouTube 영상 중복이 없는지 확인 없이 단정하지 않는다.
4. 충돌 5건만 있는 상태에서는 leave-one-source-out을 사용하되 결과 분산이 매우 크다는 한계를 남긴다. 누락 라벨의 검증 점수를 조작해 종합점수로 보고하지 않는다.
5. 진입 첫 프레임, 좌/우 진입, 교차로, 차선 가림, 이미 접촉한 영상 시작, 다중 충돌/접촉, 야간/악천후를 별도 오류유형으로 기록한다. 다중 접촉에서 어느 접촉이 정답인지 명세가 불충분하면 공개 개발 라벨의 일관성을 확인한다.
6. 좌우반전 증강은 side를 반대로 변환해야 한다. 접촉 이후 crop은 entry가 crop 이전이면 첫 프레임으로 갱신한다. 회피 공간은 화면을 자르면 판단 근거가 바뀌므로 강한 crop을 피한다.

## 6. 경량 추론·제출 검증

- Stage2 함수 호출 시 모델 한 번 로딩, 파일마다 독립 상태 초기화, 평가 중 `eval`/`inference_mode`, 로컬 자산만 로딩.
- 이미지 모두를 고해상도 tensor로 저장하지 않고 경로 목록+작은 특징/썸네일을 유지한다. 사건 후보 주변에서만 원본 해상도를 읽는다.
- coarse→fine VLM 호출 수·입력 픽셀·출력 토큰에 파일별 고정 상한을 둔다. 다른 평가 파일 길이나 예측 통계를 사용해 상한을 바꾸지 않는다.
- 필요한 파일별 2-pass 처리는 허용되지만 첫 파일 결과로 다음 파일을 보정하지 않는다. batch norm 통계 갱신과 테스트시간 적응은 하지 않는다.
- 원본 프레임 번호가 비연속인 fixture, 1장 입력, 긴 폴더, 손상 이미지, JSON 형식 실패 등을 검사한다. 유효 이미지가 없는 경우는 조용히 가짜 프레임을 반환하지 말고 계약에 맞는 명확한 오류를 낸다.
- 예제 실측 시간만으로 60분 전체 통과를 보장할 수 없다. 프레임 수별 시간을 기록하고 L40S/7CPU 환경 대비 연산량을 제한한다. 실제 평가 수량은 비공개다.

## 7. 바로 실행할 실험 순서

1. Qwen3-VL-2B의 로컬 모델과 processor 로딩 및 5개 공개 사고의 coarse→fine 예측을 시험한다. 별도 평가 비공개 데이터는 보지 않는다.
2. 공개 충돌 5건을 시간 기준으로 검증하고, 진입/방향/회피를 근거 프레임과 함께 추가 판독해 비교한다. 기존 5건은 규모가 작으므로 모델 선정 근거를 과장하지 않는다.
3. VLM-only, 움직임-only, 결합 모델의 오류 유형·호출 시간·범주 성능을 비교한다. 개선 근거 없는 복잡한 모듈은 추가하지 않는다.
4. 추가 사고 데이터의 사용조건이 확인되면 자차 관여 subset을 취득하고, 사건 기준 라벨을 재검수한 뒤 경량 temporal 모델로 확장한다.
5. 제출마다 세 Stage 전체 가중 종합점수를 기록한다. Stage1 Public 최고점 대표표시만으로 Stage2 개선을 판단하지 않는다.

## 8. 이번 구현과 실제 확인 결과

`solution/stage2.py`에 구현했다. 전체 저해상도 광류 스캔으로 motion 후보를 제안하고, VLM overview → collision 정밀 → entry 정밀 → 두 시점과 상황 최종 확인의 **영상당 4회 호출**을 사용한다. 원본번호가 표시된 이미지와 후보번호 목록을 전달하며, 불법 후보 응답은 후보 집합 안으로 복원하고 경고를 기록한다. 모델 파일은 `model_dir/vlm`에서 로드한다. `model_dir/config.json`의 `motion_only=true`는 비교용이며 진입=첫 프레임·회피=0의 미검증 기본값을 사용하므로 완성 모델로 해석하지 않는다.

`research/stage2_probe.py`로 배포 영상 5개를 모두 실제 디코딩해 `research/stage2_public/images`에 저장했다. 각 50프레임, OpenCV가 읽은 FPS는 모두 10이다. 학습하지 않은 motion 충돌 예측은 [35, 47, 33, 42, 33]으로 공식 [32, 30, 31, 41, 30] 대비 절대오차 [3, 17, 2, 1, 3]프레임이다. ±0.3초 기준으로 4/5이며 이것은 **공개 5개에 대한 ablation 결과일 뿐 대회 점수 추정이 아니다.** 저해상도 스캔과 overview 생성은 영상당 약 0.85~0.98초였다. 실제 VLM 및 전체 제출 시간은 아직 검증하지 않았다. 상세 측정은 `research/stage2_public/motion_report.json`에 있다.

공개 contact sheet를 시각 검토한 결과 S2_002는 전방 트럭과 다른 차량 사고로 보이는 장면이며, 자차 실제 접촉 여부는 이 자료에서 확인 불가다. S2_004는 첫 프레임부터 앞 차량이 자차 차로에 있다. LEFT/RIGHT 진입 정보는 관찰되지 않는다. 따라서 **공개 예제 5개의 모든 상황을 실제 평가의 차선진입 사고 정의와 동일하다고 가정해 추가 정답을 강제로 만들면 안 된다.** 이 검토에서는 불확실한 entry/side/evasion 정답 파일을 생성하지 않았다.

`research/stage2_contract_check.py`를 실행해 비연속 원본번호 보존, 번호 전체 offset 변경에 대한 equivariance, 영상당 4회 호출 상한, 한 장 입력, 빈 입력의 명시적 오류, motion 후보가 overview에 실제 포함되는지, markdown JSON 파싱을 확인했다. 이 검사는 **가짜 VLM을 사용한 인터페이스 검사**이며 정확도 검증과 구분한다.

## 9. 실제 VLM 평가 스크립트 준비

`scripts/evaluate_stage2_vlm.py`를 작성했다. GPU 동시 사용을 피하기 위해 실행 담당자가 아래 순서로 실행한다. 스크립트는 비공개 평가셋을 사용하지 않고 기본값으로 공개 5개만 읽는다.

```powershell
.venv/Scripts/python.exe scripts/evaluate_stage2_vlm.py --dry-run
.venv/Scripts/python.exe scripts/evaluate_stage2_vlm.py --limit 1 --save-images
.venv/Scripts/python.exe scripts/evaluate_stage2_vlm.py --ids S2_002 S2_003 S2_004 S2_005 --save-images
```

출력은 기본적으로 `artifacts/eval_stage2/<실행시각>/`에 쓴다. 각 호출별 원문 응답·파싱 결과·프롬프트·후보 집합·이미지 크기·호출 시간·CUDA peak memory가 즉시 저장되어 중간 실패를 추적할 수 있다. `--save-images`는 실제 전달 이미지도 저장한다. `--pixel-budget`으로 공통 VLM 입력 상한을 비교할 수 있다. `--output-dir` 기존 결과를 덮어쓰지 않는다.

평가 라벨은 추론 함수에 전달하지 않고 **응답이 나온 뒤에만** 채점/후보 진단에 사용한다. 공개5개는 별도 디코딩 검사에서 10 FPS를 확인했으므로 이 비교에서는 ±3프레임을 사용한다. 이 규칙을 비공개 평가에 적용하지 않는다. 진입·방향·회피에는 공식 라벨이 없으므로 이 항목의 정확도나 가짜 종합점수를 계산하지 않는다.

후보 갇힘 진단은 overview에 ±3프레임 후보가 있었는데 refinement에서 사라졌는지, 마지막 후보들로는 정답 허용구간 도달 자체가 불가능한지, 마지막 호출에서 넓어진 후보가 실패를 회복했는지를 각각 기록한다. 최종 후보에 정답이 없을 때와 후보는 맞지만 VLM이 오선택했을 때를 구분한다.

연산량은 영상당 4회, 출력 토큰 상한 합계 438, 기본 총 시각 입력 상한은 호출별 1.2M 픽셀이므로 4.8M 픽셀/영상이다. 이는 코드 설정의 상한이며 **초당 처리량 또는 실제 메모리/시간의 측정값이 아니다.** 실제 실행 후 영상당 4회 시간과 장치명을 보고서에서 확인한다. L40S 전체60분 통과 여부는 공개 예제 실측으로 확정할 수 없다.

모델 없는 `--dry-run`에서 전체5개 선택 및 frame개수를 확인했고, `--limit`과 공백/쉼표 ID 필터도 확인했다. 후보 목록 파싱·coarse 갇힘·최종 후보 회복 진단을 별도 CPU 검사에서 확인했다. 실제 VLM 모델 실행은 이 준비 작업에서 하지 않았다.
