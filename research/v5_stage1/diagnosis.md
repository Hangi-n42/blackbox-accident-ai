# V5 Stage 1 병목 재진단과 단일 구조 실험 제안

작성: 2026-09-13. 기존 코드·모델·설정·원본 자료를 읽고 저장된 확률만 Python 표준 라이브러리로 집계했다. GPU 작업, 학습, 모델 교체, 추가 자료 취득, 기존 파일 변경은 하지 않았다. 아래 실험은 **설계안이며 실행 결과가 아니다**.

## 1. 확인된 원인과 확인 범위

공식 V4 Stage 1 점수 0.5078837545가 이전 제출과 같다는 사실은 root가 확인한 공식 결과에 근거한다. 집계 Macro-F1만으로 공식 영상의 원본 오탐 수, 재촬영 미검출 수, 개별 판정의 동일성은 복원할 수 없다. 아래는 로컬 진단에서 확인된 실패와 구조상의 제한이다. 어느 항목이 공식 점수 손실의 몇 %를 설명하는지는 확인 불가다.

### 1.1 독립 원천 수와 목표 현상의 불일치

`research/stage1/training_manifest.json`의 공개 자료는 원본 5개와 동일 원천의 simulated 재촬영 5개다. 독립 원천은 5그룹이다. 현재 forensic 아티팩트는 clean/JPEG75/JPEG95/half_resolution 양 클래스 공통 변형으로 학습했지만, 40개 학습 행이 40개 독립 촬영 환경을 뜻하지 않는다. source-group 검증은 원천 누출을 줄였으나 동일 5그룹으로 특징군 4개와 결합 비율 5개를 반복 비교했다. 모델 선택에 사용한 결과를 최종 독립 검증으로 볼 수 없다.

TPO는 실제 물체의 원본·인쇄·화면 공격을 학습한 모델이다. 기록된 원천은 실내 채소 장면과 Surface/Galaxy 재촬영이며, attack은 화면 재촬영 전용 라벨이 아니다. DLC의 ORIGINAL은 물리적 문서를 촬영한 영상이라 인쇄 공격을 포함하는 TPO 학습 라벨과도 완전히 일치하지 않는다. 이 라벨·장면 차이가 존재하는 것은 확인됐지만 개별 도로 오탐의 시각적 원인을 증명하지는 않는다. 공식 출처를 검증한 기록은 `research/stage1/real_recapture_validation_audit.md`에 있다.

**현재 보유 진단 중 실제 도로 원본을 디스플레이에 재생하고 다시 카메라로 촬영한 양성 검증은 없다. 그 영역의 검출률·Macro-F1은 확인 불가다.**

### 1.2 고정 픽셀 특징은 해상도 변화에 안정적이지 않았다

`solution/stage1.py`는 프레임당 native 최대 192×192 패치 5개에서 픽셀 단위 FFT 주파수와 색 잔차를 계산한다. 영상 내 패치 median/q90을 사용하며 현재 모델은 총 50개 중 주파수 계열 22개만 선택한다. 계산한 화면 가장자리 특징 12개는 현재 판정에 사용하지 않는다. 시간 순서를 바꿔도 동일 집계이며 프레임 간 주사·반사·카메라 운동을 직접 모델링하지 않는다.

| 동일 공개 5원천의 검증 조건 | 현재 forensic Macro-F1 | 고정 0.5 결합 Macro-F1 |
|---|---:|---:|
| clean | 1.00000 | 1.00000 |
| JPEG75 | 1.00000 | 1.00000 |
| half_resolution | 0.45055 | 0.69697 |

현재 forensic의 half_resolution 혼동행렬은 원본 [정상 4, 오탐 1], 재촬영 [미검출 4, 검출 1]이다. 따라서 공개 clean 1.0이 크기 변화에서 유지된다는 가설은 반증됐다. 축소는 주파수의 픽셀 좌표와 실제 증거 자체를 동시에 바꾸므로, 이 결과만으로 모든 resize를 안전한 불변 변환으로 선언할 수는 없다. 근거: `robustness_metrics.json`, `fixed_blend_diagnostic.json`.

TPO는 전체 프레임을 224×224로 직접 resize하고 영상당 12개 attack 출력의 평균을 사용한다(`solution/stage1_tpo_merged.py`). 저수준 원해상도 패치와 전역 축소 표현을 함께 쓰지만, 현재 입력 크기/증거 손실에 맞춘 학습된 결합은 없다. 전역 resize가 실제 모아레를 얼마나 없애는지는 별도 대조가 없어 확인 불가다.

### 1.3 평균 결합은 두 모델 사이의 상충을 실제로 만들었다

현재 규칙은 `p=(pF+pT)/2`, `RERECORDED iff p>=0.5`다. 즉 `pF>=1-pT`일 때만 재촬영이다. 낮은 forensic 출력은 TPO 양성 판정도 음성으로 뒤집을 수 있다. 예를 들어 **실제 관측된** DLC `aze_passport/03.re0002`는 pT=0.519875, pF=0.334166, 결합=0.427021이었다. `esp_id/01.re0002`도 0.584206, 0.356896, 0.470551이었다. 둘 다 TPO가 검출했지만 결합은 미검출했다.

| DLC: 24개 영상의 배포 JPEG 부분집합, 6문서 | Macro-F1 | 원본 오탐 /12 | 재촬영 미검출 /12 |
|---|---:|---:|---:|
| TPO | 0.78836 | 1 | 4 |
| forensic | 0.49580 | 0 | 10 |
| 0.5 결합 | 0.73333 | 0 | 6 |

DLC 재촬영의 forensic 출력 중앙값은 0.378798, TPO는 0.552041, 결합은 0.495209였다. 원본 forensic 중앙값은 0.334410이었다. 이 분포에서는 forensic이 대부분 낮게 출력하며 결합의 재촬영 판정을 억제한다. 이 숫자를 교정된 실제 도로 재촬영 확률로 해석하면 안 된다.

반대로 comma 도로 원본에서는 결합이 실제로 유리했다.

| comma: 기존 공개 중복 1개 제외, 원본 23구간 | 오탐 수 | 관측 오탐률 |
|---|---:|---:|
| TPO | 4/23 | 17.39% |
| forensic | 0/23 | 0% |
| 0.5 결합 | 0/23 | 0% |

TPO 오탐 4개는 pT=0.580166~0.814164, pF=0.059823~0.169219로 결합이 전부 0.5 미만이었다. 전체 comma forensic 중앙값은 0.230502였다. 따라서 **낮은 forensic 출력을 전부 무시하는 것이 안전하다는 주장도 성립하지 않는다**. DLC의 TPO 우위만으로 TPO 단독 전환을 채택할 수 없다.

DLC 원본은 JPEG 48장 1080×1920, 48장 2160×3840이고 재촬영은 96장 모두 2160×3840이다. 문서 콘텐츠, 해상도, 화면·카메라 조건의 교란이 남는다. comma는 두 차량의 제한된 도로 구간이며 23개 독립 카메라가 아니다. HEVC는 잘못된 seek metadata를 피해 순차 디코딩한 12개 균등 프레임으로 검사했다. DLC는 영상당 JPEG 8장이므로 제출 영상 평가와도 다르다. 두 자료의 클래스를 합친 새 Macro-F1은 계산하지 않는다.

근거: `research/stage1/dlc_subset/frozen_predictions.json`, `frozen_metrics.json`, `research/stage1/comma_original_diagnostic/predictions.json`, `report.md`.

### 1.4 공식 V4 점수 불변은 새 분류 모델의 실패가 아니다

V3/V4 manifest에서 Stage 1 설정, forensic, merged TPO, 기존 stage1.py, TPO runtime SHA가 동일하다. V4 `inference.py`는 `stage1_v4`의 입력 방어 후보를 호출하지만 분류 특징·가중치·결합은 그대로다. 따라서 V4에서 실제 재촬영 식별 구조를 새로 학습·교체한 것은 아니다. decoder 보완의 점수 개선이 관측되지 않았다는 사실을 넘어 공식 입력의 오류 발생 여부나 개별 결과 불변을 단정하지 않는다.

## 3. 지금 가능한 단일 구조 수정 실험

### 3.1 제안: 두 점수의 고정 평균을 작은 학습 결합기로 바꾸는 진단

**설계 의견:** 현재 GPU·새 모델·큰 다운로드 없이 시험할 수 있는 가장 직접적인 구조 수정은 저장된 pT/pF를 입력으로 하는 2변수 규제 로지스틱 결합이다. 임의로 비율 하나를 고르는 대신 각 출력 척도의 차이와 절편을 학습한다. 바꾸는 것은 마지막 결합뿐이다. TPO/forensic/프레임/threshold 0.5는 동결한다. 학습 입력에는 파일명, 문서 ID, 카메라 ID, 해상도, 도메인 구분을 넣지 않는다.

단일 후보를 사전에 고정한다: 두 확률을 [1e-6,1-1e-6]로 제한한 logit 두 개, fold 학습 자료만의 표준화, L2 logistic C=0.1, 절편 포함, 고정 seed, threshold 0.5. 이것은 사전에 정한 실험 규칙이며 C=0.1이 최적이라는 근거는 없다. 비율/threshold/C grid search, 특성 추가, 실패 후 다른 후보 탐색은 이번 단일 실험에 포함하지 않는다. 출력은 목표 도메인의 보정된 확률로 주장하지 않는다.

저장 확률만 쓰므로 CPU 2스레드 이하에서 가능하다. 하지만 DLC에 학습한 결합기는 문서 라벨에 적응하는 모델이므로, 도로 문제의 근본 해소를 곧바로 증명하지 못한다.

### 3.2 사전에 동결할 원천 분리

1. **DLC 주 진단:** 문서 ID별 Leave-One-Document-Out 6fold. 한 fold는 해당 문서의 or/re×iphone/android 4행 전부를 검증에 두고 나머지 20행으로 학습한다. ID는 `srb_passport/04`, `aze_passport/03`, `esp_id/01`, `aze_passport/04`, `rus_internalpassport/01`, `lva_passport/02`로 기존 선택을 유지한다. 프레임을 행으로 늘리지 않는다. 24개의 held-out 예측을 모아 기존 고정 결합과 동일 단위로 비교한다.
2. **기기 스트레스:** 위 문서 제외를 유지하면서 학습은 반대 카메라 10행만, 검증은 제외 문서의 지정 카메라 or/re 2행만 사용한다. 6문서×2카메라 12fold. 문서와 카메라를 함께 배제하지만 카메라 종류 2개뿐이고 학습 표본 10행에 불과하다는 한계를 명시한다. 같은 문서의 다른 카메라를 학습에 두는 편한 split을 쓰지 않는다. 화면 기기는 희소해서 독립 display-holdout 성능은 여기서 확보되지 않는다.
3. **comma 음성 대조:** 23개를 결합기 학습과 threshold 선택에 쓰지 않는다. 각 DLC 주 fold 결합기의 원본 오탐 수를 별도로 기록한다. 23개를 독립 무작위 분할하지 않는다. 이미 결과를 본 자료이므로 미사용 최종 평가로 이름 붙이지 않는다.
4. **공개 회귀 검사:** 기존 5원천의 clean/JPEG/half 결과는 합성 회귀 검사로만 사용한다. calibration 학습에 섞지 않으며 기존 저장 점수의 OOF/최종 학습 구분을 유지한다. 공개 결과를 보고 결합기 규칙을 다시 고르지 않는다.

### 3.3 Stop / Go 기준과 제출 채택의 한계

**추가 실제 도로 검증으로 진행할 Go 조건**을 사전에 정한다: DLC 주 진단의 재촬영 미검출이 기존 6개보다 적고 원본 오탐은 기존 0개보다 늘지 않을 것; 각 6fold 결합기 모두 comma에서 기존 0/23 오탐을 유지할 것; 공개 동일 조건 회귀 결과가 기존 결합보다 악화되지 않을 것. 기기 스트레스에서 개선이 한 카메라에만 몰리거나 원천별 판정이 불안정하면 보류한다. 이 엄격한 문턱은 탐색 확대를 막기 위한 설계 선택이지 통계적으로 성능 향상을 보장하는 기준이 아니다.

하나라도 실패하면 이 단일 결합 수정은 **Stop**한다. 실패 표본에 맞춰 비율·threshold를 바꿔 성공으로 재정의하지 않는다. 모두 통과하더라도 **자동 제출 채택은 불가**다. DLC 전이와 도로 음성 보존만 확인되며 목표 양성 검출은 여전히 확인되지 않는다.

제출 모델로 채택하려면 별도 허가된 실제 도로 원본/화면 재촬영 자료에서 원천 콘텐츠와 그 파생본을 같은 그룹에 두고, 재촬영 카메라·디스플레이도 분리한 검증이 필요하다. 모든 기존 public/DLC/comma는 이미 살펴본 개발·회귀 자료로 남겨야 한다. 현재 제한 안에서는 그런 목표 양성 holdout을 만들 수 없으므로 **검증 가능한 근본 성능 개선 모델의 채택 근거는 확보 불가**다. 예상 개선 수치는 제시하지 않는다. 단순 V3 복원도 이 병목을 해결하지 않는다.

코드 접점은 `solution/stage1.py:feature_probability`, `predict_stage1`의 평균 결합 줄이며, 실험을 승인받으면 기존 파일을 수정하지 않고 별도 후보와 별도 CPU 진단 기록으로 구현할 수 있다. 현재 문서에서는 실행하지 않았다.
