# Native video 고정 진단 결과 독립 검토

2026-09-15. 실제 `native_video_run/{report,evaluation,assessment}.json`과 원응답·고정 protocol·실행 코드를 읽었다. 신규 모델 실행, 후보 변경, 추가 탐색은 하지 않았다.

**판정: 이번 contact 교체안은 사전 gate 실패이며 미채택·탐색 중단이 타당하다. 다만 native temporal 처리 일반이 무효라고 결론 내릴 수는 없다.** 후보 커버리지와 선택 실패가 함께 있었고, 최종 V6 motion 출력과 원래 VLM fine 출력은 서로 다른 기준선이다.

## 두 기준선을 분리한 결과

- 최종 V6 contact: 4/9 → native 선택으로 교체 시 1/9. MAE 3.7323166303558457 → 11.692378999530096초. 00007을 새로 맞혔지만 00000·00003·00006·00008을 잃었다.
- **같은 fine 후보를 보던 원래 내부 VLM 선택:** 0/9 → 1/9. 따라서 “선택기가 모든 면에서 전혀 개선되지 않았다”는 표현도 정확하지 않다. 00007 한 건의 개선이 있으나, 최종 정책보다 낫다는 근거가 되지 않는다.
- ±0.3초 안의 후보가 존재하는 영상은 00000·00004·00005·00007·00013, 총 5개다. 이 중 새 선택이 맞은 것은 00007 하나이며 **나머지 4개는 후보 중 선택 실패**다.
- 00003·00006·00008은 V6 final motion은 맞았지만 원래 fine 후보에는 정답 범위가 없다. 이번에처럼 유효한 offered frame을 반환하여 motion을 덮어쓰면 이 세 성공은 반드시 사라진다. 00010도 정답 범위 후보가 없으나 V6부터 오답이었다. 이 구조적 손실을 temporal 처리의 오인만으로 설명하면 안 된다. null/불량 응답 fallback은 성공 보존 경로였지만 실제 9개에는 발생하지 않았다.

9개 원응답 모두 완결된 `collision_frame` JSON이고 제공 번호에 속했다. 출력은 13~14 토큰으로 48 토큰 상한에 잘리지 않았다. fallback은 0개다. 00000·00006·00008·00013은 기존 내부 선택과 동일했고 나머지 5개는 달라졌다. 6/9에서 마지막 두 후보 중 하나를 선택한 것은 관측 사실이나, 이것만으로 recency bias나 temporal patch의 특정 결함을 인과적으로 확정할 수 없다.

## 실행·자원 감사

고정 protocol은 SHA `c53ce56b7c571d9e45bcf742e2bbc5b66b197971f015e66667fd151077a13aa9`, report는 `8ca554c2a63438700ee85b9b680e4266cf835ad817a4498fadf248ddf0f9b432`다. report가 참조하는 freeze SHA를 직접 대조했다. freeze에 등록된 1MB 미만 파일 160개와 실제 선택 원본 PNG 132개의 SHA를 독립 재확인했고 불일치는 없었다. 대형 모델·원본 영상 전체 SHA는 이번 읽기 감사에서 다시 계산하지 않았으며, 실행기의 전체 binding 사후검사 PASS 기록과 구분한다.

실행 기록은 4B saved NF4/FP16, 모델 로드 1회, 질문 9회, 네트워크 시도 0, 완료 상태다. 원본 번호/후보 순서, synthetic metadata 순번, 48 출력 토큰, 패딩 포함 픽셀 상한, 다른 세 출력의 복사 동등성을 9개 모두 다시 확인했다. 15개 타일은 마지막 한 개를 복제하여 16개로 인코딩했고 00010의 12개는 복제하지 않았다. 실제 video grid는 각각 `[8,12,20]` / `[6,16,24]`, visual token은 480 / 576이다. 패딩 포함 픽셀은 983,040 / 1,179,648로 1.2MP 이내다. 전체 input token은 687~749였다.

최대 reserved VRAM은 3.357421875GiB, 기록된 전체 실행은 42.1633679초다. 질문별 전처리+생성 합은 15.4213607초이며, 저장된 원래 call2 시간 합은 20.5081692초였다. 자원상 실행 장애는 나타나지 않았다. 다만 과거와 현재의 시간은 같은 세션의 paired 측정이 아니고, 전체 4-call/전체 제출 재실행도 아니므로 서버 60분이나 end-to-end 속도 개선을 증명하지 않는다. 실제 protocol의 시간 gate는 600초이며 PASS다.

기록상의 작은 주의점: `report.runtime.ask_implementation`에는 CandidateVLM에서 상속된 이미지 `ask` 설명이 남아 있다. 실제 runner는 `helper.ask_native_video`를 호출했고 video tensor/grid/token 기록이 있으므로 이 문자열을 실제 이미지 경로 사용 증거로 읽으면 안 된다. 예측 실행 오류는 발견하지 않았다.

## 결론의 범위와 동결 이후 처리

이번 결과는 합성 2fps, 고정된 희소 fine 후보, 두 프레임 patch, 별도 timeline 선언, 달라진 픽셀·토큰 배분을 함께 사용한 **이 특정 구조**가 V6 final contact를 대체할 근거를 주지 못했다는 뜻이다. 실제 촬영 시간 기반의 모든 video 모델이나 모든 temporal 입력을 반증한 결과는 아니다. 반대로 내부 선택 1건 개선만 골라 실패한 전체 gate를 통과로 바꾸는 것도 부당하다.

정당한 다음 처리는 frozen stop을 지켜 결과·실패 원인을 보존하고 이 후보를 패키징/제출하지 않는 것이다. 기존 V6를 유지하는 것은 안전한 기준선 보존이며 V7 성능 목표 달성은 아니다. 이 9개의 결과를 보고 FPS·후보 창·허용 응답·문구를 다시 조정하거나 성공 00007만 별도 규칙으로 편입하지 않는다. 새 실험을 제안하거나 실행하지 않았다. 이 자료는 이미 노출된 개발 cohort이며, 공식 점수나 전체 S2로 제시하지 않는다.
