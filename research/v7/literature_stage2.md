# V7 Stage2 문헌 검토와 제한된 구조 설계

작성: 2026-09-15. 논문 원문과 실제 `artifacts/submissions/verify_v6/model/stage2/code/solution/`을 읽었다. 이 문서는 연구 설계이며 성능 개선 결과가 아니다. 현재 Qwen3-VL-4B NF4와 RTX2080 SUPER 8GB를 유지한다. 기존 모델·제출 파일을 변경하거나 모델을 실행하지 않았다.

## 1. 확인한 문제

- 실제 V6의 VLM 경로는 `stage2_v2.py:72–138`이다. 전체 10장으로 접촉과 방향을 함께 답한 뒤, 최대15장 접촉 선택, 내부 접촉까지 최대12장 진입 선택, 내부 접촉 주변3장 공간 판단을 수행한다. 36타일이라는 과거 일반 표현은 실제 이 경로에 맞지 않는다. `_sheet`는384×256 타일이고 `vlm.py:26–45`에서 호출별 총1.2MP로 축소한다. 각 ask는 독립 메시지다.
- `stage2_v2.py:104`의 진입 상한은 내부 VLM 접촉이며 최종 출력 접촉과 다를 수 있다. 실제 제출 `stage2_uncapped_jerk_v6c.py:70–99`는 네 질문 뒤 **접촉 하나만** uncapped jerk 점수 argmax로 교체한다. 방향/진입/공간의 판단 문맥은 내부 접촉에 남는다. 이 불일치는 코드상 사실이며, 모든 오답의 원인이라는 뜻은 아니다.
- 노출된 Nexar6개 전체 프레임에서 기존 V5는 접촉0/6, 진입0/5, 방향2/4, 공간1/6이었다. 접촉 fine 후보가 ±0.3초 안을 포함한4개도 VLM 선택은 틀렸다. 진입은 내부 상한 누락1개, 균등 후보 누락1개, 선택 실패3개로 분해됐다. 근거: `research/v6_stage2/v5_fullframe_error_decomposition_v2/summary.md:3–28`, `review_followup_result_20260915.md:23–36`. 이는 단일 사람 검수 초안에 대한 개발 진단이며 공식 S2가 아니다.
- 후속00008/00010/00013의 고정 V6 로그에서도 접촉 fine 후보 누락2개, 후보가 있지만 선택 실패1개다. 00013은 coarse666이 사용자 접촉662의 허용 범위에 있었으나 fine506으로 바뀌었다. 00008/00010의 가장 가까운 fine 후보는 각각 정답보다+0.5333/−0.5333초였다. 근거: `research/v6_stage2/round2_validation/run/report.json` SHA256 `d97a0ad3c438362c2cad22d67ba1e95b7ce9e2a35d047e52a13286bd19ec3915` 및 같은 run의 평가/검수 바인딩. 세 영상도 이제 결과가 노출됐다.
- 따라서 **후보를 조밀하게 만드는 일과, 후보 안에서 실제 접촉을 고르는 일은 별도 과제**다. 접촉에 대해서만 확인한 개선을 진입·방향·공간 개선으로 계산해서는 안 된다.

## 3. 반복하면 안 되는 기존 실패

V5 ROI 후보는 잘못된 차량 영역을 기하 추적이 안정적으로 따라가기도 했다. `research/v5_stage2/roi_visual_audit.json`의 영역 확인은 AI 사후 관찰이며 공식/사람 GT가 아니다. 그럼에도 JSON의 IDENTIFIED와 추적 성공이 의미적 차량 일치를 보장하지 않는 반례다. 복잡한 상태 응답은15개 파생 입력 모두 `invalid_fallback_first`로 귀결됐고 시간 비율은1.4521–1.7835였다. 근거: `results.md:3,17–27,55`.

단순 entry coarse→local fine도 이미 실행했다. 형식과 시간은 통과했지만 잘못 고른 중간 창에서 정답 구간을 잃었다. 양끝 원본을 넣는 것만으로 다른 중간 사건을 복구하지 못했다. 근거: `results_simple.md:9–26`. 그러므로 이번에도 창 축소만 하고 성능이 나아질 것이라고 주장하면 기존 실패의 반복이다. **선택창 원본/대체창/실제 제시 후보를 모두 기록하고, 창 선택 오류와 선택 오류를 따로 판정해야 한다.**

## 4. 구현할 단일 통합 설계: 사건별 탐색 후 공간 판단

2026-09-15 root와 합의한 제한된 후보. 새 파일은 `research/v7/solution/stage2_v7_grounded.py`; 기존 V6 소스·scan·가중치는 불변이다. 공개/사용자 GT나 영상 ID별 규칙을 추론에서 읽지 않는다.

| 호출 | 입력/출력 | 끊는 오류 전파 |
|---|---|---|
| 1. 전역 계획 | 전체 구간16개 균등 원본 + 최대4개 분리된 motion 제안. 같은 충돌 상대의 짧은 외형 설명, 제시된 reference_frame와 해당 원본의 정규화 bbox, 접촉/진입의 `[이전, 대표, 이후]` 원본 번호를 요구한다. | side 답이 접촉 시점에 영향을 주는 결합을 제거한다. 진입은 내부 접촉 상한으로 자르지 않는다. |
| 2. 접촉 정밀 선택 | 유효 접촉창16개 균등 원본에 정확 coarse와 V6 motion argmax를 반드시 합친다. reference는 **해당 시점 crop만** 별도 표기하며 전역 프레임을 유지한다. 최종 접촉은 제시된 정수만 수용, 불량이면 기존 V6 motion으로 복귀한다. | V6 motion은 제안/명시적 fallback이며 접촉 정답으로 강제하지 않는다. 앞의 올바른 coarse가 후보 생성 과정에서 사라지는 것을 막는다. |

사전 구현 파라미터:4회, 생성 상한 `[120,24,24,24]` 총192토큰, 호출별 기존1.2MP 상한, 별도 탐지기/전 프레임 추적 없음, scan은 V6 그대로. 첫 계획의 복잡한 출력이120토큰 안에 제대로 생성되는지는 **미확인**이며 필드별 실패를 기록한다. crop도 같은 픽셀 예산을 공유하므로 나머지 프레임 해상도가 감소하는 비용이 있다.

반환 bracket은 실제 제시된 원본 번호이고 대표를 포함해야 한다. 최대폭은 입력 순서상 `ceil((N−1)/8)`이다. 그보다 넓거나 잘못된 창은 조용히 자르지 않고 invalid로 기록한 뒤 유효 coarse 주변의 같은 최대폭 창으로 복귀한다. 이 fallback은 또 다른 잘못된 창을 만들 수 있으며 정답 보장이 아니다. 40초 영상의1/8 구간을16장으로 나누면 약0.33초 간격이다. 실제 허용 시간 커버리지는 native PTS로 계산해야 하고 숨은 영상 FPS를 가정하지 않는다.

index1의 shift−0는 앞선 shift 차분과 다른 초기 조건이다. 추가 motion 제안 순위에서는 제외하되 원래 V6 motion argmax가1이면 정확히 보존한다. 이는 초기화 영향 회피 가설이며 첫 접촉을 제외해도 안전하다는 증명이 아니다. 기존 V6 점수나 최종 baseline을 수정하지 않는다.

bbox를 다른 시점에 복사하지 않는다. 유효한 좌표는 오직 문법/범위 검사 통과일 뿐이다. reference 이미지의 crop을 잘못 고르면 후속 모든 선택을 오염시킬 위험이 남는다. reference가 무효면 crop 없이 전체 화면으로 진행하며 `reference_valid`를 `target_identity_correct`로 부르지 않는다. 진입 이전 상대가 화면 밖에 있거나 접촉이 화면 밖이면 추론 가능성이 제한되지만, 화면 안 차체 접촉만 정답으로 강제하는 규칙도 추가하지 않는다.

## 5. 분리 ablation과 채택 전 판정

1. **먼저 모델 호출 없는 후보 감사:** 실제 PTS와 알려진 정답으로 원본 전체→계획 bracket→fallback bracket→제시 후보→선택을 분해한다. 경계/전체 구간 누락과 틀린 선택을 구분한다. 단일 frame GT가 없는 interval 주석은 조건부 포함률이며 정답 정확도로 부르지 않는다.
2. **시간 구조와 참조 효과 분리:** 같은 새 시간 후보/같은 token·pixel budget에서 reference crop 없는 대조와 있는 후보를 비교한다. 다른 시점 crop 이동/추적을 함께 추가하지 않는다. 잘못된 reference도 별도로 검사하여 대상 고정이 정답인 사례만 좋아지는지 확인한다. 자동 bbox 통과 개수를 대상 정확도로 세지 않는다.
3. **항목별 출력 대조:** 접촉, 진입, 방향, 공간을 각각 평가한다. 후단 공간 시점을 final 접촉으로 바꾼 효과와 방향 정의 변경 효과를 각각 고정 입력으로 비교한다. 통합 후보가 좋아졌다는 사실만으로 어떤 구성요소가 원인인지 주장하지 않는다. 정답 없는 항목에는 S2를 계산하지 않는다.
4. **최종 통합은 독립 자료에서 확인:** 현재9개는 이미 노출된 개발 자료다. 같은 원천의 PNG/JPEG/mirror는 독립 표본이 아니다. 개발 결과로 창 폭·프롬프트·fallback을 반복 조정한 뒤 같은9개에서 다시 채택하지 않는다. 신규 자료 및 사전 고정한 정답/규칙으로 판정하고, 명확한 기존 성공 손실과 항목별 실패를 숨기지 않는다.

4회 호출이라는 사실은60분 통과 증명이 아니다. 이미지 패치 수, 첫 계획 출력 길이, 실제 clip별 시간·peak VRAM, 최종 오프라인 패키지 총시간을 측정해야 한다. 두 시간 질문의 출력이 단순하더라도 첫 계획/bbox가 불안정하면 현재4B 표현 능력의 한계일 수 있다. 이때 성공할 때까지 문구를 탐색하는 대신 해당 구조를 기각한다.

사용자가 허용한 에이전트 검수는 `ai_review`로 출처·모델·불확실성을 보존한다. **AI는 human이 아니고, AI 간 합의도 human_adjudicated GT가 아니다.** 이번 문헌·구현 작업에서는 새 주석을 생성하거나 기존 GT를 승격하지 않는다.
