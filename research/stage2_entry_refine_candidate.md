# Stage2 진입 시점 추가 탐색 후보 — 미채택

이 문서는 후보 격자의 구현과 CPU 계약 검증을 기록한다. 실제 VLM 정확도, 진입 시점 정확도 또는 처리시간 검증이 아니다. 진입 GT가 없어 자동 채택하지 않는다. 기존 `stage2_v2.py`, NF4 제출 소스 및 모델은 변경하지 않았다.

## 구현

`solution/stage2_entry_refine.py`의 `_predict_file(paths, scores, vlm)`는 먼저 기존 V2 `_predict_file`의 4회 추론을 그대로 수행한다. 그 결과에서 진입 시점만 선택적으로 추가 탐색한다.

1. 기존 `entry_candidates` 중 선택된 진입 후보의 직전·직후 후보를 찾아 국소 구간을 만든다. 끝 후보는 영상 시작 또는 예측 충돌 위치로 제한한다.
2. 해당 구간의 원본 프레임을 최대 12개 선택한다. 선택된 coarse 진입 프레임과 구간 양끝을 보존하고, 양쪽 길이에 따라 후보 간격을 나눈다. 경로 목록의 위치로 샘플링하고 출력에는 원본 파일 번호를 그대로 사용한다.
3. 충돌 이전의 모든 원본 프레임이 기존 진입 후보에 이미 포함됐으면 추가 호출을 생략한다. 선택 구간에서 새로 보여줄 프레임이 없어도 생략한다. 그 외에는 추가 질문 1회만 수행한다. 합계는 4회 또는 5회다.
4. 정상 JSON 객체가 제시된 후보 중 정수 `entry_frame`을 반환했을 때만 진입 값을 변경한다. 문자열·소수·boolean·배열·누락·후보 밖 번호·JSON 외 설명은 수용하지 않는다. 파싱 실패나 추가 호출 예외 시 기존 진입 값을 유지하고 재시도하지 않는다.
5. 충돌 시점·방향·회피공간은 기존 결과 그대로다. 파일 간 예측값이나 데이터셋 통계는 사용하지 않는다.

진단 정보에는 기존 진입, 추가 후보, 원본 번호로 된 범위, 추가 호출 수, 원 응답, 수용/보존 이유를 기록한다. 국소 구간의 첫 프레임을 선택하면 `selected_local_window_start`로 표시한다.

## CPU 계약 검증

실행: `.venv/Scripts/python.exe scripts/test_stage2_entry_refine.py`.

결과: `research/stage2_entry_refine_contract.json`. 실제 V2의 질문·선택 경로를 실행하되 VLM 응답은 스크립트로 정해 놓았고 이미지 렌더링은 32×32 CPU 이미지로 대체했다. 실제 모델을 로드하지 않았으며 torch를 import하지 않았다.

검증한 계약은 긴 600프레임 입력, 비연속 원본 번호, 번호의 일정 offset 이동, 1프레임 입력, 모든 진입 프레임이 이미 있는 경우, 여러 잘못된 응답과 예외의 보존 동작, 다른 세 출력 필드 유지, 국소 구간 시작 선택의 범위 표시다. 소스 SHA와 실제 합성 실행 결과는 JSON에 저장한다.

600프레임 합성 사례에서는 coarse 진입 272의 이웃 구간 218~327을 다시 나눈다. 이는 제한된 구간 안의 후보 간격을 줄였다는 구현 예시일 뿐이다. 가짜 모델이 선택한 프레임을 정답으로 해석하면 안 된다.

## 해결하지 못하는 한계

- **잘못된 coarse 구간:** 실제 진입이 선택된 이웃 구간 밖에 있으면 추가 질문은 그 시점을 선택할 수 없다. 진입 전 구간을 충분히 포함하지 못한 첫 선택의 오류를 보장해서 고칠 수 없다.
- **국소 첫 이미지와 원영상 시작은 다름:** fine 질문에 국소 구간이라는 점을 명시했다. 구간 시작 전에 이미 진입했다면 반환되는 lower endpoint는 관찰 범위의 경계일 뿐 실제 진입 확정값이 아니다. 진단 flag도 과거 진입을 검증했다는 의미가 아니다.
- **사고 상대 식별 문맥 감소:** 각 `ask`는 독립 호출이다. fine 질문에는 이전 응답 대화나 충돌 장면이 자동 전달되지 않는다. 국소 구간 안에 차량이 여러 대 있으면 실제 충돌 상대를 잘못 고를 수 있다. 이번 후보에서는 이를 해결하려는 추가 이미지·차량 설명·프롬프트 튜닝을 하지 않았다.
- **FPS/타임스탬프 미지:** 원본 번호의 차이는 실제 시간 간격을 보장하지 않는다. 비연속 번호에서는 경로 목록의 인접 위치가 시간상 인접하다는 보장도 없다. 실제 평가의 FPS가 공개되지 않은 상태에서 최대 12개 후보와 한 번의 추가 탐색으로 ±0.3초 해상도를 보장할 수 없다. 긴 구간이면 fine 간격도 여전히 넓다.
- **오류 전파와 추가 비용:** 충돌 시점이 먼저 틀리면 진입 탐색의 끝도 틀린다. 1회 호출이 추가되는 영상의 실제 추론 비용은 측정하지 않았다. CPU mock 실행시간을 GPU 처리시간으로 사용하지 않는다.
- **정답 부족:** 진입·방향·회피 GT가 없으며 외부 CCD는 데이터 자체 이용범위도 미확인이다. 따라서 이 후보를 제출에 반영하거나 정확도 향상을 주장할 근거가 아직 없다.

기존 `research/stage2_temporal_resolution.json`은 가상 타임라인의 후보 격자 진단이다. 이번 계약 검증과 마찬가지로 실제 모델 성능 지표가 아니다.
